逼问需求

一次只问一个问题，把你「以为想要的」问成「真正想要的」，问到约 95% 确信才允许动手开工。

addyosmani

做什么用

一次只问一个问题，把你「以为想要的」问成「真正想要的」，问到约 95% 确信才允许动手开工。需求错了后面全白干，这个「先逼问再动手」的纪律省下的是整个项目的返工。

应用范围

用在「工作」这一格。只适用于需求模糊、需澄清意图的场景。若需求已明确（如“给60岁父母做语音提醒”），它仍会盘问，浪费你时间。

如何使用

  • 就按「逼问需求」这一件来做，不要中途改风格。
  • 按它的流程走完这一件，不要跳步骤。
  • 输出要能进仓库或工单，不要只给感想。
  • 做完对照应用范围，越权的活另找工具。

git clone --depth 1 https://github.com/addyosmani/agent-skills.git
