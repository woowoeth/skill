# AINoSleep 火柴人正文配图

## 核心定位

为中文文章设计和生成 16:9 横版正文配图。目标不是做商业插画、PPT 信息图、课程页或可爱卡通，而是把文章里的关键判断、流程、结构、状态或隐喻，变成一张清爽、克制、能看懂的手绘解释图。

默认视觉 IP 是 AINoSleep 火柴人：纯白背景上的黑色火柴人线条，身上没有任何固定标记，可以有低强度的极简黑色轻表情。角色气质是普通人视角，安静、实用、爱折腾，不装专家。火柴人必须参与画面的核心动作，不能只是站在旁边当装饰。优先用身体姿态和手上动作表达状态，表情只做很小的辅助。画面默认黑白手绘，不使用固定品牌色。

## 先读这些参考

按任务需要读取，不要一次塞满上下文：

- `references/style-dna.md`：风格 DNA、颜色、文字、禁忌。
- `references/ainosleep-stickman-ip.md`：AINoSleep 火柴人 IP 的形象、性格、动作库和禁忌。
- `references/official-reference-board.md`：官方参考板；做风格样片、稳定性测试、团队交接、README 展示图或角色校准时读取。
- `references/composition-patterns.md`：结构类型、原创隐喻方法和反复刻规则。
- `references/prompt-template.md`：单张生图提示词模板。
- `references/qa-checklist.md`：生成后检查和迭代规则。

做视觉校准时，可以查看 `assets/reference-board/ainosleep-stickman-reference-board.png` 和 `assets/examples/` 里的合格样图；正文配图不要直接照抄样图构图。

## 工作流

### 1. 消化正文

先读用户给的正文、链接、Notion 页面、Markdown 文件或截图内容。提炼：

- 核心观点是什么
- 哪些段落承担认知转折
- 哪些内容适合用图解释
- 哪些地方只适合文字，不需要图

不要平均配图。优先选择“认知锚点”，例如：核心判断、两个断点、输入输出闭环、分流、前后对比、自动化接手点、常见坑、角色状态变化。

### 2. 先出配图策略

如果用户只是说“分析怎么配图 / 思考哪些地方需要配图”，先给 shot list。每张图写清楚：

- 放在哪个段落后
- 图的主题
- 核心意思
- 结构类型
- AINoSleep 火柴人在图里做什么
- 建议元素
- 自动提炼的 1-3 个短中文标注词

默认 4-8 张。文章很短时 1-3 张；长文也不要轻易超过 9 张。够用就好，避免把正文做成画册。

### 3. 单张生成

如果用户明确要求“生成 / 输出 / 做图 / 帮我生成”，不要停下来等确认；用内置 `image_gen` 每张单独生成。不要把多张图拼在一张里。

每张图只讲一个核心结构。提示词必须包含：

- 16:9 横版中文正文配图
- 纯白背景
- 黑色手绘火柴人线条
- 可有低强度极简黑色轻表情，表情必须服务文章状态，不能抢走动作
- 火柴人身上不要任何固定标记、徽章、胸牌、logo 或复杂服装
- 画面默认黑白手绘；箭头、按钮、连线、节点也用黑色线稿表达
- 大量留白
- AINoSleep 火柴人作为核心动作主体
- 默认从文章里自动提炼 1-3 个短中文标注词
- 中文标注只做物件旁的小注释，不要放在画面顶部或像标题
- 系统/流程只画 3-4 个必要节点，优先低科技物件，不要整齐矩形节点链
- 禁止 PPT、商业插画、幼稚可爱、复杂架构、左上角类型标题
- 禁止正方形徽章、文字胸牌、logo、复杂装饰、动物拟人、耳朵、尾巴

不要复刻旧案例、旧角色或可识别设定。每次都要从当前文章重新发明一个安静、实用、成立的隐喻。

### 4. 检查与迭代

生成后检查 `references/qa-checklist.md`。如果出现以下问题，优先重生成或局部编辑：

- 火柴人只是装饰
- 角色不像黑色火柴人线条
- 面部表情过大、过可爱、像表情包或比动作更醒目
- 火柴人身上出现颜色标记、徽章、文字胸牌、logo 或复杂装饰
- 出现动物拟人、耳朵、尾巴、实心怪物感或复杂服饰
- 画面太满
- 太像流程图/PPT
- 中文标注像标题、栏目名或大段说明，而不是贴近物件的小注释
- 节点排得太整齐、太像软件架构图或自动化平台界面
- 中文太多或错字严重
- 左上角出现“常见坑/流程图/系统架构图”等标题
- 画风太可爱、幼稚、死板
- 背景不是干净白底

默认不要生成无字版。只有用户明确要求无字，或同一张图连续重生成后中文仍严重错误时，才把标注减少到 1 个或改为无字，并在交付里说明。

### 5. 保存交付

如果用户在 workspace 内工作，把最终图复制到：

```text
assets/<article-slug>-illustrations/
```

按顺序命名：

```text
01-topic-name.png
02-topic-name.png
```

保留原始生成文件，不要覆盖已有资产，除非用户明确要求替换。

## 输出口径

生成前的策略输出要短而准。生成后的交付要包含：

- 生成了几张
- 每张图的用途
- 保存路径
- 哪些图最稳，哪些图是可选

不要长篇解释风格理论；让图自己说话。
