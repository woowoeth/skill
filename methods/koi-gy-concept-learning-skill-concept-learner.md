# concept-learner

## 适用场景

适用于以下三类任务：

1. **课程概念预习**：老师提到一个新名词，想在 30 分钟内拿到一份"知道它在说什么、为什么重要、用在哪里"的入门资料。
2. **跨课程概念归档**：在不同课程、不同项目里反复遇到的概念，希望用统一格式沉淀到个人仓库，方便日后检索。
3. **作业/汇报素材**：需要为一个概念写出一段"个人解释 + 案例 + 边界"，而不是抄百科。

不适用于：
- 需要实时联网抓取最新数据（如今天的股价、最近一条新闻）。
- 需要运行代码或访问本地文件的实操型任务。
- 整本教材或长篇报告的总结。

## 输入信息

调用 Skill 时需要明确告诉 AI 以下信息，缺一项就停下来问：

| 字段 | 说明 | 必填 |
|------|------|------|
| `concept` | 要学习的概念名（例：Agent、大模型的上下文、RAG、Function Calling） | 是 |
| `audience` | 学习者是谁（默认：学过 LLM 基础、正在做 Agent 课程作业的同学） | 否 |
| `prior_knowledge` | 已经知道的先验概念（例：知道 Transformer 是什么、没听过 RAG） | 否 |
| `use_case` | 想用这个概念做什么（例：写作业 / 给同学讲 / 自己复盘） | 否 |
| `output_path` | 学习页输出到哪里（默认：`learning-materials/<concept-slug>.html`） | 否 |
| `source_requirement` | 资料来源的最低可信门槛；可填"教材级 / 官方文档级 / 论文级" | 否（默认官方文档级） |

调用模板：

```
@concept-learner 学习概念：<concept>
我的身份：<audience>
已知：<prior_knowledge>
目标：<use_case>
输出到：<output_path>
来源门槛：<source_requirement>
```

## 生成步骤

执行时严格按以下 7 步走。**不要跳步**。

### Step 1 — 概念界定
用一句话回答"这是什么"。给出至少 2 个不同的可信来源对该名词的定义（不要求逐字引用，但要标注出处）。如果两个来源定义冲突，要点出冲突。

### Step 2 — 个人解释
用"如果我给同学讲，我会这样说……"的口吻写 2–4 段。这一段必须是**用户自己改写过**的，AI 给出的版本只是草稿。**判断标准**：如果把这一段整段粘给一个完全没听过这个概念的同学，他能不能听懂。

### Step 3 — 核心机制 / 组成
拆成 3–6 个组件或机制，每个组件写：
- 它是什么（一句话）
- 它和别的组件怎么连
- 没有它会怎样

可以画一个分步骤的图（用 Mermaid 或编号列表都行）。

### Step 4 — 一个具体应用场景
挑一个**真实存在的**案例（不是假想的），说清：
- 谁在用
- 解决什么问题
- 流程是怎样的
- 关键效果（最好有可核查的数据）

### Step 5 — 边界与容易混淆的点
至少列出 3 条：
- 这个概念**不是**什么（最容易混的概念，例：Agent ≠ ChatGPT）
- 它的**限制**是什么（什么场景下它不 work）
- 它**和邻近概念**的区别（用一个对比表）

### Step 6 — 可核查的资料来源
每一条来源写明：
- 标题
- URL
- 发布方 / 作者
- 发布时间
- 用了哪一段（自检时方便回头查）

**硬性要求**：
- 至少 3 条来源
- 至少 1 条是官方文档 / 论文 / 教材级别
- 不允许编造 URL——AI 出草稿时如果编了一个看起来很像但不存在的链接，必须删除或换成真实存在的链接
- 教材级以外的来源（如博客、视频）可以加，但必须有官方来源做"锚"

### Step 7 — 自检清单
生成完毕后按下面 6 条逐项检查：

- [ ] 概念界定引用了 ≥2 个来源
- [ ] 个人解释里没有任何一段是把 AI 输出原样搬过来未改写的
- [ ] 核心机制里至少有一个"它和别的组件怎么连"的描述
- [ ] 应用场景是真实存在的，不是凭空编的
- [ ] 边界与混淆点至少 3 条，且至少 1 条用对比表
- [ ] 资料来源全部 URL 都已点开过、确认能打开、内容对得上

任意一条没勾上，就回去补，不能交付。

## 输出结构

每份学习页（HTML）必须包含以下区块，缺一不可：

1. **顶部元信息**：概念名、生成日期、来源门槛、最后核查日期。
2. **TL;DR**：3–5 条要点列表，让 30 秒读完的人能讲出这个概念。
3. **这是什么**：概念界定。
4. **我的理解**：个人解释（这是用户改写过的那段）。
5. **核心机制 / 组成**：分点 + 可选图示。
6. **一个具体应用场景**：真实案例。
7. **边界 & 容易混淆的点**：含对比表。
8. **可核查的资料来源**：编号列表。
9. **自检勾选**：把 Step 7 的 6 条做成可勾选的清单。

样式要求：
- 一个 HTML 一个完整页面，不依赖外部 CSS/JS（自包含，方便 GitHub 直接预览）。
- 配色简洁（黑/白/灰 + 一个 accent 色），不花哨。
- 移动端可读。

## 资料来源要求

- **门槛**：默认"官方文档级"，即来自 Anthropic / OpenAI / Google DeepMind / Hugging Face / 知名大学课程 / 知名教材 / arXiv 同行评议论文。
- **可降级**：如果是冷门概念，官方来源不存在，可以降到"权威博客"（知名研究者、知名机构博客），但要在来源列表里说明"为何降级"。
- **不可编造**：AI 输出里的任何看起来合理的 URL，必须人工打开过一次确认存在。AI 在 2024 年之后训练数据里有大量"看起来对但实际不存在的引用"，这是高发错误区。
- **多源交叉**：核心定义最好有 2 个独立来源相互印证。

## 自检要求

提交前必须做的事（这是评分点）：

1. **链接核查**：每一个 URL 用浏览器打开过，确认 200 OK 且内容与引用段落一致。
2. **概念改写**：个人解释部分至少有一段是用户自己写的、不是 AI 输出原样。
3. **场景核查**：应用场景里的人物、产品、数据，至少有一项是用户验证过的。
4. **对比核查**：边界对照表里的"区别"，每一条都能在来源里找到依据，不能是 AI 自己推的。
5. **改写记录**：在 README 的"AI 使用与人工核查"小节里，记下哪些段落做了人工修改、改了什么、为什么。

## 不要做的事

- 不要把整段 AI 输出贴进 HTML 了事。
- 不要编造看起来很像但实际不存在的论文、博客、人物。
- 不要用"我作为 AI……"这种话术污染个人解释部分。
- 不要在资料来源里只放 Wikipedia 一条。
- 不要为了凑数把同一个来源的三个不同章节算成三条来源。

## 调用示例

```
@concept-learner
学习概念：Agent
我的身份：学过 LLM 基础，正在做 Agent 课程作业
已知：知道 ChatGPT、Prompt Engineering、Function Calling
目标：在 30 分钟内搞懂"Agent 到底是什么、和 ChatGPT 差在哪"
输出到：learning-materials/agent.html
来源门槛：官方文档级
```

预期产物：`learning-materials/agent.html` 一个自包含 HTML 文件。
