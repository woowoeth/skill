# Novel-Writing：长篇小说创作技能（作者在环 · 批次工作流）

你维护的是一个**创作系统**，不是文本生成器。铁律：**单次产出 ≤ 批次上限（默认 3,000 字，即一批一章）；每批开始前要有方向提案并经作者确认；每批结束后输出故事变化总结并停止，等作者修缮后再开下一批。绝不自动续批、绝不未经确认一次性推出大段内容。**

## 0. 定位与边界

- **技能本体**：本 `SKILL.md` 所在文件夹 `.claude/skills/novel-writing/`。它不含任何一本书的内容。
- **小说工作区**：默认在技能被调用的工作区下 `novels/<书名>/`（作者可显式指定）。
- **模板**：位于技能本体 `templates/`。不确定路径时先 `Glob` 定位 `*.tmpl` 目录。所有 scaffold 从模板复制改写，不凭空建结构。
- 一次只维护当前这本书的状态。

## 1. 文件职责速览

| 文件 | 职责 | 更新时机 |
|---|---|---|
| `project.md` | 元信息、**批次上限**、进度指针、变更日志、硬约束速查 | 每章后 / 每次改动 |
| `world.md` | 硬规则、地点、历史事件 | 章后如有新事实 |
| `style.md` | 风格锚点与规则 | 极少 |
| `outline.md` | 卷层骨架 + 章节卡 | 大纲期 / 软约束回填 |
| `characters/*.md` | 每角色静态卡 | 设定期/章后事实 |
| `characters/relationships.md` | 关系表 | 关系变化时 |
| `characters/state.md` | **动态状态快照** | **每章后** |
| `chapters/cNNN-*.md` | 每章文件 | 每章 |
| `memory/timeline.md` | 剧情时间线（追加） | **每章后** |
| `memory/foreshadowing.md` | 伏笔台账 | 埋/收伏笔时 |
| `memory/recent_summaries.md` | 最近 10 章摘要（滚动） | **每章后** |
| `memory/arc_summary.md` | 分卷摘要（追加） | 卷末 |
| `reviews/review_卷N.md` | 卷末自查报告 | 卷末 |
| `archive/` | 归档过季过程材料 | 卷末 |

## 2. 设定分级（冲突裁决依据）

- **硬约束**：世界观基础规则、能力体系、已写定关键事实、已发布章节。**不可静默改动**。
- **软约束**：大纲节拍、人物弧计划。可被好故事推翻，但必须**回填**并记录原因。
- **活跃记忆**：timeline / state / foreshadowing / summaries。每章后必须更新。

## 3. 创建一本新小说（全关卡）

1. 收集最小需求：类型、主角一句话、风格基调、预计章数与每章字数、**批次上限（默认 3,000 字，即一批一章；可上调，建议 ≤ 10,000 字）**。不足就问，不臆造。
2. scaffold：建 `novels/<书名>/`，从 `templates/` 复制改写各文件到对应路径；`project.md` 写清篇幅与批次上限。
3. **关卡 A**：只产出 5~8 卷卷层骨架，请作者确认。**未经确认不写正文。**
4. **关卡 B**：确认后**一次只展开一卷**的章节卡，请作者确认后再展开下一卷。不一次性吐全部章节卡。
5. 创建主要角色卡与关系表初稿，请作者过目。
6. 进入 §4 批次循环。

## 4. 批次循环（写作的主范式）

### 4.0 方向提案（每批第一步）
先给出几行方向提案：本批写哪一章（默认每批一章，作者调大上限后才含多章）、关键推进、要埋/收的伏笔（F-xx）、会动到的角色状态。**请作者确认或改方向；未经确认不得写正文。** 作者说「直接写」= 已确认当前提案。

### 4.1 有界读取清单（读，禁止通读 chapters/ 与全部 memory）
按需局部读取：
1. `project.md`：批次上限、进度指针、硬约束速查、变更日志尾部。
2. `world.md`：硬规则 + 本场相关历史。
3. `style.md`：锚点与文风规则。
4. `outline.md`：当前卷段 + 本批涉及的章节卡 + 下一张卡。
5. `characters/`：本场角色卡 + `relationships.md` + `state.md`。
6. `memory/`：`timeline.md` 尾部、`foreshadowing.md` 相关未回收行、`recent_summaries.md` 最近 3~5 条、所在卷 `arc_summary.md`。

### 4.2 分章写作（批内累计 ≤ 批次上限）
- 每章复制 `templates/chapter.md.tmpl` 为 `chapters/cNNN-第N章-标题.md` 并填元信息块。
- 每章 ≤ 3000 字（以 project.md 为准）；批内累计接近批次上限即**停止本批**——默认上限 3,000 字即一批一章，作者在 project.md 调大上限后才一批多章。
- 严格贴合章节卡、硬约束、style.md 锚点。
- **创作走向若与硬约束冲突：停下，不硬写，走 §6。**

### 4.3 每章写完 → 立即自查
- [ ] 本章确立了哪些新事实？写回哪份文件？
- [ ] 时间与 timeline 当前剧情时间衔接无冲突？
- [ ] 人物言行/能力/称呼与卡和 state 现状一致？
- [ ] 埋设了未登记伏笔？意外消耗未回收伏笔？有无到期该收的？
- [ ] 风格贴近锚点？禁用词未混入？

### 4.4 每章写完 → 立即写回（不攒到批末）
- 新事实/历史 → `world.md` 历史节（注来源章）。
- 剧情时间 → `timeline.md` 追加一行。
- 角色现状 → 刷新 `state.md`；关系变化 → `relationships.md`。
- 伏笔埋设 → `foreshadowing.md` 登记 `planted`；回收 → 状态改 `paid` 填回收章；逾期 `active` 尽快安排。
- 摘要 → `recent_summaries.md` 追加；超 10 条裁最旧。
- `project.md` 更新进度指针；设定改动记入变更日志。

### 4.5 卷末收尾（本批恰好到卷末时）
全卷浓缩一段追加 `arc_summary.md` → 生成 `reviews/review_卷N.md`（用 review 模板，分卷抽查）→ 归档上一卷过季材料。

### 4.6 批后：故事变化总结（必交，给作者，不落文件）
正文停止后，用几行小结向作者交代——
- **剧情进展**：本批从哪推到哪；
- **人物状态**：谁的位置/关系/处境变了；
- **新事实**：确立了哪些此前没有的设定、已写进哪份文件；
- **伏笔**：埋了 F-xx、收了 F-xx、有无逾期 active 待安排；
- **遗留悬念**：下一批天然要接的钩子。

然后**明确停止，交还作者**（如「本批完成，请修缮或批准下一批」）。不要替作者决定继续写；作者说继续时，也只推进一个批次（回到 4.0 方向提案）。

### 4.7 修缮与修订回填（作者对产出下手后）
作者可能：改正文、给修改意见、调整已产出的某章。处理：
1. 读取作者改动，**提取新事实**并同步进相应记忆文件（时间/状态/伏笔/摘要/指针）。
2. 改动若与硬约束或已发布章节冲突 → §6。
3. 若作者改的是**较早批次**而其后已有后续章：检查受影响的后文并**提示级联修改**，不静默装作自洽。

## 5. 面向作者的检查指令（都不通读全本）

| 作者说 | 做法 |
|---|---|
| 查看/列出未解决伏笔 | 读 `foreshadowing.md`，列 `planted/active` 按预期回收卷分组，标逾期 active |
| 检查时间线 | 读 `timeline.md`，抽查相邻章时间衔接、时间类硬规则 |
| 检查人物矛盾 | 对照角色卡 / relationships / state 与最近摘要 |
| 检查一致性 / 风格 | 用 4.3 清单对照最近数章，给结论与应回填项 |
| 新增角色 | 建卡（character 模板），更新 relationships、state，请作者确认关键设定 |
| 修改设定 | 走 §6 冲突协议 |

## 6. 冲突裁决协议

1. 判定冲突级别（§2）。
2. **硬约束冲突**：暂停，说明冲突点、可选改法与后果，由作者决策；批准后改设定文件，变更日志记录「何时/改什么/为何/批准人」。
3. **软约束冲突**：可执行，但**立即回填** outline 相关章节卡，必要时更新人物弧与伏笔表；变更日志留一行原因。
4. 回填后检查依赖该改动的后续章节与伏笔预期回收。

## 7. 护栏（时刻遵守）

- **字数**：单批累计 ≤ project.md 的批次上限（默认 3,000 字，即一批一章）；每章 ≤ 设定章字数。
- **方向**：每批先提案并取得作者确认；作者未确认方向不写正文。
- **停点**：每批结束输出「故事变化总结」后**必须停下**等作者；「继续」也只推进一批。
- **读取**：定位读取，不把整本 chapters/ 读进上下文。
- **记忆有界**：recent_summaries 只留 10 条；卷末归档；不把整章正文复制进 memory。
- 单会话默认最多一个批次；作者明确要求时才连续处理多个批次，且每批都保持 4.3/4.4 闭环与批间停点。
