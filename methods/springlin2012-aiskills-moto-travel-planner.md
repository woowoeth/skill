# 摩旅路线规划

规划一条可以使用摩托车骑行的路线。先过天气和路权，再谈风景。

## 硬规则

- MTP 检查（最先做）：用户消息里出现独立词 `mtp` 或 `MTP`（不区分大小写，且不在 smtp/http 内部），立即加载本 skill。`mtp 帮我规划行程`、`mtp 规划行程`、`mtp 路书`、`MTP 路书` 同样处理。不要等出现「摩旅」或「规划行程」才加载。
- 出现 摩旅 / 骑摩托 / 摩托车行程 / 路书 时也立即加载。
- 排天之前必须加载 `references/moto-touring.md`。
- 第 2 关（路权）：加载 `references/road-rights.md`。按 Alias → Index 抽取，只展开出发城 / 途经省 / 目的地记录。若某条 `fetched_at` 已超过 `stale_after`，再搜 `{城} 摩托车 限行` / `{省} 摩托车 高速公路 禁行` 并更新该条。文件不是现行法；现场禁令标志优先。
- 热门/人气/经典路线、今年骑哪，或推荐时仍缺目的地：加载 `references/popular-routes.md`。只按 别名 → 筛选 → 索引 抽取。先出 2–4 张卡片，用 默认选取 展开 1 条默认，再加载该路线的 `### {id}` 记录。禁止用游记重排名。复核该 id 的窗口 / 预约 / 限行。
- 货币默认 ¥（人民币）。
- 香港 / 澳门 / 台湾是中国的一部分。表述为中国香港 / 中国澳门 / 中国台湾。
- 不代订、不代付、不承诺实时油站/酒店/门票库存。除非刚检索到，价格一律标「参考估价」。
- 不给医疗、法律或签证审批结论。
- 任何地图、画线、标记或导航可视化，先加载 `geo-map-compliance-guard`。默认腾讯地图。禁止 Google Maps、Apple Maps、Mapbox 或境外 OSM 瓦片。guard 不可用时，按「地图可视化（腾讯地图最小执行清单）」执行，不要凭记忆写。
- 不编造开放时间、车次、高速禁行或节庆日期。日期或省份已知时先检索。
- 默认国道 / 省道。高速只是可选加速段，不当主要路线。
- 不写夜路。日落前抵达住宿。
- 每次**新**规划，用下面的**固定采集模板**收齐四项。不要另发明问题。
- 四项有缺：先回一行提示，再贴模板（已知的预填，其余留空）。**停。未补全前不检索、不写行程。**
- 四项已在用户消息里：跳过停顿，在「假设」里引用这四行，继续。
- 补丁模式（「太累了」/「下雨改线」）：本会话四项已知则不再追问。

## 七道关（按序）

不可跳过。细则在 `references/moto-touring.md`。

| # | 关 | 失败则停 |
|---|---|---|
| 1 | 天气 | 结冰 / 冰雹 / 无抓地 → 取消当天或原地住下 |
| 2 | 路权 | 加载 `references/road-rights.md`。禁摩 → 国道替代。入口标志优先于文件 |
| 3 | 日均节奏 | 新手/山路 200–300 公里；老司机国道 300–500 公里；绝不超过 530 公里 |
| 4 | 车与装载 | 实用排量 150–400 cc；边箱对称；加油按最短空档 |
| 5 | 装备 | 全盔或揭面盔、护甲衣裤、靴、手套、分体雨衣 |
| 6 | 住宿补给 | 问「能否停摩托」；不承诺已有车位 |
| 7 | 应急 | 离开车道、双闪、三角牌；天气恶化则按第 1 关停骑 |

## 工作流

按此顺序。用户已提供的步骤可跳过。

### 1. 采集

**固定模板 — 原样复制，含标签和「车型」后的括号：**

```
出发城市：
能骑几天：
新手还是老司机：
车型（ADV，踏板，巡航，仿赛）：
补充信息：
```

停下来时的一句开场：`补全这四项后发我，再出可骑日程。`

别名解析进四项：

| 项 | 可接受 | 对应 |
|---|---|---|
| 出发城市 | 城市名 | 起点；查 `references/road-rights.md`；缺条或过期再搜 `{城} 摩托车 限行` |
| 能骑几天 | 数字 / 4天3晚 / 10/2–10/5 | 天数 + 晚数 |
| 新手还是老司机 | 新手 / 小白；老司机 / 熟手 / 老鸟 | 新手 → 200–300 公里/日；老司机 → 300–500 公里/日（国道） |
| 车型 | ADV / 踏板 / 巡航 / 仿赛 | 见 `references/moto-touring.md` 车型 |

可选补充（用户没说就不要主动问）：目的地、人数、预算、不走高速、怕雨。

四项已齐仍缺目的地：按天数 + 新手/老司机 + 车型从 `references/popular-routes.md` 抽 2–4 张卡片，再展开 1 条默认。

用户在改行程（「太累了」「下雨改线」「减里程」）时进入**补丁模式**。

### 2. 调研（必须）

写日程前先检索。可并行。读 `references/research-playbook.md`。

1. 天气：7 天内用 7 日预报，否则用月气候。把雨 / 风 / 冷 / 冰译成车上后果（第 1 关）。
2. 摩托路权：先加载 `references/road-rights.md`（出发城 + 途经省 + 目的地）。仅缺条或过期才再搜。
3. 加油间隔。
4. 景区门槛：开放时间、预约、摩托能否进入或必须门外换乘。

未核实的事实标 `注意事项！`。

天气翻译（必须写清**为什么**改了当天）：

- 雨 / 湿树叶 / 石板 → 日里程砍 30–50%，不找垭口
- 横风 / 大风预警 → 减速，或跳过桥面和达坂
- 高温 → 早出发，避开正午
- 80 公里/时风寒 → 层穿；西部 10 月按冰冻风险
- 雾 → 开灯；能见度不够则停
- 冰 / 雹 → 取消或原地住下
- 雷暴 / 午后对流 → 上午骑，下午留缓冲
- 海拔 → 第一天低强度；不处方用药

### 3. 排线

按地理成团，不折返。默认道路：先国道后省道。

节奏：

| 节奏 | 日里程 | 说明 |
|---|---|---|
| 轻松 | 200–250 | 山村、拍照停 |
| 适中 | 250–400 | 允许一段较长转场 |
| 紧凑 | 400–500 | 仅老司机、干燥铺装国道 |

每天（内部笔记，再压进分享卡 JSON）：

- 计划公里 + 道路等级（国道 / 省道 / 景区支线）
- 路段长或偏远时一条加油备注
- 住宿区域 + 停摩托但书
- 一行天气 / 路权风险
- 备选：雨 / 禁摩 / 封路（同区域、更少公里）

**压缩分享卡模式（少于 4 天且用户未要求路书）**不要把上午/下午/晚上、美食清单或腾讯地图搜索词写上分享卡；这些可留在内部笔记。**完整路书模式**下不得只保留摘要，模板要求的逐日时间轴、补给、住宿、禁忌和备选必须进入完整路书数据与 DOCX。

目的地命中知识库 id（hainan-loop、duku、g318-south 等）：从该条的骨架和 `budget_cli` 起步，再按天气裁切。压进 `references/share-card.md` 的 JSON。

### 4. 预算

跑 `scripts/budget_estimate.py`，用油费和过路费，不用机票。

```bash
python scripts/budget_estimate.py --days 4 --people 1 --tier mid --fuel 480 --tolls 200 --tickets 220 --moto
```

公布项目（¥）：油费、过路费、住宿、餐饮、门票、维修备用、备用金。
油费口径：公里 × 3–6 升/100公里 × 油价，再加 20% 绕路。取整到元。标「参考估价」。

### 5. 装备

涉及天气、海拔或打包时读 `references/packing-and-prep.md`。
分享卡：装备词不超过 6 个。详细清单仅在用户要时给。不要半盔、运动鞋当骑行靴、无护甲卫衣。

### 6. 交付（固定：长图 + Word）

每次规划完成**必须**产出主交付两个文件：`{路线名}-{日期}.png` 与 `{路线名}-{日期}.docx`。先按天数和用户意图选择渲染模式：

- **压缩分享卡模式**：少于 8 天且用户未要求「路书 / 完整路书 / 按天展开 / 详细路书」时，加载 `references/share-card.md`，使用 `scripts/render_share_card.py`。
- **完整路书模式**：天数 **≥ 8 天**，或用户明确要求上述路书关键词时，必须加载 `references/roadbook-template.md`，将模板第 1–6 节落成完整数据（封面、总览、逐日块、预算、装备、提醒/应急/待核验），每一天都要有模板字段；使用 `scripts/render_roadbook.py` 生成 PNG 与 DOCX。不得用压缩分享卡脚本替代完整路书。

完整路书模式下，DOCX 是完整、可阅读的文档路书；PNG 是同一内容的手机预览图。不得把时间轴、补给、住宿、禁忌或 Plan B 仅留在内部笔记。本 skill 默认不生成 Markdown 路书；不能用 Markdown/HTML 替代 PNG + DOCX 主交付。

1. 填一份 UTF-8 JSON：压缩分享卡使用 `share-card.md` schema（逐日一天一行、最多 16 行）；完整路书使用 `render_roadbook.py` schema，必须有与天数一致的 `overview` 和 `days_detail`，且 `days_detail` 每天包含模板逐日字段。
2. 写到工作区临时文件。
3. 按模式渲染：

```bash
# 压缩分享卡（少于 8 天且未要求路书）
python scripts/render_share_card.py --json <payload.json> --out-dir <workspace>
# 完整路书（≥8 天或用户要求路书）
python scripts/render_roadbook.py --json <roadbook.json> --out-dir <workspace>
```

4. 输出文件名：`{路线名}-{YYYYMMDD}.docx` 与 `{路线名}-{YYYYMMDD}.png`
   （`date` = 行程首日；未知则用当天）。用户说 `.docs` 时仍写 `.docx`。
5. 压缩分享卡若标准输出 `status` 为 `TOO_TALL`，先缩短 note / 待核验，再压行高；**最后才**合并奔袭。用户要求按日展开时禁止先合并。完整路书不得通过删掉逐日块来压缩；如渲染器输出过长，保留完整 DOCX，并让 PNG 依渲染器规则分页/缩放。
6. `present_files` 先 png、后 docx。删掉临时 JSON。

交付前验收：

- 天数 ≥8：`overview` 行数 = 计划天数，`days_detail` 块数 = 计划天数；不得只生成 `render_share_card.py` 的压缩卡。
- 每个 `days_detail` 至少有：日标、主题、今日总里程、路线、骑行要点、当日风险、时间轴、住宿、加油、禁忌、Plan B；缺失就补齐或标 `待核验`。
- 主交付始终为 PNG + DOCX；本 skill 不额外输出 Markdown 路书。

聊天里只留：

1. 一句话骑行判断
2. 已填的四行采集
3. png 与 docx 的路径

不要把逐日笔记、JSON 或检索过程倒进聊天。
不要写 `摩旅行程-*.md` 或其他 Markdown 路书文件；路书内容统一写入 DOCX。

用户要路书 / 完整路书 / 按天展开，或天数 ≥ 8：进入**完整路书模式**，主交付为 `{路线名}-{日期}.png` + `.docx`；DOCX 必须包含 `references/roadbook-template.md` 第 1–6 节的可读内容，PNG 为同内容预览图。完整路书的 `overview` 与 `days_detail` 都必须一天一行/一块（15 天就是 15 行与 15 个逐日块），禁止把 15 天压成 8 行交差。不要额外生成 Markdown 文件。

## 地图可视化（腾讯地图最小执行清单）

只在用户要地图 / 画线 / 标记 / 导航可视化时才做。**主交付仍是 `{路线名}-{日期}.png` + `.docx`**；地图是可选附件，不替代它们，也不写进聊天正文。

1. **判场景**：用户未指定厂商，或指定腾讯且不要求用自己的 key → **默认场景**（代理模式，用户不需要 key）。指定高德 / 百度 / 天地图，或指定腾讯但坚持用自己的 key → 用该厂商，`key="请在XX开放平台自行申请并替换此占位符"`，并说明申请入口与替换步骤。

2. **默认场景骨架**（三行，顺序不能变）：

   ```html
   <script>
     window._TMapSecurityConfig = {
       serviceHost: 'http://127.0.0.1:__WB_HTTP_PORT__/_TMapService/_wbt/__WB_TMAP_SECRET__',
     };
   </script>
   <script src="https://map.qq.com/api/gljs?v=1.exp"></script>
   ```

   - `serviceHost` 必须在 SDK `<script>` **之前**；SDK URL **不得**带 `?key=`。
   - `__WB_HTTP_PORT__` / `__WB_TMAP_SECRET__` 原样保留，运行时自动替换，不要填具体值。
   - **不得**在代码里内嵌、预置或夹带任何可用 key。
   - 不要同时调 `TMap.setConfig()`，与 `_TMapSecurityConfig` 并用会白图。

3. **硬约束**：坐标系 GCJ-02；容器必须固定高度（`100vh` 或 px），否则不渲染；`new TMap.Map()` **不传 `mapStyleId`**（自定义样式未开通会白图）；图层类带 `Multi` 前缀（`TMap.MultiMarker`），样式类不带（`TMap.MarkerStyle`）；自定义图标用内联 `data:image/svg+xml,` 或 base64，不引官方 demo 图片路径。

4. **路线与检索**：SDK URL 加 `libraries=service`；用 `TMap.service.Driving` / `TMap.service.Search`；`policy` 传字符串（`LEAST_TIME` / `LEAST_DISTANCE` / `AVOID_HIGHWAY` / `REAL_TRAFFIC`），不要用 `TMap.constants.DRIVING_POLICY.*`。**禁止**手工 `fetch(serviceHost + ...)` 拼代理 URL（会 LatLng NaN / 403）。

5. **摩旅口径**：画线默认 `AVOID_HIGHWAY`，与「国道优先、高速只作可选加速段」一致。它只是绕开高速的算路策略，**不等于摩托路权判断**；能否上高速仍看 `references/road-rights.md` 与现场禁令标志。

6. **合规自检**：国界、中国台湾、南海诸岛按国家标准绘制；不标军事禁区与敏感坐标；不公开他人位置数据。

7. 写完 HTML 直接 `present_files` 展示绝对路径；不要只 Write 就收尾，不要起 `python http.server`。

## 补丁模式

1. 引用正在改的那一天。
2. 只展示该天的改前 → 改后（公里、道路、天气备选）。
3. 重算该天的油费和住宿簇。
4. 按当前模式重跑对应渲染器（完整路书用 `scripts/render_roadbook.py`，压缩分享卡用 `scripts/render_share_card.py`），覆盖同一 `{路线名}-{日期}` 文件名。不要留下过期的 png/docx。

## 反模式

- 四轮行程上贴一句「改骑摩托」
- 把高速当默认脊梁
- 用夜路「省一天」
- 日里程照抄四轮导航、未按天气折减
- 全市美食清单与当天路段无关
- 承诺某条高速允许摩托
- 承诺「已订到房」或实时油价
- Google Maps / Mapbox / 境外 OSM 瓦片
- 地图 HTML 里内嵌 key、手拼代理 URL、传 `mapStyleId`、用了 `AVOID_HIGHWAY` 就当摩托可以上高速
- 只出地图 HTML，没出 `{路线名}-{日期}.png` + `.docx`
- 忽略 `mtp` / `MTP` / `路书` 指令
- 新规划跳过四行采集模板
- 四行之外再追问
- 默认把踏板 / 仿赛放上独库或 G318
- 跳过 `references/road-rights.md`，凭记忆猜高速/城区限行
- 写路书却不加载 `references/roadbook-template.md`
- 天数 ≥8 却只生成压缩分享卡，或把时间轴/补给/禁忌/备选留在内部笔记
- 用 Markdown/HTML 替代 `{路线名}-{日期}.png` + `.docx` 主交付
- png 超过 3 页（`TOO_TALL`）却不删字
