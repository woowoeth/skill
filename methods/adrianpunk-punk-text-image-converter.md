# Punk 图文转换 Skill

## 首次使用欢迎语

用户第一次打开或询问本 Skill 能做什么、但尚未提供文章时，使用下面这段欢迎语：

> Hi，我是 Punk，欢迎使用 **Punk 图文转换 Skill**。
>
> 这个 Skill 专门把冗长的 Markdown 或长文章，整理成适合 **小红书、微信公众号贴图和抖音图文**发布的 3:4 竖版内容。它会先理解文章结构和重点，再生成 5 张不同构图的封面供你选择；选定封面后，继续制作配色统一、图文并茂的正文卡片。排版完成后，还可以根据发布平台提供 3 套推荐标题、300 字以内的发布正文和 Tag／关键词。
>
> 开始时，把文章或 Markdown 发给我，并告诉我作者名即可。如果原文自带封面，我会先问你是否保留。

如果用户已经提交文章、Markdown 或明确任务，不重复输出完整欢迎语，直接进入固定工作流。

把文章转换成两种不同媒介的成品：

> Markdown → 理解文章 → 设计库选型 → Image 2 直接生成 5 张封面 PNG → 用户选 1 张 → HTML 正文 → PNG → 询问发布平台 → 3 套发布文案

封面和正文必须严格分阶段：

- **封面是 Image 2 直接生成的完整海报位图。**它不是 HTML，不由浏览器截图，也不是先生成无字插画再由 HTML 叠标题。
- **正文才使用 HTML。**选定封面后，正文继承其配色、字体方向、对齐轴和图形语言，再渲染为 PNG。

核心风格拆成两层：排版是现代主义编辑排版与 Swiss / International Typographic Style；图片按文章内容从 6 种已确认视觉来源中选择。Less is more：一个焦点、一条主轴、有限颜色、明确尺度差和可读负空间。

## 固定工作流

### A. 五张 Image 2 封面

1. 完整读取 Markdown，理解对象、读者、矛盾、方法、数字证据和可视化隐喻，不只拿标题做表面联想。
2. 提取唯一原始标题、可选副标题、作者、真实数字、主题关键词和 Markdown 自带封面图。若存在自带封面，先问是否将其加入五个候选之一；选择加入时适配其背景到当前配色，选择不用时改为按主题生成图片。
3. 先把长标题编译为 `display_text + detail_text`，再分别从构图、层级、字体、标题强调、配色、图片风格六个视觉库按文章主题、标题容量、素材条件和可读性筛出合格子集；只在这些合格子集的兼容交集中，以文章指纹和 `variant` 做 seeded 随机排序，选择五组明显不同的 `composition + hierarchy + title font + emphasis + palette + visual language`。随机用于避免套路化，不得绕过资格过滤或质检。五案不承担“展示五种画风”的任务，同一种最适合的视觉来源可以重复使用，甚至用于全部五张；不合适的画风一张也不生成。
4. 把每组选择编译成结构化 Image 2 提示词；一张封面一次独立生成调用。
5. Image 2 在同一张位图中完成标题、数字、插画、线条、标签和纸张色。
6. 保存进项目并规范化为 1080×1440 PNG；生成 540×720、270×360 缩略图和五案总览。
7. 逐张执行文字、构图、缩略图和审美质检。失败图不得进入五案；按稳定候选顺序补足。
8. 只展示五张 `PASS` 封面并停止，等待用户回复 `1–5`。

### B. 所选封面＋HTML 正文

1. 把选中的封面 PNG 原样作为 `page-01.png`，不得用 HTML 重画或替换。
2. 锁定配方与实际图像中确认的背景、正文色、强调色、字体方向和主轴。
3. 读取 [正文页面系统](references/inner-page-system.md)，生成正文 HTML 与正文 PNG。
4. 深色封面使用其极浅渐进色作为正文底色；原深色只作标题、规则线和少量强调。浅色封面直接继承纸张色。
5. 含封面总数不得超过 20 页。交付 PNG、HTML、缩略图、总览和质检报告。

### C. 排版完成后的发布文案

排版成品完成后才进入本阶段。若用户尚未说明平台，只问一次：`这套内容准备发到哪个平台：公众号、抖音还是小红书？` 若用户已经说明，不重复询问。

平台确定后读取 [平台发布文案](references/platform-publishing-copy.md)，输出 **3 套**可独立发布的候选。每套必须包含：

1. `推荐标题`：可直接使用，不是封面主标题的机械复述；
2. `发布正文`：300 个可见字符以内，不含标题与 Tag；
3. `推荐 Tag`：小红书与抖音使用相关话题；公众号改为 `推荐关键词`，不伪装成平台依赖的 Hashtag。

三套必须是不同的信息角度，而不是近义改写。默认覆盖：问题／搜索意图、结果／收益、教程／经验；若文章类型不适合，按文章内容替换为三个真实角度。只提供文案草稿，不自动发布。

除“从五张中选一张”和正文完成后的“选择发布平台”外，不追加设计问卷。能从文章和设计库推断的内容直接推断。

## 设计库的角色

需要向用户介绍、审阅或筛选本 Skill 的设计能力时，先展示 `assets/system-preview/index.html`。它必须是一张可从上到下连续滚动的完整系统页，同时包含封面构图、配色表、图片风格、真实字体样张、四种标题强调和正文版式；不得默认只显示其中一节，也不要只罗列 JSON 数量或文件名。

这些文件是**Image 2 封面提示词的选择库与约束源**，不是 HTML 封面模板：

- `assets/system-preview/index.html`：完整设计系统预览，其中封面部分只包含 20 种已经用户筛选确认的版式定位图；未出现在该图册中的实验构图不得进入交付候选；
- `design-system/palettes.json`：双配色、三配色与颜色角色；
- `design-system/hierarchies.json`：标题、说明、数字和微型信息层级；
- `design-system/typography.json`：字体方向、字重关系和声部组合；
- `design-system/english-font-library.json`：用户原先确认的 40 种英文字体图鉴、分类、用途与提示词；
- `assets/font-library/glyphs/`：上述英文库的 40 张原始字形样张；
- `design-system/image-styles.json`：六种已确认视觉来源、适用条件与图像合同；
- `assets/image-style-library/`：六种视觉来源的原创辨识样张；
- `design-system/selection.json`：兼容过滤、稳定排序和五案差异；
- `design-system/inner-pages.json`：正文 HTML 模板；
- `design-system/fonts.json`：字体参考与正文实际字体文件。

字体预览不得用不存在的字体名称触发统一回退。预览样张只显示 Skill 内嵌字体与当前机器确实可加载的本机字体，并标记来源；本机专有字体只作本地选择，不复制或打包进项目发行物。实际交付若依赖可移植渲染，仍以 `design-system/fonts.json` 中的内嵌字体为保底。

正文阶段还必须读取 [正文版式定位图册](references/body-layout-atlas.md)。其中 20 个编号是与配色无关的信息骨架；先按文章语义选版式，再应用已选封面的 `inner_theme`，不得把示例文章或示例配色固化进模板。

封面阶段读取 [视觉系统](references/visual-system.md)、[Image 2 封面工作流](references/image2-cover-workflow.md)、[主题视觉语言](references/image-style.md) 和 [稳定与验证](references/stability-and-validation.md)。设计库回答“选择什么”，Image 2 把选择转成一张完整海报。不得退回旧的 HTML 封面生成器。

## 封面合同

- 最终格式：PNG，1080×1440，竖版 3:4。
- 生成提示明确要求 3:4 完整海报；比例错误时优先定向编辑或重生，不裁掉标题和主题物。
- 四边视觉安全区约 72px；装饰可出血，语义文字不得贴边或裁切。
- 使用 12 栏网格、8px 基线和单一主轴作为构图语言，但不把完整网格画成装饰。
- 最多三种字体声部、三档字重、一个巨型数字事件、一个非水平方向事件和一个主视觉中心。
- 五张主标题不得全部依赖同一种字形。先按中文／英文、主题、标题长度与方向从字体库筛选，再在合格字体中 seeded 随机；整组至少出现 3 种肉眼可辨的主标题字体类别，同一类别最多主导 2 张。仅改变字体名称而字形近似，不计为差异。
- 主标题对齐由已确认版式决定，可左对齐、居中或右侧配重；不使用中文两端对齐。
- 保留 30%–70% 的有效负空间；只允许一个高密度区和一个视觉中心。
- 主题图必须解释文章。合法视觉来源仅为：Markdown 自带封面适配、Anthropic 风格插画、瑞士国际主义线条／色块／形状、扁平插画、中期现代主义复古编辑插画、纯文字排版。详见 [封面图片风格](references/image-style.md)。
- 禁止纸雕、浅浮雕、拟物卡片、悬浮图标阵列、UI 仪表盘、塑料 3D、“多个功能按钮围绕一个物件”的信息面板、写实摄影生成、动漫和无关装饰堆叠。

### 文字角色与字体方向

1. `Display`：主标题；
2. `Editorial`：一次编辑型衬线转折，可选；
3. `Information`：副标题与说明；
4. `Data`：真实数字、英文与编号；
5. `Annotation`：作者、日期与微型信息。

中文字体清单：苹方 SC、冬青黑体简体、思源黑体、思源宋体、宋体 SC、黑体简、兰亭黑 SC、圆体 SC、楷体 SC、华文仿宋、方正清刻本悦宋、幼圆。

英文视觉方向必须使用用户原先提供的「Punk Font Field Notes · 40 种英文字体图鉴」，完整清单以 `design-system/english-font-library.json` 为唯一真源：01–16 编辑衬线，17–32 现代主义无衬线，33–40 英文手写。不得再用 macOS 系统字体清单替换或近似模拟这套库。预览必须显示 `assets/font-library/glyphs/` 中的原始样张；商业字体名只作为视觉方向与图片生成提示词，不声称字体文件已内嵌。

英文手写组固定为 Biro Script、Sacramento、Caveat、Allura、Permanent Marker、Rock Salt、SignPainter、Mrs Saint Delafield。它们只用于短题签、英文批注或署名，一页最多一次，不用于正文；Biro Script 的基准方向是圆珠笔式自然笔触、轻微不齐基线与自然间距。

标题强调只有 4 种：默认层级、完整关键词使用点缀色、短下划线、使用当前 palette 点缀色的荧光笔底纹。一张封面最多使用一种；不得用大色块代替超大字。

Image 2 不能保证加载某个具体字体文件，封面配方锁定的是**可观察的字体类别、宽度、字重、字距、行距和声部关系**；正文 HTML 才锁定实际字体文件。允许 `horizontal / vertical / diagonal / curve`，但一张封面最多一次非水平事件。

### 标题语义分层与准确性

原始标题必须逐字保留，标点不变。长标题不能作为同一字号、同一字重的连续大标题处理。生成前先得到：

- `display_text`：文章的核心问题、判断、动作或主题钩子；应能独立说明文章在讲什么；
- `detail_text`：数量、范围、工具、路径、教程、对象、版本等解释性信息；
- `display_lines / detail_lines`：各自内部的合法断行；
- `split_reason`：使用了哪一个语义边界。

冒号是最高优先级边界：冒号前若能独立成立，冒号保留在 `display_text` 末尾，冒号后全部进入 `detail_text`。例如本系统的测试标题必须解析为：

```text
display_text = AI 音乐怎么赚钱：
detail_text  = 11 款主流工具、6 条变现路径和提示词编曲教程
```

没有冒号时，依次识别问句／判断句／动作句与其后的数量清单、方法范围或补充限定；短标题没有真实说明层时可全部作为 `display_text`。禁止仅按字符数机械切半。`display_text + detail_text` 必须严格等于原始标题。

提示词必须把两个角色分开写为 `Primary display text (verbatim)` 与 `Supporting detail text (verbatim)`，不得把完整长标题只列成若干同级 `Line`。视觉上：

- 主标题通常 1–2 行、112–180px 感知尺度、680–820 字重；
- 说明标题通常 2–4 行、34–58px 感知尺度、450–600 字重；
- 主副尺度比至少 1.75，两个文字块间距 48–88px；
- 数字若属于 `detail_text`，默认随说明标题排版，不自动升级为巨型数字；
- 缩略图第一眼必须先读到 `display_text`，第二眼才读到 `detail_text`。

随后分别断行：

- 优先在冒号、逗号、顿号与并列短语间换行；
- 数字与单位、产品名、专有名词和固定词组不得拆开；
- 标点不得出现在行首；连接词不得单独成行；普通汉字不得形成单字孤行；
- 最多六行；最多一次刻意短行强调；重新连接后必须等于原始标题。

Image 2 可能产生错字或伪文字。生成后必须逐项核对主标题、数字、单位与标点，并拒绝乱码、假英文、伪 Logo 和水印。无法读清的小型装饰文字应从提示中删除，不允许乱码充当纹理。单张最多两次针对性修复；仍错误则淘汰并使用下一合法配方，不能因风格好看放过文字错误。

## 五案与稳定选择

五张不能只是换色，也不能预先塞进五个固定模板槽。系统只允许从预览图册中已经确认的 20 种版式按标题容量、主题和视觉载体资格参与竞争，再选出结构差异最大的五张。每案都必须记录 `title_anchor + display_orientation + type_program + image_text_relation + dominant_mass` 组成的结构签名，五个签名不得重复。

图片风格先按文章语义做资格判断，再参与配方组合。不得为了证明风格库“丰富”而让五张各用一种插图效果，也不设置最低画风数量：教程文章可以五张都使用同一种合适的编辑插画，强标题文章可以多张甚至全部使用纯文字，文化文章也可以集中使用中期现代主义。五案的多样性来自版式、文字方向、字号尺度、标题锚点和图文关系，而不是强制换画风。

一组五张至少覆盖 5 个构图族、4 个标题锚点、4 种图文关系、4 个字体程序、3 种可辨识的主标题字体类别和 3 种 Display 方向；同一主标题字体类别最多主导 2 张，水平左对齐大标题最多两张。必须出现一次底部锚定、一次右侧对抗、一次边栏。方向从水平、竖向、斜向、曲线中选择至少三种兼容方案；曲线不强制，文字准确性优先。说明标题保持水平可读，非水平方向只用于主标题片段、真实数字或微型信息。

图文关系从 `separate-fields / edge-aligned / controlled-crossing / text-in-negative-space / type-as-image / orbital` 中选择。若五张都呈现“左上大黑体＋下方小字＋右下图形”，或黑白缩略图轮廓近似，即使颜色与插画不同也整批失败并替换相似候选。

“随机筛选／随机组合”统一指 qualified seeded variation：每个环节先从自身已确认视觉库做语义与可读性过滤，再对合格候选用文章指纹与 `variant` 做 SHA-256 稳定排序。封面依次处理版式、层级、字体、强调、配色、图片风格；正文先按内容块过滤 20 种版式与组件，再只在同等合格项中变换节奏，同时锁定封面配色。生成失败只能沿排序取下一合法候选，不能临时发明风格，也不能纯随机抽到不适合的方案。

相同文章和 `variant` 必须得到相同的五份**选择与提示词配方**。Image 2 是生成模型，不要求 PNG 像素哈希相同；稳定性来自配方锁、生成记录和验收门。

## Image 2 调用

- 默认使用内置 `image_gen`，一张封面一次调用。
- 每次提示必须明确记录所选的合法视觉来源，并包含文章主题摘要、构图、`display_text/detail_text` 的独立排版合同、字体方向、颜色面积角色、原文标题重连校验、断行和禁止项。
- Markdown 含封面时先问是否纳入候选；若纳入，保留主体并适配原底色到当前配色，最终仍输出完整海报位图。
- 每次生成后先看原图，再通过、定向编辑或淘汰。
- 项目成品必须保存进项目目录，不能只留在默认生成图片目录。
- 不生成任何第三方品牌 Logo、受保护角色或专属视觉资产；全部主题隐喻、构图和图形关系必须为当前文章重新设计。

## 正文合同

正文才使用 HTML：左上章节、右上页码、左下作者；无衬线正文优先；清爽、紧凑、图文并茂；从 20 种已确认版式中按内容语义选择，不随机抽版、不把某篇文章的文字或图片固化为模板；保留 Markdown 顺序、图片、引用、代码、表格与列表；引用保持正常层级；代码块使用主题点缀色和克制的 macOS 编辑器语言，红黄绿状态点保留功能色；小字不压复杂图片。来自 𝕏 / Twitter 的 Markdown 清除平台链接和导流 CTA，保留有意义正文。超过 19 张正文页时做忠实压缩版，不把字缩到不可读。

## 验收

封面逐张检查 1080×1440、540×720 和 270×360：

- 标题、数字、单位、标点正确，无乱码和额外伪文字；
- 一秒内找到主标题并判断主题；
- 无裁切、遮挡、低对比、贴边和错误重叠；
- 字体有粗细差，行距与块间距清楚，不是所有字都极粗；
- 需要语义分层的长标题已形成主标题与说明标题；两者尺度比至少 1.75，不能看成同一文字块；
- 只有一个中心，图片不吞标题；
- 构图简单、负空间完整，缩略图不拥挤；
- 图片风格属于 6 种确认来源之一，符合文章调性，且没有额外未确认画风；
- 与其余四张并排时差异明确，但不以牺牲可读性或过度实验换取差异。

任何错字、乱码、标题缺失、语义层级扁平、未确认画风、拟物纸雕、箭头图标地图、UI 图标阵列、3D、动漫、双重中心、遮挡或缩略图失效均为 `FAIL`，不进入五案。正文继续执行 HTML 字体、溢出、链接、图片、密度和总页数质检。
