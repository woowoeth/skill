# 照片题材打标工作流

## 目标

为一个照片根目录下的所有 JPG 照片，按"题材"维度批量打标签，写入 EXIF 元数据，方便后续在访达/预览/Lightroom/Photos.app 中检索。

题材打标和地点打标（City/Sub-location）是正交的两个维度。本 skill 只处理题材；地点打标见用户自己的 rewrite_location 脚本（如有）。

## 核心工作流

1. **配置确认**：和用户确认词汇表、是否打个人照、拼图密度。词汇表已有合理默认，多数情况可直接采用。
2. **枚举末端文件夹**：列出所有装着 JPG 的叶子目录，按路径排序。报告总文件夹数和总照片数。
3. **逐文件夹打标循环**（每个文件夹做完才进下一个）：
   1. 生成该文件夹的联系印相图 PNG（默认 6×6，超过 36 张自动分页）。
   2. 用 `open` 命令在 macOS 预览中弹出拼图，**不要**用 Read 工具看图——Read 看到的图用户看不到。
   3. 给用户列出本文件夹路径、张数；提示一级题材+二级修饰的编号表格。
   4. 等用户回复标签。
   5. 把本文件夹的标签追加写入 `<根目录>/题材标签记录.jsonl`。
   6. **立即**调用 `write_tags.py` 把这一夹标签写入 EXIF；不要等所有文件夹打完再批量写。
4. **完成报告**：所有文件夹打完后，汇报标签分布统计、跳过的文件夹清单。

## 词汇表（默认）

一级题材（不互斥，一张图可多个）：

```
 1 城市风光    2 自然风光    3 航拍       4 建筑       5 人文
 6 个人照     7 抽象几何    8 动物生态    9 花草树木   10 景物小景
11 仰望星空   12 地标打卡   13 日常随拍   14 胶片摄影   15 旅游打卡
```

二级修饰（可多选，写入时加 `#` 前缀以便和大类区分）：

```
 a 夜景    b 蓝调    c 日落    d 日出    e 晚霞
 f 樱花    g 银杏    h 红叶    i 雪景    j 雾
 k 微距    l 长曝    m 月食    n 黑白    o 全景
```

不在表里的二级修饰，用户可直接写中文（"秋景"、"烟花"、"雨景"等），脚本原样写入。

第一次启动时必须用 AskUserQuestion 让用户确认：
- 是否用默认词汇表（或修改/扩展）
- 个人照/人像类目是否要打标
- 拼图密度（默认 6×6，备选 4×4 看更清晰 / 8×8 看更密集）

## 用户回复格式

约定一种紧凑的输入语法，让用户用极少的字符表达意图：

- **整夹同一组**：`1,4` 或 `10 | h,秋景`（一级用数字，二级用字母或中文，多个用逗号或空格分隔）
- **整夹同主体 + 个别例外**：`9 | h,红叶 | 6,8: +5`（主体是「花草树木+#红叶」，第 6、8 号图额外加 5号「人文」）
- **整夹分歧大**：`split`（脚本会按子组询问或逐张询问）
- **跳过本夹**：`skip`
- **同一夹分组**：`group: 1-12=1,4 | 13-30=9,h`（按编号范围分组）

解析回复时严格按此协议，不要自行猜测。如果回复格式无法解析，明确告诉用户哪里不懂。

## EXIF 写入规则

- 一级题材：直接写入 `IPTC:Keywords` 和 `XMP-dc:Subject`，例如 `城市风光`
- 二级修饰：加 `#` 前缀写入，例如 `#夜景`
- 使用 `+=` 追加而非 `=` 覆盖，但**先**用 `-IPTC:Keywords=` `-XMP-dc:Subject=` 清空可能存在的脏标签，再追加新标签——保证幂等
- 必须加 `-charset iptc=UTF8` 和 `-IPTC:CodedCharacterSet=UTF8` 确保中文不乱码
- 使用 `-overwrite_original` 避免生成 `_original` 备份

## 关键约束（违反会让流程崩溃）

- **不要用 Read 工具显示拼图给用户看**。Read 显示的图只有助手能看到。必须用 `open <png>` 让 macOS 在用户屏幕上弹出预览窗口。
- **不要把所有文件夹的拼图一次性生成好再问**。一次一张，节奏紧凑，避免 /tmp 堆积大量 PNG。
- **每答完一夹立即写 EXIF**，不要等整体打完。这样中途中断也只损失当前一夹的进度。
- **每打完一夹要明确说出来"已写入"**，让用户确认进度，避免他怀疑没生效。
- **末端文件夹枚举要排除**：`源文件 / 缩略图 / 压缩 / 缩 / 1080p / 1080 / temp / _original / 别人校色版本 / 未标题-1-assets / 边框`。其他目录都纳入。
- **跳过的文件夹也要记录**到 jsonl，标记为 `"skipped": true`，方便后期补打。

## 用到的脚本

两个脚本放在 skill 目录的 `scripts/` 下，调用时用绝对路径或先 cd 到照片根目录后用相对路径：

- `make_contact_sheet.py <folder> <output.png> [--cols N] [--rows N]` — 生成联系印相图，支持自动分页
- `write_tags.py <folder> <一级,逗号分隔> [--mods <二级,逗号分隔>] [--files <编号或编号范围>] [--exceptions <"4,7:+5" "10:+a,b">]` — 批量写入 EXIF 标签

第一次为某个根目录工作时，把这两个脚本**复制**到根目录下（与照片同级），不要每次都从 skill 目录调用。这样脚本和数据走在一起。

## 续打与中断恢复

- 进度文件：`<根目录>/题材标签记录.jsonl`，每行一个 JSON 对象 `{"idx": N, "folder": "...", "primary": [...], "modifiers": [...]}`，跳过的 `{"idx": N, "folder": "...", "skipped": true}`。
- 启动时先 Read 这个文件，跳过已打过的文件夹（按 `folder` 字段去重），从未打的继续。
- 如果用户想重打某个文件夹，明确告诉他 jsonl 里改对应行（或删掉那行重打），脚本写 EXIF 时已经先清空旧 Keywords，所以重打能正确覆盖。

## 与地点打标共存

如果用户先用过 rewrite_location 脚本设过 City/Sub-location，本 skill 不会动这些字段——只写 Keywords/Subject。两套元数据互不打架。

## 启动提示

skill 触发后第一步：
1. 询问照片根目录（如果消息里没明说）
2. Read 该目录下的 `题材标签记录.jsonl`（如有，列出已打过的文件夹数）
3. 用 AskUserQuestion 确认词汇表+个人照+拼图密度
4. 把两个脚本复制到根目录（如果还没有）
5. 开始第一个未打文件夹的循环
