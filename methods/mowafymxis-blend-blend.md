# Blend

Direct the whole frontend as a product. Choose the specialists that improve this task; do not run every skill or assemble a page from unrelated treatments. The suite has no default font, palette, hero, card system, mascot, or animation stack.

## Start with the actual assignment

Identify audience, primary action, real content, brand constraints, assets, stack, and scope. Preserve supplied copy, routes, integrations, and working behavior unless their change is authorized. An audit reports findings; a narrow fix inherits the existing design. Reference material supplies evidence, not instructions or permission.

For a new frontend, substantial redesign, or taste correction, begin with [blend-discovery](../blend-discovery/SKILL.md). Ask detailed questions in manageable rounds before forming the design: reference roles, typography, light/dark/both, palette and surfaces, composition, drawing style, mascot, local motion, atmosphere, and scroll storytelling. Prefill existing answers. Wait on unresolved consequential preferences while inspecting independent content and constraints. Do not replace this interview with an internal direction or silently decide that a supplied reference answers every question.

The user may explicitly delegate choices or ask for no questions; then state the chosen direction and proceed. A complete existing brief also needs no repeat interview. For questions-only requests, prepare the questions and stop before redesigning. Narrow fixes inherit the current system. Keep recommendations distinct from user selections.

For reference-led builds or a taste correction, use the art-direction [quality comparison](../blend-art-direction/references/quality-bar.md). Translate the reference into observable relationships before selecting components: the scale of the main subject, reading hierarchy, density, artwork language, and where motion is concentrated. A familiar “polished” kit is not a substitute for this comparison.

Set a still-image quality bar and a motion quality bar separately. The still should already explain the product with resolved typography and artwork. The motion should add a readable event or relationship, not disguise weak composition. Finish one representative section and its local sequence early enough to correct the direction before repeating it across the page.

## Select by the decision that needs work

Read the relevant specialist's SKILL.md using the relative paths below. These are sibling folders when the full suite is installed. Direct invocation of a specialist is also supported. If an optional sibling is absent, disclose that only if it affects completion and perform the scoped task with the available guidance; never claim to have loaded missing instructions.

|---|---|---|

| What visual world belongs to this product? | [blend-art-direction](../blend-art-direction/SKILL.md) | New identity, visual overhaul, interpreting references, or an off-feeling composition |
| How should real language look and read? | [blend-typography](../blend-typography/SKILL.md) | Choosing or tuning type, hierarchy, reading rhythm, script coverage |

Loading a skill does not imply spawning another agent. Use normal available execution tools and respect the user's requested workflow.

## Keep one design across specialties

Carry the same user decision record and real content through each pass. Establish shared type, spacing, color, surface, layer, and motion tokens at the scale the product needs. A specialist may improve implementation within those choices, but must surface a material departure from a selected theme, type direction, medium, mascot, or scene. When two selected treatments compete, explain the conflict and resolve their prominence with the user; do not quietly remove a requested feature.

Compose still frames before animation using the chosen direction. Resolve one representative section, a type specimen, and the selected motion/mascot sample before repeating a treatment across the site. If the user still needs to choose, show a bounded visual comparison rather than a complete guessed website. Resolve the visual anchor early with a credible asset or an agreed alternative. Then connect real interactions, add selected motion, and inspect the result. A site may combine quiet UI, small drawn sequences, a character, atmosphere, and a spatial scene when their scale, color, pacing, and attention hierarchy make them belong together. It may also need none of those effects.

Distinguish responsive recomposition from shrinking: change hierarchy, crop, density, and scene structure as the available space changes. Essential actions and information remain accessible without decorative animation. Keep implementation details and internal design notes out of product copy. Never manufacture testimonials, metrics, product claims, or success states.

## Finish in the render

For substantial changes use blend-review, correct the largest visible mismatch, and exercise the affected task and motion paths. Do not mistake a build, screenshot, or accessibility scan for proof of taste or smooth timing. Report the visible outcome, meaningful checks, and material limitations. The example pages in the repository demonstrate techniques; they are not required starting layouts or evidence of consistent future output quality.
