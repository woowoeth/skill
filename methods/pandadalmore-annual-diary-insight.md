# 年度日记洞察

## 用途

两个功能，一纵一横，共用同一批日记 dump：

| | 功能 A · 年度洞察 | 功能 B · 全景看板 |
|---|---|---|
| 产出 | `<YYYY>年度洞察.md` | `年度洞察全景.html`（单页，离线可用） |
| 粒度 | 一年一篇，纵深 | 全部年份，横向 |
| 做法 | 精读全文后**人写** | 脚本统计后**自动生成** |
| 回答 | 这一年是什么样的 | 十年里什么在变 |
| 入口 | `references/insight-structure.md` | `references/dashboard-spec.md` |

**顺序是 A → B。** 看板的里程碑时间线直接读年度洞察里人工标记的条目，
洞察没写，看板的时间线就是空的。

**核心原则：统计负责事实校准，精读负责论点生成。**
主题词频只能说明"反复提到什么"，说明不了"发生了什么"。跳过精读、直接从统计生成文本，产出的必然是换个年份也成立的模板废话——这是这个 skill 要解决的首要问题。
（因此本 skill **不提供**"自动生成洞察正文"的脚本，理由见 `references/dashboard-spec.md` 末节。）

## 三种产出

| 产出 | 文件 | 粒度 | 说明 |
|---|---|---|---|
| **A1. 年度洞察** | `<YYYY>年度洞察.md` | 一年 | 十段结构的深度解读，主产出 |
| **A2. 人生大事记** | `人生大事记.md` | 跨全部年份 | 里程碑时间线，一年 5–8 条，含认知里程碑与未遂里程碑 |
| **B. 全景看板** | `年度洞察全景.html` | 跨全部年份 | 七模块交互式可视化，1.1 MB 单文件，无外网依赖 |

A1 与 A2 共用同一批 dump 与统计，但**判据完全不同**：
年度洞察问"这一年是什么样的"，大事记只问"哪一天之后你回不去了"。
详见 `references/milestone-taxonomy.md`。

## 适用场景

- 写某一年的年度洞察 / 年度总结 / 年度复盘
- 重写质量不达标的旧洞察
- 年份未结束时写"进行中"版本（如截至 8 月）
- 跨年对比分析（主题迁移、情绪变化、人物注意力分布）
- 整理人生大事记 / 重大事件时间线 / 里程碑清单
- 生成或更新历年全景看板 HTML

## 激活方法

这是 WorkBuddy 的 skill，由对话中的自然语言意图触发，无需手动命令。常见激活说法如下。
- 年度洞察，对我说「帮我写 202X 年度洞察」「复盘今年」「分析我的日记」
- 全景看板，对我说「生成全景看板」「把十年写进一页」「历年数据可视化」

首次激活时，先向用户确认日记库路径与洞察输出目录（见步骤 0）。

## 环境

脚本使用 Python 3.8+，仅依赖标准库，无需 pip 安装。先 `cd` 到一个工作目录再运行——
中间产物 `dumps/` 与最终的 `年度洞察全景.html` 都落在当前目录，不会污染 skill 目录。

## 功能 A · 年度洞察工作流程

### 步骤 0 · 获取库的路径
初始时直接向用户询问日记库（vault）的根目录与年度洞察的输出目录，拿到路径后再继续后续步骤。

### 步骤 1 · 导出全文
```bash
python scripts/dump_diaries.py <YEAR>
python scripts/dump_diaries.py --all        # 需要跨年基准表时
```
产出 `dumps/<YEAR>.txt`，头部含篇数、正文字数、平均字数、月度分布——**这些数字直接抄进「数字快照」，不要手工估算**。
同时留意头部的「已排除非日记文件」清单，确认排除正确。

### 步骤 2 · 统计
先扫一眼 dump，按当年语境增删 `scripts/themes.json` 的关键词与 `markers`（例：你某年才启用了某种自评符号，或某年才出现某个专有称呼），再运行：
```bash
python scripts/year_stats.py <YEAR>
```
输出：数字快照 / 月度分布（含断更月）/ 主题分布 / 关键词 Top N / 自定义标记 / 金句候选。
金句候选给两份清单——**全年最长**和**每月最长**，必须结合使用，只用前者会让金句扎堆在某一两个月。

### 步骤 2.5 · 里程碑候选
```bash
python scripts/milestones.py <YEAR>
python scripts/milestones.py --all        # 写人生大事记时用，附跨年模式报告
```
输出三块：外部事件候选（六类）/ 认知里程碑候选（只在超长篇内匹配）/ 模式词报告。

**输出的一切都只是候选。** 词典命中 ≠ 事件发生——真实教训：某年某篇命中"失业"，
但原文说的是对失业的**担忧**，作者年底仍在原单位。**每一条都必须回原文确认。**

`--all` 会打印跨年模式报告（如「某反复出现的主题出现于 N/N 年」）。
出现年份越多，越说明它不是里程碑而是终身模式，应写进「被忽略的角落」。

### 步骤 3 · 精读（不可跳过、不可自动化）
完整通读 `dumps/<YEAR>.txt`。篇数多的年份分段读，但必须读完。
带着七个问题读：转折点在哪 / 哪句话说了不止一次 / 哪个承诺没兑现 / 谁的名字在变多变少 / 他自己提出却没回答的问题 / 哪篇写得特别长 / 去年那封信的追问今年答了吗。
详见 `references/close-reading-method.md`。

### 步骤 4 · 写作
严格按 `references/insight-structure.md` 的十段结构：
**一句话 → 数字快照 → 年度大事记 → 四大主题 → 身份画像 → 高频人物 → 情绪底色 → 被忽略的角落 → 金句录 → 给下一年的你**

写「人生大事记」时改用 `references/milestone-taxonomy.md` 的格式：按年分组，
每条含 日期 / 类目 / 事件 / 原文 / **之后**（这件事改变了什么）。写不出「之后」的条目直接删掉。

该文件给出每段的硬性要求，以及取自真实定稿的正例与模板腔反例。写完每段自检一次：**把年份换掉，这段还成立吗？成立就重写。**

### 步骤 5 · 校验
```bash
python scripts/verify_insight.py --year <YEAR>
```
自动检查：篇数一致性、极值断言、乱码字符、frontmatter、核心九段完整性、金句时间跨度，
外加提示级的年度大事记检查（条数是否 5–8、是否每条都有日期）。
**这一步必跑**——历史上出现过 7 个年份篇数虚报、3 篇同时宣称"历年最多"等事故。

## 功能 B · 全景看板工作流程

前提：想让时间线有内容，相关年份的洞察必须已写完，且「年度大事记」表格带 `是否里程碑` 列。

### 步骤 1 · 确保 dump 齐全
```bash
python scripts/dump_diaries.py --all
```
看板按 `dumps/<YYYY>.txt` 自动识别年份，缺哪年就少哪年，不会报错——**跑完核对一下年份清单**。

### 步骤 2 · 生成
```bash
python scripts/gen_dashboard.py \
    --dumps ./dumps \
    --insight-dir "<你的洞察目录>"
```
常用参数：`--years <起始年>-<结束年>` 限定范围、`--out` 指定输出、`--title` 改标题、
`--no-milestones` 在洞察尚未写完时先出一版没有时间线的。

脚本会打印年份跨度、总篇数总字数、情绪关键词数、金句数，以及**逐条列出提取到的里程碑**。
里程碑那份清单要逐条扫一眼——它直接反映洞察里的人工标记是否正确。

### 步骤 3 · 体检
```bash
python scripts/verify_dashboard.py 年度洞察全景.html
```
检查占位符残留、CDN 引用、DATA 可解析、七模块非空、维度一致性、里程碑日期合法性。
**这一步必跑**——「数据都消失了」那次故障，肉眼看 HTML 是好的，只有逐模块查才发现问题。

人工再确认两件事：
- 浏览器打开后七个模块都有内容。若 01/03/04 空白而 02/05/06/07 正常，
  是图表库没嵌进去，检查 `assets/` 下两个 js 是否存在
- 里程碑标签若暴露了公司名、宠物名等隐私，改 `scripts/milestone_labels.json` 的覆盖表重跑，
  **不要去改年度洞察原文**

七个模块的数据契约、词典选择、四次历史事故详见 `references/dashboard-spec.md`。

## 不可违反的规则

1. **禁止用正则抽取中文人名。** 早期版本把"方式""方向""养老""陆家嘴""任重道远"都识别成了人名。高频人物一律靠精读人工判定。
2. **任何「历年最…」必须对照 `verify_insight.py` 打印的基准表。** 不确定就加限定词（「近 N 年以来最多」）。
3. **金句必须逐字引用并标注日期**，不得润色，时间跨度至少覆盖 5 个月。
4. **篇数、字数一律取脚本输出**，禁止估算。
5. **年份未结束时**，frontmatter 加 `status: 进行中`，标题写「（截至 X 月 X 日）」，文末注明年末需重跑。
6. 洞察写入你的洞察目录（如 `<你的洞察目录>`），不要放回日记年份目录（会被 dump 误统计）。
7. **里程碑必须是不可逆的状态改变。** 反复出现的事（删游戏、立志早睡）是模式不是里程碑。
   `milestones.py` 的输出是候选不是结论，每条都要回原文看过才能写进大事记。
8. **推断出的日期必须标注推断依据。** 例：某人生日无直接记载，只能写「约某年某月下旬
   （日记某段至某段断更 N 天）」，不得直接给一个看起来精确的假日期。
9. **看板的里程碑只能来自年度洞察中人工标记的条目**，禁止改回关键词自动检测。
   历史事故：关键词把某外部事件判到了它被「提及」的年份，而非真实发生的年份。
10. **看板的图表库必须内联，不许改回 CDN。** 国内网络下 jsdelivr 失败会让三个模块整片空白。
    HTML 因此有 1.1 MB，这是刻意的取舍。
11. **看板里的数字不要反向抄进洞察正文。** 词典有称呼歧义（某年「育儿/家庭」命中了几十篇，
    但那年作者还没有孩子——某个称呼当时指伴侣）。看板是索引，洞察的事实以精读为准。

## 文件说明

| 文件 | 用途 |
|---|---|
| `scripts/dump_diaries.py` | 导出年度日记全文，自动排除洞察/索引类文件（A、B 共用） |
| `scripts/year_stats.py` | 主题/情绪/关键词/标记统计与金句候选 |
| `scripts/milestones.py` | 里程碑候选抽取 + 跨年模式报告 |
| `scripts/verify_insight.py` | 成稿后的事实校验 |
| `scripts/gen_dashboard.py` | **全景看板生成**：读 dump + 洞察，产出单页 HTML |
| `scripts/verify_dashboard.py` | 看板成品体检：占位符/CDN/模块非空/维度一致性 |
| `scripts/themes.json` | 主题词典，按年份语境调整（统计与看板同源） |
| `scripts/emotions.json` | 情绪词典：积极/消极/反思，看板专用 |
| `scripts/milestones.json` | 里程碑词典：六类外部事件 + 认知词 + 模式词 |
| `scripts/milestone_labels.json` | 看板时间线的标签覆盖表（脱敏、精简、剔除） |
| `assets/echarts.min.js` | 图表库，内联进 HTML，消除 CDN 依赖 |
| `assets/echarts-wordcloud.min.js` | 词云扩展 |
| `references/vault-profile.md` | 路径、历年基准表、称呼消歧、生平锚点 |
| `references/insight-structure.md` | 十段结构规范与正反例 |
| `references/milestone-taxonomy.md` | 里程碑判据、三种类型、条目格式 |
| `references/close-reading-method.md` | 精读方法与七类失败模式 |
| `references/dashboard-spec.md` | 看板七模块规格、DATA 契约、四次历史事故 |

## 扩展到其他日记库

脚本不内置任何路径默认值，必须显式传入 `--vault` / `--insight-dir` / `--dumps`，
或在 `references/vault-profile.md` 里约定好你库的路径。换库时需要：
1. 重写 `references/vault-profile.md`（新库的基准表与人物表）
2. 重新校准 `themes.json` 与 `milestones.json`
3. 清空 `milestone_labels.json` 的 `overrides`（那是你自己的脱敏映射，不应随库发布）

十段结构、里程碑判据、精读方法、看板七模块结构均通用。
看板的年份范围自动从 dump 目录识别，页面文案（「把十年写进一页」）按年数自动改写，无需改代码。
