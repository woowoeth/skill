# se-design — 코드보다 먼저 디자인

"전문가가 만든 것 같다"는 결과물의 속성이 아니라 **작업 순서의 속성**이다. 디자이너가 하는 일을 순서대로 한다.
세 레퍼런스 앱(Job Monitor·Dataset Explorer·Release Desk)을 만들며 사용자가 "밋밋하고 양산형"이라 한 것을 "큰 발전"으로 바꾼 규칙들이다.

## 1. 디자인 플랜 — 화면마다 10줄, 파일 상단 주석으로 남긴다
```
/**
 * <화면 이름> — <패턴> 패턴.
 *  목적       : 이 화면이 답하는 단 하나의 질문. (예: "지금 괜찮은가"를 3초 안에)
 *  첫 시선    : 사용자가 처음 3초에 봐야 할 것. (예: 상태 스트립 → 빨간 실패 카운트)
 *  주 액션    : primary 하나. 없으면 "없음(읽는 화면)". 보조·위험 액션도 적는다.
 *  정보 계층  : 위→아래 순서. (제목 → 요약 → 1차 분류 → 2차 필터 → 목록 → 상세)
 *  밀도       : compact / comfortable, 컨텐츠 폭.
 *  액센트     : 액센트 색을 쓸 곳 (2–3곳 이내).
 *  3상태      : 로딩·빈·에러를 각각 어떻게.
 *  톤         : se.identity.json의 tone — 문장 어미까지.
 */
```
플랜을 쓰면서 답이 안 나오는 항목이 있으면 화면이 아직 정의되지 않은 것이다. 코드로 넘어가지 않는다.

## 2. 정보 설계 — 순서가 품질의 절반
- **요약 → 분류 → 목록 → 상세.** 표만 덩그러니 있는 화면은 실패다. 목록 위에 "지금 상태" 한 줄(시그니처)과 1차 분류 탭이 있어야 한다
- **읽히는 화면이 아니라 스캔되는 화면.** 상태는 형태로(pill·점·미터), 숫자는 우정렬 tabular, ID는 mono
- **겹치지 않는다.** 헤더에 있는 정보를 사실 행에, 사실 행의 정보를 탭에 또 쓰지 않는다
- **빈 곳은 안내로 채운다.** 상세 개요 탭이 60% 비면 "쓰기 전에"·"최근 변경"·"관련 항목"을 넣는다
- **필터는 URL에.** 새로고침·공유해도 같은 화면

## 3. 구성 규칙 — 디자이너의 기본기
- 4pt 리듬. 섹션 간 24px(`gap-6`), 요소 간 16(`gap-4`), 밀집 8. 레이아웃은 grid/flex + gap — 개별 margin 금지
- 컨텐츠 최대 폭 1120px, 폼은 720–900px. 표가 화면 끝까지 늘어나지 않게
- 타입 8단계만: 페이지 제목 28 · 핵심 숫자 28 · 카드 제목 14 semibold · 본문 14 · 보조 13 · 라벨 12. "다 같은 목소리"를 피한다
- **액센트는 확신 있게, 한두 곳에.** 시그니처의 상태 블록은 단색 액센트로, 활성 탭 밑줄, 선택 행, primary 버튼. 나머지는 회색. 액센트를 아끼면 "회색 관리자 화면"이 된다 (실제 리뷰에서 6점 → 9점의 차이)
- 의미 색(success·warning·danger·info)은 액센트가 아니다. 상태에만 쓴다. 액센트 hue는 의미 색과 18° 이상 떨어져 있어야 한다(토큰이 검사)
- 표는 조용하게: 바깥 테두리 없이 행 구분선만, 헤더 12px muted, 행 44px(comfortable)
- 카드는 역할이 있을 때만. 보더·배경·그림자 중 하나만. 모든 블록을 카드로 만들지 않는다
- 컨트롤 질감: 얇은 보더 + 1px 그림자(`shadow-xs`). 납작하지도 튀어나오지도 않게
- 모션은 상태 전이에만 150–220ms: 숫자 트윈, 탭 밑줄 슬라이드, 페이지 진입 rise, 행 호버 액션. 장식 애니메이션 금지, `motion-safe:`

## 4. 안티패턴 — "AI가 만든 티"
이모지 아이콘 · 전부 가운데 정렬 · 그라디언트 히어로 · 모든 블록이 같은 둥근 카드 · 보라–파랑 조합 · 데이터 없는 KPI 타일 나열 · 설명 없는 대시보드 · 100% 회색 뉴트럴 · 내용 없는 "환영합니다" 화면 · 섹션마다 01·02·03 장식 · 모든 것에 그림자 · **표만 화면 끝까지 꽉 찬 목록** · 아이콘 하나+문장 둘로 끝나는 빈 상태 · 장식용 검색창(⌘K가 실제로 동작해야 한다)

## 5. 카피 — 디자인 재료
- 톤은 `se.identity.json`의 `tone`: `terse`(~합니다/~없습니다) · `friendly`(~해요/~없어요) · `procedural`(~되었습니다/~하십시오). 한 서비스 안에서 섞지 않는다
- 버튼은 동사: "재시도" "승인하기" "필터 초기화". "확인/취소" 대신 무엇을 하는지
- 에러 = 원인 + 해결: "스케줄러(scheduler-01)에 연결할 수 없습니다 · 다시 시도"
- 빈 상태 = 왜 비었는지 + 다음 행동: "조건에 맞는 잡이 없습니다 · 필터 초기화"
- 시간은 상대("3분 전") + 절대(title). 숫자는 `toLocaleString`

## 6. 확인 — 스크린샷 1회 (필수)
구현 후 1440·1024 폭, 라이트·다크, 빈·에러 상태(`?__state=empty|error`)를 찍어 아래 루브릭으로 스스로 채점한다. 7점 미만 항목이 있으면 고친 뒤 다시 찍는다.
| 항목 | 묻는 것 |
|---|---|
| 계층 | 첫 3초에 봐야 할 것이 맨 위에 있는가. 요약→분류→목록 순서인가 |
| 정렬·간격 | 1024에서 깨지는 곳이 없는가. 카드 높이가 맞는가. 줄바꿈으로 깨지는 라벨이 없는가 |
| 밀도·디테일 | 다이얼로그가 드로어 위에 뜨는가. 라벨이 한 줄인가. 숫자가 줄맞춤인가 |
| 일관성 | 다른 화면과 버튼·표·배지 질감이 같은가 |
| 개성 | 서비스 색이 첫 시선에 보이는가. 시그니처가 있는가 |
| 상태 | 로딩·빈·에러가 있고 빈 상태에 다음 행동이 있는가 |
| 카피 | 톤이 일관되고 버튼이 동사인가 |
| 접근성 | 키보드로 행·탭·다이얼로그를 다룰 수 있는가 |

## 7. 실제로 겪은 결함 — 같은 실수를 반복하지 않기
- `ChartCard`에 `h-full` → flex 부모 높이를 순환 참조해 위 블록을 눌러버림. 차트 높이를 맞추는 걸로 해결
- 삼항 양쪽의 같은 `Button`이 DOM 노드를 재사용 → 위자드 "다음" 클릭이 submit. `key`를 다르게
- 확인 다이얼로그 z-index가 드로어보다 낮아 옆에 뜸 → Dialog `z-[70]/[80]`, Sheet `z-50`
- 호박색(45°) 액센트가 warning/danger와 헷갈림 → 토큰이 18° 규칙으로 거부. 자두(310°)·인디고(235°)로
- 워크스페이스 패키지 export가 바뀌면 dev 서버는 재시작해야 한다 (HMR이 옛 모듈 그래프를 캐시)
