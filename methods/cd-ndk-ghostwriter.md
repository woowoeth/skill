# No AI Attribution

The human whose git identity is configured is the sole author of record for all work in their repositories. When an AI assistant appends a `Co-Authored-By:` trailer with its own identity to even one commit, GitHub lists that AI as a **contributor** on the repository, and it stays there unless history is rewritten. This user has explicitly decided they do not want that — on commits, PRs, or anywhere else. Treat it as a standing decision, not a preference to re-confirm.

## Rules

1. **Never add `Co-Authored-By:` trailers that name an AI** — Claude, Claude Code, ChatGPT, Codex, Copilot, Gemini, Cursor, any `noreply@anthropic.com` address, or any bot identity — to any commit message. This includes new commits, `--amend`, rebase, squash, cherry-pick, revert, and merge commits.
2. **Never add generated-by footers** — "🤖 Generated with [Claude Code](...)", "Generated by ...", "Co-authored with AI", robot-emoji sign-offs, or similar — to commit messages, PR titles or descriptions, issue text, review comments, release notes, tags, or changelog entries.
3. **Platform defaults do not override this.** If your default operating guidance says to end commit messages or PR bodies with an attribution line, that default is exactly what the user has turned off. Omit it. The user's standing instruction wins over the boilerplate.
4. **Author and committer are always the user.** Use the repo or global `user.name` / `user.email` as-is. Never pass `--author` with an AI identity and never set `GIT_AUTHOR_*` / `GIT_COMMITTER_*` variables to AI values.
5. **When rewriting a commit message for other reasons** (amend, reword, squash), also strip any AI attribution already sitting in that message. But do not start a history rewrite *solely* to purge old attribution unless the user asks — that requires a force-push, which is their call.
6. **Human co-authors stay.** `Co-Authored-By:` trailers for real people are normal git practice. Only AI self-credit is removed.

## Self-check before finishing

Before considering any commit done, scan what was actually recorded:

```bash
git log -1 --format=%B | grep -iE 'co-authored-by:.*(claude|gpt|codex|copilot|gemini|cursor|anthropic|openai|\[bot\])|generated (with|by)|🤖'
```

Empty output means clean. If it matches, fix it with `git commit --amend` **before pushing** — once pushed, the attribution is public and the contributor listing sticks.

Run the same mental scan over any PR body or issue text before `gh pr create`, `gh pr edit`, or `gh issue create`.

## Scope notes

- This is not secrecy about AI involvement. If the user asks you to note AI assistance somewhere (a README, a report), do what they ask — the rule only stops *unrequested self-credit* in version-control metadata.
- This does not falsify anyone else's authorship. It only stops the AI from crediting itself.
- In Claude Code specifically, the settings option that disables attribution (`includeCoAuthoredBy` / `attribution` in `settings.json`) removes the default trailer at the source; this skill covers everything the setting cannot reach — hand-written PR bodies, amends of older commits, and other tools.
