# Windows 카카오톡

실행 중인 공식 Windows 카카오톡 앱의 화면을 읽고 조작한다. 이 스킬은 macOS용 `katok` CLI를 Windows로 빌드한 것이 아니다. 현재 화면에서의 대화 조회·검색과 개별 메시지 입력·전송을 위한 Computer Use 절차다.

## 실행 경로

현재 사용 가능한 `computer-use:computer-use` 스킬과 그 스킬의 `docs/guidance.md`, `docs/api.md`, `docs/confirmations.md`를 따른다. 같은 대화에서 이미 읽은 동일 버전의 문서를 매번 다시 읽지는 않는다. 현재 세션의 스킬 목록에서 Computer Use의 실제 설치 경로를 확인한다. 사용자명이나 플러그인 버전이 포함된 다른 PC의 경로를 그대로 사용하지 않는다.

- Windows 앱 제어는 `mcp__node_repl__js`의 `@oai/sky` API로만 수행한다.
- 브라우저용 `mcp__cua_repl`에서 native API가 꺼져 있어도 별도의 Windows `node_repl` 경로가 있을 수 있다. 두 도구를 구분한다.
- 해당 런타임이 없거나 초기화·창 읽기에 실패하면 사용 가능하다고 보고하지 않는다. 셸 UIAutomation, 비공개 helper 프로토콜, 카카오톡 DB·암호화 키 접근으로 우회하지 않는다.
- 설치·설정 요청만으로 대화를 수집하거나 전송하지 않는다. 로그인·보안·개인정보 권한 화면은 사용자가 직접 처리한다.

새 JavaScript 세션에서 초기화한다.

```javascript
if (!globalThis.sky) {
  const { sky } = await import("@oai/sky");
  globalThis.sky = sky;
}
```

실행 중인 카카오톡은 별도 호출의 `sky.list_windows()`로 먼저 찾는다. 사용자 지정 방이 이미 열려 있으면 그 창을 바로 관찰하고 메인 창을 거치지 않는다. 없으면 `sky.list_apps()`와 메인 UI를 사용한다. 반환된 `app`과 `id`만 사용하고, 창 제목·프로세스·현재 화면을 대조해 정확히 하나의 창을 선택한다. 결과 출력은 필요한 대상 후보로 좁힌다. HWND, 좌표, screenshotId, 요소 번호를 세션 간 저장하거나 추측하지 않는다. 상세 절차는 [references/ui-workflow.md](references/ui-workflow.md)에 있다.

## 조회와 검색

1. 사용자가 지정한 대화방·검색어·기간을 기준으로 필요한 화면만 연다. 설치 점검은 메인 창 한 장이면 충분하며 대화방을 순회하지 않는다.
2. `get_window_state`로 현재 화면을 읽는다. 카카오톡 접근성 트리에는 대화방 이름이나 본문이 빠질 수 있으므로 스크린샷을 함께 확인한다.
3. 화면에서 확인한 검색 버튼·대화방·검색 결과만 조작한다. 메인 대화방 검색과 방 안의 메시지 검색을 혼동하지 않는다. 동명 대화방은 제목만으로 선택하지 말고 화면에 보이는 참여자·맥락으로 구분하며, 여전히 모호하면 사용자에게 확인한다.
4. 한 호출에서 관찰하고 멈춘 뒤, 다음 호출에서 관찰 근거에 따른 입력 한 번과 새 상태 읽기를 수행한다. 입력 후 이전 좌표·요소 번호를 재사용하지 않는다.
5. 결과에는 실제로 읽은 범위와 필요한 짧은 인용만 제공한다. 화면에 없거나 아직 로딩되지 않은 과거 메시지를 없다고 단정하지 않는다. 스크린샷과 대화 본문을 파일·로그·외부 서비스에 기본 저장하지 않는다.

화면 조회는 읽음 표시를 바꿀 수 있다. 사용자가 읽음 상태 유지를 요구하면 읽지 않은 방을 열기 전에 이 제약을 설명한다. 읽음 상태 보존을 보장하지 않는다.

## 초안과 전송

- 준비: 정확한 대화방과 최종 텍스트를 확정한다. 입력·전송 직전의 방, 입력창 내용, 마지막 말풍선 위치를 비교 기준으로 확인한다. 이 기준과 승인 정보는 현재 작업 메모리에만 둔다. 단순히 “전송 기능을 설치해”라는 요청은 테스트 메시지를 보낼 권한이 아니다.
- 초안: 사용자가 채팅 입력창에 입력하라고 요청한 경우에만 수행한다. 현재 방과 실제 입력 포커스를 확인하고, 기존 작성 중인 내용이 있으면 임의로 덮어쓰지 않는다. 입력 뒤 전체 초안을 화면으로 확인하고 전송 버튼·Enter를 누르지 않는다.
- 전송: 현재 적용되는 Computer Use 확인 정책에 따라 **실행 시점에 정확한 방·최종 내용·지금 전송한다는 행동의 확인**을 받는다. [전송 절차](references/ui-workflow.md#전송)를 적용한다. 민감한 내용을 입력하는 단계부터 전송으로 취급하는 정책도 확인한다.
- 검증: 전송 직전 기준보다 뒤에 최종 텍스트와 일치하는 새 발신 말풍선이 생기고 입력창이 비었는지 함께 확인한다. 예전의 동일 문구나 빈 입력창만으로 성공을 보고하지 않는다. 표시된 전송 상태를 보고하고 상대방 수신·읽음까지 추정하지 않는다.
- 입력 오류: 도구가 오류를 반환해도 입력은 이미 반영됐을 수 있다. 같은 방을 다시 읽어 최종 텍스트가 정확히 전부 입력됐다면 재입력하지 않는다. 비어 있거나 부분·다른 내용·다른 방이면 덮어쓰거나 다시 입력하지 않고 멈춘다.
- 전송 오류: 자동 재전송하지 않는다. 창을 다시 연결해 읽기만 수행하고 전송 직전 기준과 비교한다. 새 발신 말풍선의 증거가 부족하거나 화면과 접근성 정보가 충돌하면 `전송 여부 미확인`으로 보고한다. [오류 복구 표](references/ui-workflow.md#오류-복구)를 적용한다.

## 기능 범위

- 제공: 화면 조회, UI에서 제공하는 대화방·메시지 검색, 개별 텍스트 초안과 확인 후 전송 절차.
- 파일·이미지: 이번 스킬의 검증 범위에 포함하지 않는다. 요청되면 별도 작업으로 업로드 UI와 권한을 확인한다. 텍스트 전송 절차를 그대로 재사용해 첨부를 보내지 않는다.
- 제공하지 않음: 전체 DB 자동 추출·복호화, BM25/임베딩 인덱스, 모든 방의 백그라운드 동기화, 예약·반복·대량 발송, 수신자 목록 순회.
- TXT 아카이브 검색이 필요하면 별도 작업으로 다룬다. 이 스킬이 `katok sync`, `index`, `send` 명령을 제공한다고 주장하지 않는다.

## 완료 보고와 기록

결과는 `화면 조회 확인`, `초안 입력 확인`, `전송 확인`, `전송 여부 미확인`으로 구분하고 실제 확인한 단계까지만 보고한다. 보통 한 번의 성공적인 전송은 방과 전송 완료를 짧게 알리면 충분하다.

일반 조회·단건 전송마다 보고서 파일을 만들거나 Obsidian 검증을 반복하지 않는다. 사용자나 상위 지침이 기록을 요구한 경우에는 따른다. 스킬 수정·새 실행 경로 검증처럼 재사용할 변경은 정본의 현재 상태를 갱신하고 간결한 실행 기록을 남긴다. 옛 `미검증` 상태 뒤에 완료 문장만 계속 덧붙이지 않는다. 대화 본문·수신자·스크린샷은 기록에 기본 저장하지 않는다.
