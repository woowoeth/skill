# 概念学习资料生成器 (Concept Learning Material Generator)

本 Skill 的目标：把一个"概念"变成一个**可学习、可复核、可复用**的结构化资料，而不是一段 AI 聊天记录。
它适用于课程学习、读书笔记、技术调研、新人 onboarding 等任何"我要搞懂 X"的场景。

---

## 一、适用场景 (When to use)

- 用户说"帮我学习 / 搞懂 / 整理 / 出一份资料 关于 <概念>"。
- 用户在做某个主题的调研，需要把零散信息收敛成一份带来源的笔记。
- 用户需要为团队或课程产出可复用的概念说明（如 Agent、上下文、Skill、RAG……）。
- **不适用**：纯代码实现、纯文本翻译、一次性问答（这些用普通对话即可）。

触发判断：若用户给的是一个**名词/概念/术语**，且期待一份"资料"而非一句话答案，则使用本 Skill。

---

## 二、输入信息 (Input)

调用时尽量收集以下信息（缺省项可合理假设，但要在生成物中标注"假设"）：

1. **概念名称**（必填）：如 `Agent`、`大模型的上下文`、`Skill`。
2. **学习视角 / 背景**（可选）：如"从 AI Agent 工程角度""面向大三学生""用于面试复习"。
3. **目标产出格式**（可选，默认 HTML）：`html`（默认，独立可打开）、`md`。
4. **输出路径**（可选，默认 `learning-materials/<slug>.html`，slug 为概念英文/拼音短名）。
5. **已有偏好**（可选）：配色、语言（默认中文）、是否要 Mermaid 图。

---

## 三、生成步骤 (Procedure)

> 核心理念：**先找真实来源，再写自己的话。禁止凭空编造引用链接。**

### Step 1 — 拆解与检索 (Research first)
- 先用 `WebSearch` 检索该概念的**权威、可核查来源**，优先顺序：
  1. 官方文档 / 官方工程博客（如 Anthropic、OpenAI、Google DeepMind、AWS）。
  2. 经典论文（arXiv，如 Attention Is All You Need）。
  3. 领域公认的技术博客 / 综述（如 Lilian Weng 的 Lil'Log、Weaviate、AWS 中国博客）。
  4. 课程 / 百科（仅作辅助，不单独作为主来源）。
- 记录每条来源的**真实 URL 与标题**，稍后原样写入"参考来源"。
- 若概念太新或来源稀少，明确标注"公开可靠来源有限，以下为基于既有资料的推论"。

### Step 2 — 结构化组织 (Organize)
按下面的"输出结构"把内容组织成 8 个板块。每个板块都要用自己的话写，**不得整段照搬任何来源或 AI 对话原文**；引用处用 `[来源 N]` 标注。

### Step 3 — 撰写个人解释 (Personalize)
"个人解释"板块必须以**第一人称**写，体现学习者自己的理解（"我理解它其实是……""它和 Y 最大的不同是……"）。这部分可由 AI 起草，但应留出供本人修改的空位或明显标注，便于人工复核。

### Step 4 — 生成文件 (Generate)
- 生成独立 HTML：内联 CSS（不依赖外部样式表，便于直接双击打开），使用清晰的卡片/分区布局，浅色主题，中文排版。
- 顶部放概念名、一句话定义、生成日期。
- "参考来源"用 `<ol>` 列出，每条含**可点击真实链接**与一句话说明。
- 如需要，可用 Mermaid（通过 CDN `https://cdn.jsdelivr.net/npm/mermaid`）画一张关系/结构图，并附文字说明兜底（防止离线无法渲染）。

### Step 5 — 自检 (Self-check)
执行下方"自检要求"清单；不通过则修正后再交付。

---

## 四、输出结构 (Output structure)

每份资料必须包含以下板块（HTML 中的 `<section>`）：

1. **学习目标** — 学完这份资料后，应能回答/做到什么（3 条左右）。
2. **核心问题** — 围绕该概念最该搞清楚的 2–4 个问题。
3. **个人解释** — 第一人称、用自己的话概括"它到底是什么"。
4. **核心机制 / 组成** — 它由哪些部分构成、如何运作（可用列表/图示）。
5. **应用场景** — 一个**具体**的例子（说明谁、在什么环节、用它解决了什么）。
6. **易混淆 / 使用边界** — 常与什么概念搞混、什么情况下不适用或会失效。
7. **自测问题** — 3–5 道简答题/选择题，附答案或答题要点（折叠或置于文末）。

   **自测题出题规范（务必遵循，确保可真正用于自我测验）**：
   - **题型组合**：3–5 道简答题 + 1–2 道选择题 + 1–2 道应用题（"请描述 / 举例"类）。
   - **覆盖维度**：①概念辨析（与易混概念的区别）；②核心机制（组成 / 运作）；③具体应用场景；④风险与边界（何时失效 / 常见失败模式）。
   - **答案格式**：每题配答案或答题要点；选择题给出正确选项并简述理由；答案置于 `<details>` 折叠区，便于先自测再看；应用题给"答题要点"而非唯一标准答案。
   - **语言**：题干与答案用中文，可保留英文术语（如 Planning / Tool Use / Workflow）。

8. **参考来源** — 真实、可核查的链接列表，带编号。

---

## 五、资料来源要求 (Source requirements)

- **禁止伪造**：不得编造 URL、论文编号、作者或"据说某大厂说过"。
- **可核查**：每条来源必须是真实存在、可点击、内容相关的链接；不确定是否仍有效时，先 `WebFetch` 验证。
- **主来源优先官方**：概念的解释以官方文档/论文为准，博客仅作补充与通俗化。
- **标注引用**：正文中用 `[来源 N]` 对应"参考来源"列表，便于回溯。
- **区分事实与观点**：官方事实、他人观点、本人理解要分开写，不混为一谈。

---

## 六、自检要求 (Self-check before delivery)

交付前逐条确认，全部为"是"方可提交：

- [ ] 概念名称明确，且资料确实围绕该概念展开？
- [ ] 8 个板块齐全（目标/问题/解释/机制/场景/边界/自测/来源）？
- [ ] "个人解释"是第一人称、非照搬来源？
- [ ] 所有参考链接都是**真实可点击**的（未伪造）？
- [ ] 没有整段复制 AI 对话或某一来源原文？
- [ ] 应用场景是具体例子，而非空泛描述？
- [ ] "自测问题"含题型组合（简答/选择/应用）且覆盖概念辨析、机制、应用、风险四维度？
- [ ] HTML 可独立打开、无明显排版错乱？
- [ ] 若使用了 Mermaid 图，有文字说明兜底？

---

## 七、示例调用 (Example invocations)

- "用 concept-learning-generator 学习一下 Agent，做成 HTML 放到 learning-materials/agent.html"
- "帮我生成'大模型的上下文'的学习资料，视角是 AI Agent 工程，输出中文 HTML"
- "我想搞懂 Skill 在 AI Agent 里是什么，给我一份带来源的学习卡片"

> 注意：本 Skill 面向任意概念，不要把它写成只服务于 Agent / 上下文 / Skill 三个概念的一次性提示词。新增概念时，只需提供概念名，重复 Step 1–5 即可。
