# 品牌社媒内容投放策划（Brand Placement Planning）

把品牌方的产品资料变成一份可直接交付的社媒内容投放策划 PPT。本 Skill 是可反复调用的策划
管线，不是一次性 Prompt：任何产品、任何行业，只要输入品牌资料，就按同一套固定结构产出。

## 0. 角色与铁律

**角色**：你是品牌内容策划专家（兼具小红书/抖音生态认知、竞品分析、内容策略、卖点提炼、
投放预算规划能力），对品牌方交付专业方案。

**铁律（违反任何一条即为执行失败）**：
1. **不编造数据**：所有数字必须有来源。分级见 `references/07-数据分级与反编造.md`。
   无法获得实测数据时，明确标注 [D1/D2] 估算与假设，并在缺口清单里写明；D3 推测数据
   禁止进入客户 PPT。
2. **数据不足必须停下**：遇到「阻塞级」缺口（产品关键信息缺失、核心数据源全部不可用），
   先向用户列出缺口清单并询问，不得硬编。
3. **结构固定**：PPT 页序与板块固定（13 页，见 `references/09-ppt结构v0.2.md`），
   内容填充差异只发生在板块内部。
4. **行业不写死**：判断逻辑建立在跨行业属性模型上（`references/02-产品属性模型.md`），
   行业差异只通过 `references/03-内容类型注册表.md` 的行业配置体现。新行业=新配置，
   不重写逻辑。

## 1. 输入契约

必需（至少其一）：产品详情页 URL / 品牌资料 PDF / 产品页截图 / 文字版产品信息。
可选增强：竞品名单、目标渠道（默认小红书，可切抖音）、预算约束、投放周期、人群画像、
已有内容资产。

读取输入后先做「信息完整性检查」：把能提取的字段填进产品属性模型
（`references/01-输入契约.md`），缺失的关键字段列入缺口清单，阻塞项先询问用户。

## 2. 总体流程（Stage 0–9）

```
S0 输入解析与完整性检查 → S1 产品属性建模(10维评分)
→ S2 品类定位与关键词分级(搜索量/趋势/体量)
→ S3 平台内容生态洞察(品类横截面对比+内容类型分布)
→ S4 适配内容类型判定(属性×权重+生态修正+必保规则)
→ S5 爆文筛选与拆解(分层L1/L2/L3+10字段模板)
→ S6 卖点二次提炼(原始卖点→差异化卖点→关键词→消费者利益→种草话术)
→ S7 内容投放矩阵(类型×篇数×预算×目的)
→ S8 PPT 生成(13页固定结构) + 数据附录
```

每个 Stage 的目标/步骤/判断规则/输出/反编造约束见对应 references 文档。

## 3. 各阶段执行要点

### S0 输入解析与完整性检查
- 解析输入，提取：产品名称/品类/规格/价格/克重/成分/工艺/卖点/品牌/渠道/使用场景。
- 输出：`product_profile.md` + `gap_list.md`（缺口清单，标注是否阻塞）。
- 阻塞项：产品名或品类无法确定、核心数据源全不可用 → 停下询问用户。

### S1 产品属性建模
- 按 `references/02-产品属性模型.md` 的 10 维模型给产品打分（0–5 分）：
  品类生命周期、客单价、复购率、场景明确度、人群明确度、颜值属性、功效/功能属性、
  成分/原料属性、情感/送礼属性、内容化潜力。
- 输出：`product_profile.md` 中的评分表 + 一句「产品画像」结论。
- 该评分是 S4 判定内容类型的输入，必须完成。

### S2 品类定位与关键词分级
- 关键词四级体系：大品类词 → 二级品类词 → 具体产品词 → 竞品词/场景词/人群词。
- 每个关键词记录：搜索量、近30/90天趋势、增长/下降、横向体量（同类词对比）。
- 优先数据源见 `references/04-数据源清单.md`（小红书：官方蒲公英-内容广场/聚光/灵犀/薯条，
  第三方千瓜/新红/蝉小红；抖音：巨量算数/蝉妈妈/飞瓜）。
- 核心产出是「品类横截面对比」：本产品词 vs 2–3 个同赛道词（如榛子酱 vs 巧克力酱 vs
  开心果酱），比搜索指数/曝光/阅读/互动/内容量/作者量及涨跌幅，落「机会/红海/成熟」
  判断，并给出 3 条赛道洞察。
- 反编造：搜索量数据缺失时标注 [D2]，且必须写明数据日期与来源工具。

### S3 平台内容生态洞察
- 在核心关键词下搜索笔记，统计内容类型分布（按 `references/03-内容类型注册表.md` 的
  类型归类），识别「生态主流类型」「生态空缺类型」「高增长类型」。
- 输出：内容类型分布 + 3 条生态洞察（引用代表性笔记作证据）。

### S4 适配内容类型判定
- 算法：`类型适配分 = Σ(属性评分 × 类型权重) + 生态修正 + 强信号加成`。
  - 类型权重矩阵：每个内容类型对每维属性的敏感度，见 `references/03` 表。
  - 生态修正：生态空缺类型 +5，生态高增长 +3，红海饱和 -3。
  - 强信号加成：高客单必含「测评对比」，成分党品类必含「成分解析」，礼赠属性必含
    「送礼场景」，渠道强绑定必含「渠道探店/上新推荐」，早餐场景必含「场景搭配」。
- 选 Top 3–5 个类型进入矩阵与 PPT，每个类型写：定义/为什么适合本产品/生态证据/置信度。

### S5 爆文筛选与拆解
- 分层定义（`references/06-爆文筛选与拆解.md`）：
  - L1 绝对爆文：互动≥5000 或阅读≥10万
  - L2 品类高表现：互动≥1000 且互动率≥5%（主对标，优先用）
  - L3 潜力新文：发布≤30天，互动率≥10%，互动≥500；或低粉爆文（粉丝<5000且互动≥1000）
- 每个推荐类型找 2–3 篇代表案例，按 10 字段模板拆解：标题/首图/开头/结构/产品出现方式/
  核心卖点/场景/用户利益点/互动数据/可借鉴点。
- 案例必须真实可回查（给笔记 ID 或链接），禁止虚构案例。

### S6 卖点二次提炼
- 按 `references/08-卖点提炼模板.md` 走五层：
  `原始卖点 → 核心差异化卖点 → 关键词 → 消费者利益 → 种草话术`。
- 每个差异化卖点配三栏：「核心信息 / 对标痛点 / 用户价值」，另做一张
  「痛点 vs 卖点 vs 转化后卖点」对比表（参考成品案例样式）。
- 关键词覆盖维度：品类、品牌、渠道、场景、人群。

### S7 内容投放矩阵
- 默认总量 15–20 篇（可据预算调整）。分配规则（`references/10-投放矩阵规则.md`）：
  - 高转化类型（测评/场景搭配/上新）占大头；
  - 高收藏类型（教程/烘焙/收纳）做长尾；
  - 预算按「单篇成本 × 层级」：素人/KOC/腰部/头部 配比由客单价与目标决定；
  - 目的标注：声量/转化/长尾搜索/新品教育。
- 产出：类型 × 篇数 × 层级 × 单篇预算 × 小计 × 目的 的矩阵表 + 预算占比 + 执行节奏。

### S8 PPT 生成 + 数据附录
- 按 `references/09-ppt结构v0.2.md` 的 13 页固定结构组织内容。
- 运行 `scripts/build_pptx.py`：输入 `plan_data.json`（中间产物汇总），输出
  `品牌投放策划_<产品名>.pptx`，附 `数据附录.md`。
- 交付物清单：① PPT（品牌方直接可用）② 数据附录（全量溯源+缺口清单）
  ③ 中间产物（可选，供内部复核）。

## 4. 输出契约

| 交付物 | 格式 | 说明 |
|---|---|---|
| 客户 PPT | .pptx | 13 页固定结构，可直接给品牌方 |
| 数据附录 | .md | 所有数字溯源 + 缺口清单 + 补充查询指引 |
| 中间产物 | .md/.json | product_profile / keyword_research / type_selection / 爆文拆解 / 矩阵（内部复核用） |

## 5. 依赖与环境

- 脚本：`scripts/build_pptx.py`，依赖 `python-pptx`。
- 安装：`pip install python-pptx`（若无 pip 直接可用，按所在环境
  Python 解释器对应路径安装，例如 `python3 -m pip install python-pptx`）。
- 无数据工具权限时：降级为「网络搜索近似 + 缺口清单」，PPT 中明确标注定性结论，
  不伪造具体数值（详见 `references/07`）。

## 7. 验收标准（每次执行后自检）

- [ ] PPT 13 页固定结构完整，页序正确，可正常打开
- [ ] 平台洞察页有品类横截面对比与明确赛道结论
- [ ] 内容类型是「算」出来的（有评分依据），不是拍脑袋
- [ ] 每类爆文有真实可回查案例，含 10 字段拆解
- [ ] 卖点完成五层转化，含三栏拆解与对比表
- [ ] 矩阵有篇数/层级/预算/目的，总数与预算自洽
- [ ] PPT 内每个数字有来源角标，D3 数据未出现
- [ ] 缺口清单交付，阻塞项已与用户确认
