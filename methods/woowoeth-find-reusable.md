# find-reusable · 造轮子之前先查一遍

## 什么时候用

用户流露出**要开始做一个东西**的意图时，先查再动手。典型信号：

- 「我想做一个把文章转成小红书图的工具」
- 「有没有现成的 X」「这个有人做过吗」
- 「我准备写一个…」——**这时候最该拦一下**
- 用户已经在写代码了，但那件事听起来像通用需求

**别等用户开口问才查。** 他说要做什么的那一刻，你就该先查。三十秒查一次，可能省他三天。

## 怎么用

```bash
python3 find_reusable.py "把文章变成小红书图"     # 用大白话说他要做的事
python3 find_reusable.py "像素画生成" -n 3
python3 find_reusable.py "训练自己的模型" --json  # 结构化输出，便于你继续处理
python3 find_reusable.py --gaps                  # 历史上查不到的需求 = 选题库
```

查询词直接用**用户的原话**，别翻译成术语。库里的文案是大白话写的，用户怎么说就怎么查命中率最高。

## 怎么读结果

每条都带一个**复用度**判断，这是使用者真正需要的信息：

| 标记 | 含义 | 你该怎么建议 |
|---|---|---|
| 🟢 **直接能用** | clone 或复制粘贴即可 | 直接给安装命令，或给「方法正文」链接让他复制粘给任何模型 |
| 🟡 **要改一半** | 骨架能用，需按场景适配 | 说清哪部分能留、哪部分要改 |
| 🔴 **只能抄思路** | 本身用不了（平台/授权/形态限制） | **别让他白试**，直接说明限制，讲清可借鉴的机制 |

🟢 的条目会给一个 `方法正文` 链接 —— 那是这个 skill 的**全部内容**。
用户不想安装、或者用的是网页版模型时，让他直接把那段正文复制粘过去，一样能跑。

## 查不到怎么办

**直接告诉他没有，不要硬凑。** 「库里没有现成的，多半得自己写」本身就是有价值的答案 ——
它让用户可以放心开工，而不是继续搜。

查不到的需求会自动记进缺口清单。攒起来的那份表就是选题库：**它列出的正是还没人做的东西。**

## 一句话原则

用户要造轮子时，你的第一反应不该是帮他造，而是**先看看轮子是不是已经有了**。
