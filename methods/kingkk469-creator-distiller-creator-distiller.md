# 归源 · 博主蒸馏器

生成的是“博主公开方法的可回源顾问”，不是人格替身。通用 Skill 负责采集、转写、蒸馏和打包；每位博主最终得到一个独立 Skill。整个流程在用户本机运行，云端模式也只是由本地脚本调用用户选择的第三方 ASR API，不需要网站或公共后台。

## 标准流程

### 对话式向导

普通用户不需要看到命令行参数。每轮只询问一个会改变结果的选择，安全步骤自动执行；用户说“全部按推荐执行”时，采用本地处理、全量作品并在完成后直接打开生成的专家。固定顺序是：

1. 接收博主主页、视频链接清单或本地素材。
2. 自动体检和预览，先报告当前可见作品、字幕/转写覆盖、未知时长与失败风险。
3. 询问处理位置：`本地处理` 或 `网络处理`。已有字幕只是自动优先使用的素材，不作为第三种处理位置。
4. 用户提供博主主页时，必须让用户从四种范围中选择：`全量`、`半年内`、`半年内 Top 10`、`最近 10 条`。
   - `半年内 Top 10` 先筛选最近 183 天的作品，再按点赞数取前 10 条；用户主动要求时，也可以改用平台实际返回的评论、收藏、转发、播放或综合互动指标。
   - 某项指标或发布日期不可用时明确说明，不能静默换成其他指标。
   - 用户不想按主页选择范围时，也可以直接提供指定视频链接清单；这是另一种输入方式，不占用上述四个主页范围选项。
5. 平台要求登录时，让用户选择：使用本机浏览器当前登录状态、手动登录后继续，或改用链接清单/本地素材。用户自己正常登录不算绕过限制。
6. 运行长任务并主动报告关键进度；验证码由用户手动完成。私密、付费、已删除或明确拒绝访问的内容不自动破解获取，单条失败时跳过并继续任务。
7. 蒸馏、绑定证据并验证后，默认生成本地可用专家。用户要求分享时再额外导出安全分享包。

用户的典型第一句话是：`$creator-distiller 帮我蒸馏这个博主：主页链接`。

1. 先体检并预览，不直接开始长任务：

   ```powershell
   python scripts/creator_distiller.py doctor
   python scripts/creator_distiller.py preview --input "博主主页、manifest、链接清单或本地目录"
   ```

   抖音主页默认由 Playwright 打开正常网页并监听页面自身返回的作品数据；`yt-dlp` 负责后续单条视频的字幕或临时音轨。用户选定范围后，用 `--scope all|recent-half-year|recent-half-year-top10|latest10` 再次预览并确认数量；半年内 Top 10 默认传入 `--top-metric likes`。指定视频直接把链接清单作为输入。

2. 告诉用户当前可见作品数、已有字幕数、未知时长、失败风险和处理方式。主页枚举只代表当前浏览器状态下可见的范围，不得宣称包含已删除、私密或受限作品。抖音无登录状态无法展示完整作品时，改用 `--browser-mode interactive --browser-channel chrome`，让用户在打开的浏览器中正常登录；也可在用户同意后使用 `--cookies-from-browser chrome` 读取当前登录状态，不得导出 Cookie 文件。

3. 选择转写路线：

   - `--asr auto`：字幕优先，无字幕时自动使用本地 ASR；没有本地 ASR 就进入待处理队列。
   - `--asr local`：本地 Whisper 路线。首次可能下载模型，执行前说明模型和空间占用。
   - `--asr cloud`：上传临时音轨到用户指定的兼容 API。执行前必须确认服务商、API Key 环境变量、每分钟价格、费用上限和保存策略。
   - `--asr none`：只建立来源台账并导入已有字幕。

4. 用户确认后运行 `ingest`。长任务产生 `job.json`，中断后使用 `resume`，以后处理新视频使用 `sync`。具体参数与状态见 [local-workflow.md](references/local-workflow.md)。

5. 转写完成后运行 `distill-input`。阅读输出中的带 ID 片段，用当前 Agent 提炼“方向、方法、问题、适用人群、限制和行动步骤”，写成 claims JSON，再执行 `import-claims`。不得只凭标题生成观点。

6. 运行 `verify`。任何标为 `direct` 的作者原意卡没有直接 `segment_id` 时，不得生成可分享版。

7. 按用途生成博主专属 Skill：

   ```powershell
   # 私人完整版：带完整本地语料，只供学习和个人使用
   python scripts/creator_distiller.py build-skill --db corpus.sqlite --output generated --skill-name creator-advisor --target private-full

   # 可分享轻量版：只有方法卡、必要短引、时间码和原视频链接
   python scripts/creator_distiller.py build-skill --db corpus.sqlite --output generated --skill-name creator-advisor --target public-light
   ```

## 蒸馏要求

方法卡至少包含：主题、结论、适用场景、限制、归属等级和证据片段。只有作者在原片明确表达且已绑定直接证据时才能标为 `direct`。

证据按“核心观点或方法卡”绑定，不要求回答中的每一句话都重复附链接：一个核心观点至少给出一个原视频出处；跨视频归纳通常给出 2–3 个主要出处；解释语和过渡语不单独引用。AI 推演应列出所依据的方法卡来源，但不能把新推演写成作者原话。

- `author_original` → `【作者原意】`
- `ai_summary_unverified` → `【AI 归纳，未经本人核验】`
- `ai_inference` → `【基于作者方法的 AI 推演】`
- 无足够材料 → `【资料不足】`

诊断、规划、评审和新文案都属于对新问题的推演，不能写成博主亲自回答。生成 Skill 应支持知识问答、诊断、规划、评审和原视频学习路径。

## 归属与分享

- 谁被蒸馏，公开内容的主体和归属就指向谁；发起整理的人不获得公开署名、运营权或商业入口。
- 生成包统一说明“基于该博主的公开内容，由 AI 整理生成”，不设置“官方版/非官方版”使用门槛。
- 私人完整版可以留在用户本机学习。
- 可分享轻量版不得包含完整逐字稿、视频、音轨、Cookie、API Key、本地路径、课程、社群、商品或咨询入口。

## 原视频回流铁律

- 来源卡始终使用平台原视频地址，不能替换成中转页、短链或自己的落地页。
- 支持时间深链的平台可以附加秒数；抖音、小红书等不支持时显示时间码后直接打开原片。
- 原片不可访问时如实标注，不重新分发本地媒体。
- 重要判断至少打开一条原片核对；转写存在明显错词时不得引用为高置信结论。

## 平台与权限边界

- 用户可以自行选择处理公开主页、视频链接清单、本地素材，或使用自己浏览器的当前登录状态；采集、下载、字幕和转写优先组合成熟的开源工具完成。
- 登录本身不是绕过。需要登录时由用户在自己的浏览器完成，Skill 可以读取当前登录状态继续；不得导出、记录或分享 Cookie。
- 验证码由用户手动处理。Skill 不破解付费、私密、已删除内容或明确的访问控制，也不提供偷取账号、破解验证码或 DRM 的方法。
- 抖音主页使用 Playwright 浏览器枚举当前可见作品；小红书及其他平台按现有适配能力处理。主页枚举失败时保留失败状态，并让用户选择交互式登录或提供视频链接清单，不把失败说成账号没有作品。
- 原媒体默认只作临时转写缓存；用户自己的本地文件永不删除。
- 用户要求分享时，只输出方法卡、每张卡 1–3 个主要出处、必要短引、时间码和原视频直链；不把完整视频、音频或逐字稿打进分享包。

## 输出标准

每次至少报告：发现作品、可访问来源、已有字幕、已转写、待处理、失败、可回源片段、作者原意卡、AI 归纳卡，以及数据库和生成 Skill 的绝对路径。

标准清单字段见 [manifest-schema.md](references/manifest-schema.md)，证据与完整度定义见 [evidence-model.md](references/evidence-model.md)。
