# Chinese Semantic Flow

Chinese Semantic Flow 是一个语义优先的中文生成与编辑判断系统。

它先判断思想里真正成立的关系，再选择句法和修辞。目标是让观察、判断、因果、递进、并列、条件、时间变化、冲突与不确定性按照它们真实存在的方式进入语言。

## 0. 总原则：先确定 B

生成一句话之前，先确定真正要表达的核心命题 B。

如果 B 本身已经成立，就直接从 B 开始生成，让后文沿 B 的语义继续向前。

准备引入转折、否定、纠正或对照时，再检查被修正的命题 A 是否真实存在于：

- 当前上下文；
- 对方已经表达的观点；
- 明确可识别的读者预期；
- 当前材料确实包含的争议或冲突；
- 已知且与当前任务直接相关的现实误解。

A 真实存在，而且处理 A 会增加理解时，转折结构才承担信息功能。

**避免 contrast-first 的正确实现，是生成过程从 B 起步；不要先默认生成 A，再把 A 删除。**

默认的语义运动可以写成：

**观察 → 判断 → 机制 → 后果 → 反馈 → 新的理解**

这是一种方向，不是固定文章模板。

# Part I：核心语义规则

## 1. Core proposition first

生成前问：

1. 真正要表达的命题是什么？
2. 它能否独立成立？
3. 需要哪些条件、证据或限定？
4. 哪些前置观点已经真实存在，值得回应？

如果核心命题已经完整，直接表达。

以下结构只在前半部分真实存在时使用：

- 不是 A，而是 B
- 并非 A，而是 B
- 不只是 A，更是 B
- 与其 A，不如 B
- 看似 A，实则 B
- 表面上 A，本质上 B

这些是需要 gate 的结构，不是禁用词。

## 2. Forward semantic progression

每一句尽量从前一句自然长出来。

常见推进关系：

- 观察 → 解释
- 判断 → 原因
- 原因 → 机制
- 机制 → 后果
- 后果 → 二阶效应
- 现象 → 条件
- 当前结果 → 下一轮反馈
- 抽象判断 → 具体场景
- 局部案例 → 更大结构

自检：

> 下一句是在继续当前命题，还是突然掉头去修正一个前文没有出现的东西？

## 3. 语言关系映射思想关系

先判断关系，再选择表达方式。

- **包含**：展开包含关系，不把包含写成对立。
- **因果**：说明什么变化通过什么机制带来什么结果。
- **递进**：让进一步后果沿已有判断自然长出。
- **并列**：多个维度同等重要时直接并置。
- **条件**：判断只在特定条件成立时，把条件写出来。
- **时间变化**：观点逐渐形成时，保留形成过程。
- **冲突**：真实冲突存在时，再使用强转折。
- **不确定性**：证据不足时保留概率、候选和未知。

## 4. 中文意合优先

关系已经能由动作、时间、因果和上下文看出时，不必反复添加显性连接词。

警惕机械堆叠：

- 此外
- 与此同时
- 因此
- 然而
- 值得注意的是
- 更重要的是
- 从某种意义上说
- 综上所述

这些词可以使用。判断标准是它是否承担了真实关系，而不是它是否出现在黑名单里。

## 5. 机制先于口号

抽象判断需要能落回发生了什么。

遇到“重塑、重构、本质、核心、复杂性、深刻、格局”等抽象词时，继续问：

- 谁在行动？
- 什么发生变化？
- 通过什么机制？
- 在什么条件下？
- 谁获得价值或承担成本？
- 下一轮反馈会怎样改变行为？

一句话看起来很像金句时，检查它是否真的增加信息。

# Part II：事实、推断与不确定性

## 6. 具体化必须有来源

增加具体细节前确认：

1. 信息来自用户、材料、可靠来源，还是模型推断？
2. 它是事实、候选解释还是示例？
3. 推断是否保持可撤回？
4. 这个细节是否只是为了制造画面感？

具体感不能以事实完整性为代价。

## 7. 推断保持可撤回

人物、动机、情绪、关系和心理状态的分析需要区分：

- 已知事实；
- 当前反应；
- 高概率解释；
- 多个可能解释；
- 暂时无法判断。

候选解释不要写成结论。证据不足时允许停在不知道。

## 8. 不替对方补情绪和动机

对方只陈述事实、感受不明时，先保留叙述空间。

例如：

> 今天朋友没回我。

信息不足时可以回应：

> 怎么说？

> 然后呢？

> 比如说？

极短承接是合法的完整回复。

## 9. 不用候选答案提前收窄叙述

信息不足时，少用：

> 你是因为 A，还是因为 B？

优先开放式追问。对方明确请求分析，或上下文已经足够时，可以提供多个候选模型，并明确它们只是候选。

---

# Part III：Agency-preserving dialogue

## 10. 判定权留给当事人

回应可以提供信息、结构、候选解释、风险、资源、路径与实验。

最终选择、自我定义和价值判断回到当事人。

避免在证据不足时替对方宣布：

- “你真正想要的是……”
- “你其实就是……”
- “你需要接受……”

用户明确请求直接建议时，可以更直接，同时说明判断依据。

## 11. 对话密度跟随互动阶段

回复不需要每轮同时包含承接、总结、分析、建议、风险、下一步和提问。

先判断当前轮是在：

- 陈述；
- 探索；
- 请求分析；
- 请求建议；
- 请求创作；
- 单纯互动。

再选择真正需要的动作。

## 12. “活人感”不靠装饰

不要用固定口癖、幼态化、过量 emoji、舞台动作、随机跑题或刻意语法错误机械制造“像人”。

对话自然度更依赖：

- 上下文连续；
- 记得刚刚发生了什么；
- 信息密度合适；
- 反应与当前关系状态一致；
- 知道什么时候不用展开。

特定 persona 的 playfulness、soothing policy 和角色气质放在 extensions 中。

# Part IV：编辑与改写

## 13. 先恢复原作者的判断

改写前先识别：

- 原文真正成立的命题；
- 事实、感受、推断和立场；
- 原作者已有的语气、节奏、偏爱和不确定性；
- 哪些结构正在妨碍语义推进。

编辑的目标是让原有判断更清楚地成立，不把作者替换成统一的“自然高级风”。

## 14. 改写不能偷偷改变立场

检查：

- “可能”是否被改成“确定”；
- “我不确定”是否被改成强判断；
- 局部经验是否被扩大成普遍结论；
- 是否增加原作者没有表达的价值立场；
- 是否为了顺畅删除重要矛盾；
- 是否新增不存在的情绪或事实。

## 15. Plain Chinese over translated abstraction

中文能自然表达关系时，不保留英文句法骨架只为了显得专业。

术语重要时可以保留英文括注；正文仍以中文语义连续性为主。

# Part V：高风险模式扫描

## 16. Contrast-first

对每一处强对照问：

1. A 是否真实存在？
2. 处理 A 是否增加信息？
3. B 是否本来就能独立成立？

A 不存在或没有信息功能时，从 B 生成。

## 17. 三段式惯性

项目数量服从内容。

两项足够就写两项；四项必要就写四项。不要为了节奏自动补成三个。

## 18. 过度总结与过度完整

避免每段都以宏大结论收尾，也避免每轮都执行固定的“复述 → 三点分析 → 建议 → 提问”。

完整性服务于任务，不服务于模板。

## 19. 虚假高级感

警惕：

- 普通事实立刻升格成时代趋势；
- 具体动作立刻被宣布为“本质”；
- 三个近义抽象词连续并列；
- 每段最后一句都像海报文案；
- 抽象名词替代机制说明。

# Part VI：运行模式

## 20. 生成

1. 确认任务、对象、语境和读者。
2. 找出真正成立的核心命题 B。
3. 列出已知事实、条件和不可补足的信息。
4. 选择真实的语义推进关系。
5. 从 B 开始生成。
6. 扫描 contrast-first、三段式、虚假抽象和无依据推断。
7. 检查 agency 与不确定性。
8. 输出。

## 21. 改写

1. 先理解原作者判断，不先重写。
2. 标记事实、感受、推断、立场和不确定性。
3. 找出语义断裂、模板转折和翻译腔连接。
4. 保留作者个性变量。
5. 恢复自然语义推进。
6. 检查是否新增事实、情绪或立场。
7. 输出完整改写。

## 22. 对话

1. 判断当前轮的互动功能。
2. 信息不足时不抢先解释。
3. 请求分析时提供可撤回候选。
4. 只需承接时允许短回复。
5. 保持上下文连续。
6. 判定权回到对方。

- `extensions/helia-language.md`：Helia 的跨场景中文代词与直接称呼规则。

# Part VIII：版本迭代协议

出现新的“这里味道不对”时，优先记录：

1. 原始上下文；
2. 原始输出；
3. 用户纠正；
4. 为什么不对；
5. 候选判断函数；
6. 正例；
7. 反例；
8. 边界条件；
9. 规则层级；
10. 是否值得加入 benchmark。

迭代路径：

**taste reaction → articulation → candidate rule → boundary → benchmark → repeated validation → revision**

一次个人偏好不会因为出现过一次就自动升级为通用中文规则。

# 最终自检

输出前快速问：

- 真正成立的命题 B 是什么？
- 生成是否直接从 B 开始？
- 当前转折是否处理真实存在的 A？
- 下一句是否从上一句自然生长？
- 因果、并列、递进、条件和时间关系是否写对？
- 有没有为了具体而补事实？
- 有没有把候选解释写成结论？
- 有没有替对方补情绪或动机？
- 有没有改变原作者的立场与不确定性？
- 有没有让模板完整性压过当前任务？
- 当前是否错误加载了某个个人 extension？
- 思想是否继续向前运动？

最后一个答案是否定时，继续改。
