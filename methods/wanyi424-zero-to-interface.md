# Zero to Interface

把零散的新产品想法推进到一套经过用户确认、可直接运行的前端设计稿。先确定产品，再确定界面；当前 Skill 到设计交接为止，不进入正式开发。

## 核心定义

- 只处理从零到一的新产品。现有产品改版、局部功能调整和正式工程开发不在范围内。
- 将最终 HTML/CSS/JS 称为“可运行的前端设计稿”，不要称为“原型图”或“低保真原型”。
- 前端设计稿的视觉、内容、状态与交互应达到正式产品应有的完成度，但所有数据与业务结果均为模拟。
- HTML 是后续一比一复刻的视觉与交互事实来源，不是生产代码。不得在本流程中接入真实 API、数据库、鉴权、支付、上传或其他后端能力，也不得自行切换到 React、Next.js、Vue 等正式技术栈。
- 只给出一个经过专业判断的最佳设计方向。不要让普通用户在多套抽象 UI/UX 方案之间选择。
- 覆盖完整核心流程、常见状态和会影响用户判断的重要异常；不要为了假想的极端情况过度设计。

## 工作流

### 1. 明确产品并建立目录

开始时完整阅读 [产品发现与 PRD](references/product-discovery-and-prd.md)。利用用户已有材料，只追问会影响产品方向、范围、流程或设计的重要缺口。分组提出简洁问题，必要时继续追问；不要把自己的推断伪装成用户已经确认的需求。

遵循当前工作区已有的文档或产物目录约定。没有约定时使用：

```text
product-design/<product-slug>/
├── prd.md
├── ui/
└── design-handoff.md
```

此时只建立产品理解，不制作界面。

### 2. 创建并确认 PRD

当剩余未知项已不会实质改变产品目标、范围、核心流程和页面结构时，创建 `prd.md`。详细程度由产品复杂度决定，不贴“轻量”或“详细”标签。

把文件链接交给用户审阅，并等待明确确认。PRD 未确认前，不进入视觉设计，也不生成 HTML。

### 3. 收集或确定视觉方向

PRD 确认后完整阅读 [视觉参考与独立设计](references/visual-direction.md)。先询问用户是否有在社交媒体或其他地方看到的链接、截图、视频画面或可描述的创意。

- 用户提供参考时，分析可观察到的视觉、布局和交互特点，将适合当前产品的部分重新组合；不要照搬整个页面。
- 链接无法访问或无法准确观察时，请用户补充截图，不要凭网站名称猜测设计。
- 用户没有具体参考时，直接根据产品自身的内容和核心交互独立设计，不把参考网站变成前置条件。
- 需要向用户推荐灵感网站时，必须一次列出参考文件中的全部地址，保持原顺序，不遗漏，也不逐个介绍网站内容。

视觉分析用于 Agent 作出设计判断。不要先输出多套专业术语方案要求用户选择，直接进入一个最合适方向的制作。

### 4. 制作可运行的前端设计稿

开始制作前完整阅读 [可运行前端设计稿规范](references/runnable-frontend-design.md)。根据产品复杂度自行决定使用一个或多个 HTML 文件，并允许配套的 CSS、JavaScript 和本地素材；不引入包管理器、构建流程或正式前端框架。

设计稿必须完整承载 PRD 中的核心使用链路。所有按钮、导航、表单、弹窗、切换和关键反馈都应能够实际操作；需要后端的行为使用可重复的本地模拟实现。

完成后使用可用的浏览器或渲染工具实际打开和检查页面，走通核心链路并修复发现的问题。无法进行视觉验证时，明确说明未验证的范围，不要声称已经检查完成。

### 5. 与用户反复打磨

向用户展示可运行页面，让用户直接根据看到和操作到的结果反馈。根据反馈修改当前最佳方案，不擅自推翻已经确认的部分，也不另起多套备选设计。

- 反馈改变产品目标、功能、页面职责或交互规则时，同步更新 `prd.md`。
- 反馈只改变色彩、排版、间距、动效等视觉表现时，不必修改 PRD。
- 每轮修改后重新检查受影响的页面和核心流程。

### 6. 确认并交接

只有用户明确确认设计与交互后，才完整阅读 [设计交接规范](references/design-handoff.md) 并创建 `design-handoff.md`。交接文件必须引用实际存在的 PRD 与设计稿路径，说明模拟边界，并明确要求后续开发使用正式前端技术栈一比一复刻。

交接文档完成后，本 Skill 的任务结束。不要继续选择技术栈、拆开发任务、设计 API 或编写生产代码。

## 完成标准

同时满足以下条件才可宣布完成：

1. `prd.md` 已由用户确认，且与最终设计一致。
2. 核心使用流程可以在设计稿中完整走通。
3. 常见状态和重要异常已经表现，未穷举假想极端情况。
4. 目标终端上的布局、交互和视觉已经实际检查，或明确披露无法检查的部分。
5. 用户明确确认最终设计。
6. `design-handoff.md` 已创建，并正确引用 PRD 和全部入口页面。
