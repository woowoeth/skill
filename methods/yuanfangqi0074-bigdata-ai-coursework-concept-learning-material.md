# 概念学习资料生成器

把一个概念变成一份能读懂、能核查、能复习的学习资料。

核心立场：**资料的价值不在"生成了内容"，而在"内容可被核查、解释是自己的话"。**
生成后必须逐条核对来源链接能否打开，禁止凭印象写链接。

## 适用场景

- 学习或复习一个新概念，希望得到结构化、可复习的笔记
- 需要向他人讲解某个概念，需要一个清晰的讲述骨架
- 对比几个相近概念，找出它们的边界
- 想检验自己是否真的理解了，而不只是"看过"

## 不适用场景

- 需要最新数据或行情（本 Skill 不保证时效性，只产出概念解释）
- 需要完整教程或代码实现（本 Skill 产出的是学习资料，不是项目脚手架）
- 纯事实查询，例如"XX 函数怎么调用"——直接查文档更快

## 输入信息

调用时只需给出概念名称。以下信息可选，给了会更好：

| 输入项 | 必填 | 说明 |
|---|---|---|
| 概念名称 | 是 | 例如 `Agent`、`大模型的上下文` |
| 学习目标 | 否 | 例如"准备课程汇报"、"搞懂它和 Workflow 的区别" |
| 已有基础 | 否 | 例如"已了解 Transformer"，决定解释的起点 |
| 关联概念 | 否 | 需要一并辨析的相邻概念 |
| 输出路径 | 否 | 默认 `learning-materials/<概念英文slug>.html` |

## 生成步骤

1. **先查，再写。** 用搜索找到该概念的权威一手来源（官方工程博客、论文、官方文档）。
   至少 2 条，优先一手来源，其次高质量二手综述。

2. **逐条验证链接。** 对准备引用的每一条来源，实际发起请求确认可访问。
   **返回非 200 的一律剔除，不得写进资料。** 这一步不可跳过，也不可用记忆代替。

3. **用自己的话重述。** 读完来源后，先合上资料，用一句话说清这个概念"是什么、解决什么问题"。
   这句话是资料的开头，必须是自己组织的表达，不能复制来源的原文段落。

4. **按输出结构填充。** 每一节都要真实有内容，不允许出现"待补充"或占位文字。

5. **写易混淆点与边界。** 这是资料里最有价值的部分。
   至少列出 3 条，优先写"看起来对但其实错"的认知，以及该概念失效或不适用的条件。

6. **出 3 道自测题。** 题目要能检验理解，而不是检验记忆。
   不好的题："Agent 的定义是什么？"
   好的题："一个把用户问题分类后转给不同提示词的系统，是 Workflow 还是 Agent？为什么？"

7. **跑一遍自检清单**（见下），全部通过后再交付。

## 输出结构

输出一个自包含的 HTML 文件，按以下顺序组织：

```
标题：概念学习资料：<概念名>
├── 一句话理解          ← 自己的话，必须最先出现
├── 学习目标            ← 读完能做到什么
├── 核心机制 / 组成     ← 它是怎么工作的，由哪些部分构成
├── 具体应用场景        ← 一个能落地讲出来的真实例子
├── 容易混淆的问题与边界  ← 至少 3 条，写明失效条件
├── 自测问题            ← 3 道题，检验理解而非记忆
├── 资料来源            ← 每条含：作者/机构、标题、可点击链接、实测状态
└── 核查记录            ← 生成时间、来源验证方式、待人工复核项
```

HTML 要求：单文件、不依赖外部资源、浅色主题、直接在浏览器打开即可阅读。

## 资料来源要求（硬性）

- **不得伪造。** 每一条链接都必须实际验证过可访问，并在资料中标注验证状态。
- **优先一手。** 官方工程博客 > 论文 > 官方文档 > 二手综述 > 博客解读。
- **标注来源性质。** 一手来源和二手解读要区分开，不能混为一谈。
- **不得整段照搬。** 引用观点要注明出处，但解释部分必须是自己组织的表达。
- 每条来源写明：机构/作者、标题、链接、访问日期。

## 自检清单

交付前逐条确认，任何一条不通过就不算完成：

- [ ] 每个准备引用的链接都实际发起过请求，可访问（非 200 的已剔除）
- [ ] "一句话理解"是自己组织的表达，不是来源原文
- [ ] 核心机制讲清了"它怎么工作"，而不只是"它是什么"
- [ ] 应用场景是具体的，包含能讲出来的细节，不是泛泛而谈
- [ ] 易混淆点 ≥ 3 条，且明确写了该概念不适用或失效的条件
- [ ] 自测题检验理解，不是检验背诵
- [ ] 全文没有"待补充"、"TODO"、占位文字
- [ ] 没有把不同来源的观点混在一起当成单一事实陈述
- [ ] HTML 能独立打开，样式正常，链接可点击

## 文件存放

- 学习资料：`learning-materials/<concept-slug>.html`
- 多概念关系说明：`learning-materials/concept-relationship.md`
- 本 Skill 自身：`.workbuddy/skills/concept-learning-material/SKILL.md`

## 示例调用

```
用 concept-learning-material 学习"向量数据库"
```

```
用 concept-learning-material 生成"上下文工程"的学习资料，
我已有 Transformer 基础，重点是它和普通提示词优化的区别
```

## 复用性说明

本 Skill 不绑定任何具体概念。三个已生成的概念（Agent、大模型的上下文、Skill）
只是三次调用的结果，不是 Skill 本身的内容。传入任意新概念，流程、结构、
来源验证要求和自检标准完全一致。
