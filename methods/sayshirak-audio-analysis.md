# 音频解析（audio-analysis）

输入一个音频文件，产出与其同目录、同名前缀的三个文件：

| 产物 | 文件名 | 说明 |
|------|--------|------|
| 文字记录 | `{basename}_原文.md` | 按发言人分段，带 MM:SS 时间戳 |
| 导读 | `{basename}_导读.md` | 关键词/摘要/章节速览/思维导图/发言总结/问答回顾 |
| 思维导图 | `{basename}_思维导图.jpg` | 左右展开脑图，中心主题 + 分支 + 要点 |

`{basename}` 为音频文件名去掉扩展名，例如 `20260713.m4a` → `20260713_原文.md`。

## 安装路径

将本 Skill 放到 Agent 可发现的目录，目录名保持 `audio-analysis`：

- Cursor 个人：`~/.cursor/skills/audio-analysis/`
- 本机 Agent（Windows 常见）：`~/.agents/skills/audio-analysis/`
- 项目内：`<项目>/.cursor/skills/audio-analysis/`

安装与依赖细节见 [README.md](README.md)。

## 环境依赖

- Python 3.10+，`ffmpeg` 在 PATH 上（非 wav 输入需要转码）
- Python 包：`pip install -U -r requirements.txt`（funasr / modelscope / torch / torchaudio / matplotlib / numpy）
- 首次运行会从 ModelScope 自动下载 FunASR 中文模型（paraformer-zh、fsmn-vad、ct-punc、cam++），需联网、体积较大；缓存一般在 `~/.cache/modelscope/`

## 工作流程

### 第 1 步：转写 + 说话人分离

运行转写脚本（**必须区分多人说话**，脚本内置 cam++ 说话人分离模型）：

```bash
python scripts/transcribe.py "<音频路径>"
```

若用户明确说明为 **N 人对话**（如「2 人对话」），传入说话人数量：

```bash
python scripts/transcribe.py "<音频路径>" 2
# 或指定输出目录：
python scripts/transcribe.py "<音频路径>" "<输出目录>" 2
```

脚本自动生成 `{basename}_原文.md`，并在最后打印分段数和识别出的说话人数量。

完成后**读取生成的原文并抽查**：
- 说话人数量是否合理（如咨询对话通常是 2 人）；若明显异常（同一句话被拆给多个发言人、只识别出 1 人但明显是对话），在原文中手动修正发言人标号
- 发言人编号在全文中保持一致
- **长录音（>1 小时）或户外/嘈杂环境**：串号风险高，不能假设「发言人1 全程 = 同一人」；同一段话可能被拆给多个编号

### 第 2 步：撰写导读

通读原文全文，写 `{basename}_导读.md`。各节的格式和篇幅要求见 [reference.md](reference.md)，章节结构固定为：

1. 标题行 `# {basename}_导读` + 日期时间行
2. `## 关键词` — 约 20 个，空格分隔
3. `## 全文摘要` — 一段 250~350 字
4. `## 章节速览` — 按内容自然转折分章（约每 4~8 分钟一章），每章 `##### MM:SS 标题` + 一段概述，时间戳取自原文
5. `## 思维导图` — `![思维导图]({basename}_思维导图.jpg)`
6. `## 发言总结` — 每个发言人一节 `##### 发言人N（身份标签）`，总结其立场、经历与观点
7. `## 问答回顾` — 从对话中提炼问答对，格式 `发言人X 问：…` / `发言人Y 答：…`

撰写时**禁止**仅凭话题推断身份（如「讲 QMT = 程序员」）而不核对原文该段的发言人编号。

### 第 3 步：发言人身份审核

导读写完后、生成思维导图前，**必须**执行审核并修正错配，再进入第 4 步。

**A. 建立身份锚点（至少 2 个）**

从 `{basename}_原文.md` 中找可唯一定位身份的自述，例如：

- 年龄 / 出生年（「我是八三年的」）
- 职业 / 公司 / 学校（「我在同方」「管 FOF」）
- 角色关系（「我是访谈者」「我学金融」）

**B. 交叉校验（原文 ↔ 导读）**

| 导读章节 | 校验内容 |
|---------|---------|
| 发言总结 | 每位发言人的经历、观点是否与原文中**该编号**下的内容一致 |
| 问答回顾 | 每组的提问者/回答者是否符合对话逻辑 |
| 全文摘要 / 章节速览 | 第三人称叙述是否把 A 的背景安到了 B 身上 |

**C. 发现错配时的处理**

- **全局对调**：若仅发言人1/2 整组标反（年龄等锚点明确），在 `{basename}_导读.md` 中对调所有「发言人1/发言人2」及发言总结条目；必要时对 `{basename}_原文.md` 全局对调编号
- **局部串号**：若原文段落内编号频繁交替、无法全局对调，在导读中按**内容语义**标注身份（见 [reference.md](reference.md)），发言总结标题写 `##### 发言人N（角色名）`；不强行改原文每一句
- 审核后在「发言总结」开头用一句话写清：`发言人1 = …，发言人2 = …`（身份 + 锚点依据）

**D. 审核清单**

- [ ] 已从原文找到 ≥2 个身份锚点
- [ ] 发言总结中每人的职业/经历与锚点一致
- [ ] 问答回顾的提问/回答方向合理（无逻辑不通的「同一人问自己答」）
- [ ] 全文摘要未张冠李戴
- [ ] 若用户提供了说话人身份说明，与导读一致

### 第 4 步：生成思维导图

先根据导读内容整理一份 JSON 大纲（中心主题 → 5~7 个分支 → 每分支 2~4 条要点，每条 ≤ 18 字），保存为临时文件，然后渲染：

```bash
python scripts/mindmap.py outline.json "<输出目录>/{basename}_思维导图.jpg"
```

JSON 结构：

```json
{
  "title": "个人现状与未来规划",
  "branches": [
    {"name": "当前生活状态", "children": ["家庭生活规律，早起早睡", "每周安排跑步和文化活动"]},
    {"name": "工作与职业规划", "children": ["尝试寻找兼职工作，但动力不足"]}
  ]
}
```

渲染完成后查看图片确认文字无重叠、无乱码（乱码说明缺中文字体，脚本默认用微软雅黑/黑体）。

### 第 5 步：收尾检查

- [ ] 三个产物都在音频同目录下且命名正确
- [ ] 原文与导读中的发言人编号一致
- [ ] **发言人身份已审核**（第 3 步清单已完成）
- [ ] 章节速览的时间戳能在原文中找到对应位置
- [ ] 导读中的思维导图图片链接可显示
- [ ] 删除中间临时文件（如 outline.json）

## 注意事项

- 音频可能在网络共享路径（`\\server\share\...`）上，脚本支持直接传入；若访问失败，先复制到本地临时目录再处理
- 长音频（>1 小时）转写耗时较长，将转写命令放后台运行并定期检查输出
- 导读和总结用与音频相同的语言撰写（中文音频 → 中文导读）
- 若设置了 `HTTP_PROXY` / `HTTPS_PROXY` 导致模型下载失败，运行前清除代理并设置 `NO_PROXY=*`（见 README「故障排查」）
- 思维导图乱码说明缺中文字体：Windows 用微软雅黑/黑体，Linux 安装 `fonts-noto-cjk`
- cam++ 可能把 2 人对话拆成 3 人；抽查原文后手动合并发言人编号
- cam++ 编号按**首次出现顺序**分配，与真实身份无固定对应；导读完成后必须执行第 3 步身份审核
