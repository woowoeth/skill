# AI 换背景（高保真主体）

## 何时用 / 何时不用

- **用**：需要替换图片背景，且主体必须保持不变（商品图、摆件图、人物图）。
- **不用**：从零生成一张新图（走 doubao-creative-design 文生图）；只需要抠图/透明底 PNG（用专用抠图工具，本 skill 不提供抠图）。

## 输入角色识别

1. **待编辑图（核心资产）**：必传，作为 `image_edit` 的 `image_reference_url_list` 第一张。
2. **背景参考图（可选）**：提供目标背景样式的图（如一张浅灰台面产品图、一张场景效果图）。与待编辑图一起传入，用 `[img1]` 标记。
3. 若背景参考图是相册截图/多图拼贴（含多张产品图），优先裁剪出其中单张干净的图作为参考；裁剪后仍不清晰时，只用文字描述目标背景，不强行传参考图。
4. 本地图片必须先 `FileBatchUpload` 上传拿 URL，再传给 `image_edit`。

## 工具协议

- 一律用 `image_edit`（图生图编辑），**禁止用 `image_gen` 重画近似版本**。
- 保持原图比例：换背景不改画幅，`width/height` 与原图一致；工具仅支持宽高时由原图比例推导。
- 多张参考图按传入顺序用 `[img0]`（待编辑图）、`[img1]`（背景参考图）等标记，prompt 中写明每张作用。

## 批量处理（文件夹输入）

用户给出**一个文件夹路径**时，先判断文件夹结构，再走对应路径。

### 第 0 步：判断文件夹结构

- 文件夹内含**子文件夹**（用户已按商品/品类分类）→ 走**路径 A**；
- 文件夹内**图片平铺、无子文件夹** → 走**路径 B（自动分组）**。

### 路径 A：有分类子文件夹

1. 逐个子文件夹单独处理，每个子文件夹 = 一个独立批次。
2. 每个子文件夹统一一个目标背景（各文件夹可用不同背景，按用户要求）；结果**存回各自子文件夹**，不新建、不覆盖原图。
3. 每批沿用下方"公共规则"。

### 路径 B：无分类、图片平铺（自动分组）

1. **自动识别分组**，多信号结合判断是否同一组商品：
   - **文件名规律**：同系列/同批次倾向同组（如 `DSC_5772~5778` 连号、`batch_0~4` 同系列、`IMG_2020xxxx` 同日拍摄）；
   - **视觉特征**：Read 每张图（图多时先看缩略图再抽查全图），比对主体类型（玻璃猫/玻璃花/陶瓷摆件/手机壳）、颜色与材质饰物（琥珀色红领结玻璃猫 vs 白色陶瓷猫）、单主体 vs 多主体组合、背景风格；
   - **分组粒度**：同一主体（同款商品）的多张图 = 同组；不同主体 = 不同组。
2. **分组确认**：分组有歧义时（某张图主体看不太清、或两种特征都沾边），一次性向用户确认分组清单再执行；分组清晰时直接执行，并在汇报里说明分组依据。
3. **按组处理**：每组内部统一保留项描述（组内主体一致，保留项写组共有的数量/颜色/材质/饰物/姿态）与统一目标背景；组与组之间背景可相同或不同，按用户要求。
4. **输出**：为每组在输入文件夹下建分类子文件夹（组名取主体特征，如 `红领结玻璃猫`、`白色陶瓷猫`），组内结果命名 `<原名>_<目标背景短名>.png` 放入对应子文件夹；若用户明确要求结果平铺在原文件夹，则不建子文件夹。

### 公共规则（A、B 均适用）

1. **列出输入图片**：扫描 `*.jpg / *.jpeg / *.png / *.webp`；跳过文件名已含目标背景短名（本批次输出命名后缀）的旧结果。
2. **统一目标背景**：同一批次（或同一分组）用同一个目标背景描述或同一张背景参考图，不混用。
3. **逐张处理**（每张走完整单张流程）：
   - **大图先压缩**：单张超过约 3MB 或任一边超过 4000px 时，先用 System.Drawing 压缩到 1600px 宽（JPEG 质量 85~88，单张约 100~150KB）再 `FileBatchUpload`，避免上传超时；换背景用 1600px 输入足够；
   - `FileBatchUpload` 上传该图拿 URL；
   - 按"Prompt 结构"写该张的 prompt（保留项按该张实际主体写，不复制其他张的主体描述）；
   - `image_edit` 生成；
   - 下载结果，保存到目标文件夹（路径 A：原子文件夹；路径 B：分组子文件夹或原文件夹）。
4. **命名规范**：`<原图文件名（去扩展名）>_<目标背景短名>.png`（如 `DSC_5772_浅灰台面.png`），与输入图并排存放或放入分组文件夹，绝不覆盖原图。短名示例：浅灰台面、纯白底、家居场景。
5. **分批与并行**：超过 10 张时先处理前 10 张、验证后再继续；单批内可并行调用多个 `image_edit` 提速，但每张结果必须单独下载核对，不得只看接口返回。
6. **失败隔离**：单张失败（接口报错 / 结果明显错误）不中断整批；记录该图文件名与原因，继续处理剩余图片，最后统一向用户汇报成功与失败清单。
7. **批量结束核对**：用目录列表确认每个输入图都有对应结果（同名、后缀不同），无遗漏。

## 场景背景工作流（生成 → 筛选 → 替换 → 归档 → 打包）

适用：用户没有现成目标背景，要求"生成多个背景方案挑选"，或指定平台调性（如 Etsy 居家、ins、北欧、极简、宜家）的场景背景。

1. **生成背景方案（`image_gen` 文生图）**：一次生成 4~6 张**空场景背景**（画面不放产品），要点：
   - **默认硬约束（已实测确认，除非用户明确要求否则必须遵守）**：① 背景**干净、无其他摆件**——不摆放花瓶/陶罐/干花/书本/雕塑等任何装饰道具；② 商品**放桌面/台面上**——只生成台面/桌面/窗台等水平承载面场景，**排除置物架、格柜、墙面挂架等非台面场景**；
   - 比例与产品图**完全一致**（产品 1:1 → 背景 2048×2048；产品 3:2 → 背景 2048×1365），禁止跨比例生成后裁切导致构图拥挤；
   - **质感与极简规范（客户实测反馈，必须遵守）**：场景**极简**——每张只保留 1 个承载台面 + 1 面墙 + 1 种自然光，无窗外建筑景、无多余道具、无多层装饰元素；质感**摄影化**——prompt 写"真实产品摄影、自然实拍、柔和阴影、真实材质纹理、克制后期、非3D渲染、非插画"，避免"透明幻彩"等塑料感描述；
   - **背景-产品关系（Etsy 客户认可例图实测，必须遵守）**：台面**占据画面下方约 3/4**，墙面只露出顶部窄条；台面宽敞平整、四周**留白充足**，产品可**居中展示**；整体**明亮浅色调、低饱和**（暖白/米白/浅灰/浅木色），浅色台面衬托产品——背景是衬托，不是画面主角；**视角为镜头位于桌面上方约 45° 俯视台面**（台面占满下部、透视纵深自然、画面底部是台面前沿），**禁止平视**（平视会出现桌腿/桌面下方暗区）；
   - 台面/焦点区**完全留空**：prompt 写明"台面完全空置，不摆放任何摆件/花瓶/陶罐/干花/书本等装饰"；
   - 每张写清场景构成：台面材质与颜色 + 墙面/纵深 + 光线氛围 + 风格词（北欧极简/ins/宜家/Etsy 手作感），六张之间拉开差异（边几/格柜/桌布/编织垫/窗台/水泥台等）。
2. **对话筛选**：把方案拼成带编号的总览图给用户选（可多选）；先按默认硬约束预筛（非台面/带摆件的直接淘汰），再结合用户当次补充约束过滤。
3. **背景替换**：`image_edit`，`image_reference_url_list` = [产品图, 选中的背景图]，prompt 写清 `[img1]` 的台面材质/墙面/光线，并加"台面上不添加其他装饰物"防止模型乱加道具；保留项仍按"Prompt 结构"逐项写死。
4. **归档**：每个选中背景建一个文件夹（如 `换背景_<背景短名>\`），把**该背景图**和用该背景生成的产品结果放进去。
5. **打包**：全部完成后把结果 zip 打包交付；先小样试跑（代表图 × 每背景）验证效果，用户确认后再全量。

## Prompt 结构（I2I 四段式）

按以下顺序组织成一段连贯中文 prompt，四段缺一不可：

1. **编辑目标**：指出 `[img0]` 是待编辑图、`[img1]` 是背景参考图（如有）、目标状态是什么。
2. **保留项（逐项写死，不要笼统写"保持不变"）**：
   - 主体**数量**（如"六只摆件"）；
   - 每个主体的**颜色/材质/饰物/姿态**逐项枚举（如"琥珀色、深酒红色、浅粉色、绿色、奶白色、烟灰色的通透玻璃质感、红色领结、各自姿态"）；
   - 主体之间的**相对位置关系**与**光影方向**。
3. **编辑项**：
   - 明确**删除的背景道具清单**（如"木质桌面、米色墙面、陶瓷花瓶、尤加利叶、书籍全部移除"）；
   - 完整描述**目标背景**（颜色、质感、光线、纯净度，见下方模板）。
4. **空间描述**：按物理空间顺序串联每个编辑区域的位置、保留内容、修改动作与融合约束。

## 目标背景描述模板

- **浅灰台面（棚拍）**：`干净统一的浅灰色纯色台面，专业产品棚拍风格，台面平整，光线均匀柔和，无杂物、无阴影以外的细节，主体自然摆放于台面上`
- **纯白底**：`纯净白色背景，均匀柔光，无渐变、无杂物、无多余阴影`
- **指定参考背景**：`参考[img1]的背景样式，将[img0]的背景整体替换为同款[颜色+材质+光线描述]`——描述要具体，不写"参考这张图"就完事。
- **场景背景（无参考图）**：写清场景构成（台面材质、墙面颜色、道具清单、光线氛围），让背景目标可复现。

## 验证（每次生成后必须执行）

1. 生成结果返回后，**下载实际图片并 Read 查看**（`curl.exe -L -o` 下载，PowerShell 下不要用 `curl` 别名）。
2. 逐项核对：
   - 主体**数量**是否与原图一致（**生成接口返回的文字描述会数错数量，例如 6 只报成 5 只，必须看实际图片**）；
   - 主体**形态、颜色、饰物**是否保真、有无被重绘变形；
   - 背景是否纯净、目标背景道具是否全部清除、有没有残留或新增杂物。
3. 发现偏差 → 重试修正 prompt（见下），不要直接交付。
4. 多主体图数量存疑时，把结果图裁剪成 4 宫格分区放大逐格数（`System.Drawing` 裁剪），以实际像素为准。
5. **浅灰背景会被误报**：生成接口和缩略图描述常把浅灰台面描述成"纯白色"，判断背景是否达标用像素采样（`System.Drawing` `GetPixel` 取背景区像素，浅灰约为 RGB 145~230 且 R≈G≈B，纯白为 255,255,255），不要被文字描述误导。

## 已知经验（已实测验证）

- 场景图 → 浅灰台面：**纯文字描述背景**与**背景参考图驱动**两条路径均成功，多主体全部保留、位置关系基本不变。
- 主体保真的关键：把**数量、每个主体的颜色/饰物、姿态**逐项写进保留项，而不是笼统说"主体保持不变"。
- 生成返回的 `Description` 计数不可靠，实际画面以 Read 图片为准。

## 常见失败与对策

| 失败现象 | 原因 | 对策 |
|---|---|---|
| 主体丢失/数量变少 | 保留项写得太笼统 | 保留项中显式写明数量与每只独有特征（颜色/饰物/姿态） |
| 主体被重绘变形 | 编辑项占比过大、保留锚点不足 | 加强保留项，明确"造型轮廓、材质、光影方向保持" |
| 背景残留道具 | 删除清单不全 | 编辑项中逐个点名残留道具并加"全部移除、彻底清除" |
| 背景不干净/有渐变 | 目标背景描述不具体 | 用目标背景模板写清颜色、纯净度、光线 |
| 参考图干扰主体 | 背景参考图同时带了产品 | 只传待编辑图+文字描述背景；或裁剪参考图中纯背景区域 |
