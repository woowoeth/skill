# Prepare a design brief

Use the validated MVP/feature specification and existing visual constraints. Produce the brief when a designer handoff is requested.

Describe the service in plain language, target users and their primary action, supported devices, feature/screen IDs, user flow and component states. For each screen include purpose, content, primary action, error/empty/loading states and acceptance criteria. Add existing brand/accessibility constraints, supplied visual references with reasons, required deliverables and priority.

Mark confirmed decisions, assumptions and unresolved questions. Separate implemented features from planned ones and preserve excluded scope. When design requests imply a new feature, flag the scope decision and send it to planning. Return DESIGN_BRIEF.md with screen/feature traceability and designer questions; creating new production UI or transmitting the brief externally requires that task scope.
