# 保研简历条目撰写

## Overview

根据科研竞赛项目原始材料生成可直接用于保研简历、个人陈述、套磁信、夏令营申请表的学术化条目，并可选产出面试答辩预答与科研主线叙事。

核心原则：**事实重组、量化强化、术语升级**，不是编造。每段输出必须经得起面试追问。violating letter 即 violating spirit：所有规则无例外、无豁免条款。

## When to Use

- 用户给出项目材料（Word/PDF/章程/报告/代码说明）要求写进简历
- 用户已有项目经历，需要压缩成学术话语或统一表述
- 需要为每段经历准备面试追问的对答
- 需要把多个项目串成一条保研叙事主线（个人陈述首段、套磁信开场）
- 需要把多段经历按不同体裁输出（简历/陈述/摘要）

不适用于：纯内容创作（无材料支撑时直接说明缺材料，不虚构）。

## 处理流程

1. **提取**：从材料中抽取项目名、赛事全称、角色、技术点（2-3 个）、关键数据（1-2 个）、成果（论文/软著/奖项/专利）。可运行 `scripts/extract_material.py <材料路径>` 得到标准文本与身份线索。
2. **身份确认**：检查材料中的主持人/负责人/成员名单（提取脚本的身份线索栏目即为此服务），确认是否包含用户本人。若名单不含用户，停止生成，先向用户确认是否参与、由谁主持，不得默认归入用户简历。
3. **核实**：
   - 角色按材料原文定级（见下方判定规则）
   - 赛事用官方全称；材料缺失赛事名或获奖信息时输出 待补充，绝不臆造
   - 材料内部数据矛盾时取保守口径并在交付说明中标注
   - 申报书/方案类材料中的成果（拟发表、拟申请、拟申报、预期）一律视为预期，不得写成已取得；批复状态未知时，标题行来源写 项目来源待补充，不得把申报级别当作已立项级别
4. **生成**：按所选规格输出（见输出规格表），默认简历版。
5. **自检**：运行 `scripts/check_entry.py --entry <条目> --role <角色> --material <材料文本> --spec <规格>`，任何 FAIL 或 WARN 处理完再交付。交付 Word 版时运行 `scripts/build_resume_docx.py`。

## 输出规格（用户未指定时用简历版；可一次输出多规格）

| 规格 | 每条目字数 | 用途 |
|---|---|---|
| 摘要版 | 40-60 字 | 邮件首段、PPT 要点、面试口头自述 |
| 简历版（默认） | 80-110 字 | 简历、套磁信经历段、报名表 |
| 陈述版 | 150-220 字 | 个人陈述、夏令营申请表长栏 |

## 输出模板

```
**项目名 | 赛事全称（无赛事写 项目来源待补充）| 角色**

一段话结构：问题（一句）→ 方法（2-3 个术语，用 提出/构建/实现/承担）→ 关键数据（1-2 个，保留仿真/实测字样）→ 成果（论文/软著/奖项）。
```

陈述版在同一结构内扩充：补充研究背景一句 + 方法与成果的因果关系一句，不堆砌形容词。

## 角色判定规则

| 材料证据 | 角色定级 |
|---|---|
| 材料写明 负责人/主持人/队长/第一完成人 | 项目负责人（项目负责人） |
| 材料写明 核心成员/独立完成某模块/承担关键技术环节 | 核心成员 |
| 材料写明 团队成员/参赛队员/第 N 完成人 | 参赛队员 |
| 材料写明 某环节负责人（算法、数据、报告） | 该环节负责人，如 算法链负责人 |

## 学术动词库（按强度分级选用）

| 层级 | 动词 |
|---|---|
| 强（负责人可多用） | 提出、构建、设计、统筹、主导研发（仅当材料支撑）、独立完成 |
| 中（核心成员） | 实现、负责（仅当材料支撑）、承担、验证、量化、推导、求解 |
| 通用 | 融合、协同、解析、消歧、适配、表征、寻优、解耦、校准、调度 |
| 弱（队员） | 参与、协助、配合、完成数据采集与处理 |

禁用：首创、颠覆、领先、国际先进、填补空白（除非公开报道明确支撑且经用户确认）。

## 数据口径规则

- 检索速度类表述：不写 提升 3 个数量级/1000 倍，写 检索延迟低于 X ms，完全离线运行 或 较向量检索降低约 15 倍（以材料实际数值为准）
- 对比表中自己的方法不是最优时：用 精度与可靠性的工程平衡 表述，不主动展开对比
- 仿真验证（FlexSim、模拟路网、仿真测试）在文字中保留 仿真 字样，答辩口径需主动说明 优化前后对比，非实测
- 代码类成果：说明性质（验证代码/生产系统），少量代码明说行数
- 论文区分 已录用/已发表/在投/拟发表，软著区分 已授权/已受理/拟申请，不得混用

## 数据表达与英文术语规范

### 数据锚点（硬性要求）

- 每条目至少 **2 个数字锚点**（摘要版至少 1 个），从四类中选取：规模（节点数/样本量/组数）、性能（精度/误差/覆盖率）、幅度（时效/效率/成本变化）、时间（时长/响应时间）
- 对比数据带双值：`20.15 → 11.4 分钟`、`4.2 → 2.7 小时`；百分比保留一位小数，误差类保留两位
- 单位规范：分钟（min）、千米（km）、小时（h）、百分比（%）、样本量（n=523）、数据集（FD002）
- 禁止无量词表述：大幅提升、显著改善、效果很好、大量数据。材料无量化数据时写 暂无量化数据，待补充，不造数

### 英文术语规则

- 专业术语首次出现写 `中文（英文全称，缩写）`，如 保形分位数回归（Conformalized Quantile Regression，CQR），后续统一用缩写
- 缩写大小写规范：CQR、SEM、K-Means、A*、PSO、BiLSTM 按惯例；单位 SI 化
- 项目类别参考术语表（按需扩展，不写无依据的英文）：

| 类别 | 术语 |
|---|---|
| 路径与优化 | A*（A-star）、TSP（Traveling Salesman Problem）、TSP-D、FSTSP、PSO（Particle Swarm Optimization）、GA（Genetic Algorithm）、SOM（Self-Organizing Map）、Lagrangian Relaxation |
| AI 与检索 | LLM（Large Language Model）、RAG（Retrieval-Augmented Generation）、Prompts、API 服务 |
| 时序与可靠性 | BiLSTM（Bidirectional LSTM）、Wiener 过程、CQR、RMSE（Root Mean Square Error）、PICP（Prediction Interval Coverage Probability）、MPIW（Mean Prediction Interval Width）、PHM（Prognostics and Health Management） |
| 实证方法 | SEM（Structural Equation Modeling）、KANO 模型、PPS 抽样（Probability Proportional to Size）、TPB（Theory of Planned Behavior）、RBV（Resource-Based View）、STP（Segmentation, Targeting, Positioning）、Cronbach's alpha、KMO 检验 |
| 物流系统 | AGV（Automated Guided Vehicle）、AS/RS（Automated Storage and Retrieval System）、FlexSim、MES、WMS、ERP、OSM（OpenStreetMap）、GIS（Geographic Information System） |

## 可选产出一：答辩预答

每个条目输出 2 个最可能被追问的问题与预答。规则：
- 优先覆盖该条目的薄弱点：角色分工、数据来源（仿真或实测）、对比表劣势、创新点归属
- 预答必须与条目口径一致，且回答中主动呈现材料中的真实证据（如 测试集为固定场景、覆盖率约束下的 RMSE）
- 语气：先承认边界，再给证据，不辩解

## 可选产出二：主线叙事

把多个条目串成一段 100-130 字的科研主线，用于个人陈述首段、套磁信开场。规则：
- 按 方法地基→优化建模→系统落地→学术深化 的能力成长链组织，不按时间流水账
- 每条经历只出现一次，用 1 个关键词锚点代表
- 结尾一句落到目标方向（读博/管科/智慧物流），与目标导师方向呼应
- 无破折号、无中文引号、无形容词堆砌

## 板块：导师定制与套磁信

**触发**：用户提供某位老师的信息（主页文字、网页截图均可）要求定制简历或撰写套磁信。

### 步骤 1：提取导师信息

- 截图输入：先读取图片文字（DSH 环境用视觉工具直接读图；其他环境转 OCR），再结构化
- 文本输入：直接用 `scripts/parse_professor.py --text <文本>` 生成结构化画像
- 画像字段：姓名、职称（是否博导/硕导）、院系、研究方向（逐条）、招生要求与门槛（原文关键句）、团队与学生情况、代表性论文（仅来自用户提供内容）、联系方式
- 未提供字段标 待补充，绝不推测补齐（不编造论文、职称、名额）

### 步骤 2：匹配度分析（输出表格）

| 维度 | 评分（5 分制） | 依据 | 调整动作 |
|---|---|---|---|
| 方向匹配 | | 用户某项目与导师某研究方向的重合度 | 简历突出对应项目 |
| 门槛匹配 | | 招生要求与用户条件（读博意愿/成绩/方向） | 明确告知是否满足 |
| 术语呼应 | | 导师常用语（协同物流、数据驱动、鲁棒优化） | 条目措辞向其靠拢 |
| 团队匹配 | | 团队现有学生方向 | 写套磁信时避免撞车点 |

### 步骤 3：简历定制

- 项目重排：方向最匹配的项目置顶
- 术语对齐：按导师领域替换或补全术语（如 无人机协同配送 → 无人机协同配送（与 FSTSP/TSP-D 框架对齐））
- 弱项处理：与导师方向弱相关的项目精简或删去，不改数据
- 条目数量 4-6 条，其余压缩为一行

### 步骤 4：套磁信模板（300-450 字）

完整结构参照 `letter_template.md`（四段式：开场引用导师方向→专业背景→科研实践→与导师方向结合的思考→研究生规划→结尾），套磁信按以下压缩：

```
尊敬的X老师：
您好，我是XX大学XX学院XX专业的大三学生，拟申请XX年推免生。拜读您关于（导师真实方向/论文，仅限用户提供信息）的研究，与我的（匹配项目）高度相关，冒昧来信……
（第一段：身份+申请意向+具体契合点，用导师真实方向）
（第二段：1-2 个匹配项目，第一人称叙述，数据保留，角色真实）
（第三段：技术能力+读博/硕士意向如实说明+态度）
（第四段：询问招生名额，说明附件：简历、成绩单、代表性成果；附联系方式）
```

可用 `scripts/build_letter.py` 生成初稿（--mode letter 套磁 / recommend 自荐，输出内置六项检查：称呼、导师方向引用、项目经历、附件说明、联系方式、字数）。

### 隐私红线（强制）

- 发送前运行 `scripts/redact_pii.py --check <草稿>`，检测姓名（--names 提供）、手机号、邮箱、身份证号、学号、日期；确认仅保留必要字段
- 任何公开渠道（GitHub、博客、社交平台）分享的样例、模板、脚本输出必须完全脱敏，个人真实姓名/学校/成绩/联系方式不得进入公开仓库
- 用户明确标记"不能泄露"的材料原文仅保留在用户本机，不写入任何版本库

### 套磁信红线

- 只引用用户提供材料中的导师信息，不编造论文题目、职称、招生名额
- 不写"求收留"式乞求语；不夸大自身（不写 第一/最强）
- 每封信只写一个导师，明显长于 500 字则压缩
- 发送前核对：导师姓氏、刊物、项目名与材料一致

## 自检清单（每项必查）

- [ ] 无破折号（em dash、en dash），无中文引号（左右双引号、单引号），补充说明用逗号或括号
- [ ] 动词与角色匹配（见角色判定与动词库）
- [ ] 每个数字都能在材料中找到出处
- [ ] 仿真数据带 仿真/测试 字样，与实测区分
- [ ] 字数落在所选规格区间
- [ ] 无 主导/首创 类空泛表述，除非材料原文明确支撑
- [ ] 赛事名称用官方全称
- [ ] 论文/软著状态用词准确（已录用/已发表/在投/已授权/已受理/拟申请）
- [ ] 若用户要求答辩预答或主线叙事，均按可选产出规则生成

## 脚本工具（推荐工作流）

| 脚本 | 作用 | 调用 |
|---|---|---|
| `scripts/extract_material.py` | 材料转标准文本，输出身份线索（负责人/成员/分工关键词行），支持 docx/doc/txt/md | `python scripts/extract_material.py 材料.docx --out 文本.txt` |
| `scripts/check_entry.py` | 条目合规校验：破折号/弯引号、禁用词（首创/颠覆等）、字数区间、数字溯源（逐数字在材料中查找）、角色动词匹配 | `python scripts/check_entry.py --entry 条目.txt --role 项目负责人 --material 材料.txt --spec 简历版` |
| `scripts/build_resume_docx.py` | 条目 md 排版为简历 Word（标题黑体加粗、正文宋体、全黑、无斜体、缩进） | `python scripts/build_resume_docx.py 条目.md --out 简历.docx --title 科研与竞赛经历 --author 姓名` |
| `scripts/parse_professor.py` | 导师信息文本结构化（邮箱/职称/研究方向/招生要求/团队学生/论文线索），供导师定制板块使用；截图先转文字再传入 | `python scripts/parse_professor.py --text 导师信息.txt --json -o 画像.json` |
| `scripts/redact_pii.py` | PII 脱敏（姓名/手机号/邮箱/身份证/学号/日期→占位符），发送与公开分享前强制运行 | `python scripts/redact_pii.py 草稿.txt --names 姓名1,姓名2 --out 脱敏.txt` |
| `scripts/build_letter.py` | 按模板生成推免自荐信/套磁信初稿（输入导师画像+用户信息+条目，内置六项检查） | `python scripts/build_letter.py --professor 画像.json --me 用户.json --entries 条目.md --mode letter --out 信.md` |

依赖：python-docx（docx 处理与 Word 生成）、pywin32（旧版 doc 提取）。脚本输出 UTF-8，中文路径安全。

## Common Mistakes

- 把 参与 包装成 负责：面试问分工必翻车，角色升格是最高风险
- 把别人的项目（主持人非用户本人）直接写进用户简历
- 把申报书中的预期成果（拟发表/拟申请）写成已取得
- 写成营销文案（首创、颠覆、领先某某）而非学术话语
- 破折号与中文引号混入（用户格式规则）
- 把 FlexSim/模拟路网结果写成像实测数据
- 陈述版堆砌形容词，没有增加事实粒度
