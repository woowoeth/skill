# 行业黑话解码器 · 领域导航术

> 每个行业都有两本词典：一本写在百科里，一本只在酒桌上流通。新人交的学费，大多是为第二本。

## 核心理念

解码器不做术语表，做**领域导航员**。

一个好的行业Skill是一张"新人生存地图"：
- 这个圈子的**黑话**是什么？（同一个词，圈内圈外意思可能相反）
- **钱和利益怎么流动**？（生态地图——谁付钱、谁抽成、谁背锅）
- 有哪些**潜规则**？（圈内共识但没人明说的规矩）
- 新人**怎么死**？（典型坑、被割模式、危险信号）
- 什么是解码器**做不到的**？（诚实边界——潜规则类信息天然难验证）

**关键区分**：捕捉的是这个行业的人 HOW they operate（怎么运作、怎么算账、怎么踩坑），不是这个行业 WHAT it is（百科定义）。

## 执行流程

### Phase 0: 入口分流

| 用户输入 | 路径 | 示例 |
|---------|------|------|
| 明确行业/圈子 | **直接路径** → Phase 0A | 「解码跨境电商」「搞懂量化私募这个圈」 |
| 只有目标 | **诊断路径** → Phase 0B | 「下周去MCN面试但我不懂这行」「想接政府项目但没门路」 |

### Phase 0A: 需求澄清（直接路径）

收到明确行业后，确认（**每项都有默认值，确认不阻塞交付**）：

1. **行业边界**：「跨境电商」是亚马逊精品还是TikTok铺货？子领域黑话可能完全不同（默认：主流子领域+标注分支差异）
2. **用户角色**（决定调研侧重）：求职者 / 创业者 / 采购合作方 / 投资观察者 / 纯了解（默认：新人通用视角）
3. **地区语境**：同一行业中美玩法可能完全不同（默认：用户所在语言区的主流市场）
4. **新建 or 更新**：检查 `.claude/skills/` 是否已有该行业Skill
5. **内部语料**：「你手上有没有这个圈子的一手材料？聊天记录、内部群精华、行业报告、合同模板。有的话质量远超公开调研。」
6. **解码档位**（开跑前必须报成本量级）：

| 档位 | 调研规模 | 适用场景 | 成本量级 |
|------|---------|---------|---------|
| 快速 | 3个维度（术语01+生态02+新人坑04），每维度限5个来源。潜规则集与信息源地图从01/02/04顺带提取，产物中标注「快速档：此节颗粒度粗」 | 面试急用 / 先看看 | 约标准档1/3 |
| 标准（默认） | 6个维度完整调研 | 大多数场景 | 中等 |
| 深度 | 6维度 + 争议事件深挖 + 信息源地图完整版 | 打算长期进入该行业 / 开源发布 | 最高 |

用户只说「就解码这个」→ 默认：主流子领域 + 新人通用视角 + 本地区市场 + 标准档，直接推进。

### Phase 0B: 需求诊断（模糊路径）

用户有目标没行业认知。通过≤2轮追问定位：**用户角色**（去干嘛）× **接触深度**（下周面试 vs 半年内创业）× **最怕什么**（说错话 / 被割 / 选错方向）。

然后给出解码方案而不是行业推荐——用户的行业通常是给定的，需要诊断的是**解码侧重点**：

```
### 解码方案：[行业]（[角色]视角）
**优先解码**：[对这个角色最致命的2-3个维度]
**可以略过**：[这个角色暂时用不到的维度]
**特别提醒**：[该行业对该角色的最大风险，一句话]
```

### Phase 0.5: 创建自包含Skill目录

**收到确认后立即执行**：

**slug命名规则**：行业通行英文名小写连字符（跨境电商→`cross-border-ecommerce-navigator`）；无通行英文名用拼音。含子领域时带上（`amazon-fba-navigator`）。

```
.claude/skills/[industry-slug]-navigator/
├── SKILL.md                          # 最终产物
└── references/
    ├── research/                     # 每个调研任务的结果（必存）
    │   ├── 01-jargon.md              # 术语与黑话：行话、缩写、圈内梗、同词异义
    │   ├── 02-ecosystem.md           # 生态地图：玩家角色、利益链、钱怎么流动
    │   ├── 03-unwritten-rules.md     # 潜规则：圈内共识但不明说的规矩
    │   ├── 04-newbie-traps.md        # 新人坟场：常见坑、被割模式、失败案例
    │   ├── 05-info-map.md            # 信息源地图：圈内可信信源 vs 卖课割韭菜的
    │   └── 06-trends.md              # 趋势与争议：最近12个月动态、圈内分歧
    └── sources/                      # 一手素材（用户提供的内部材料）
```

**关键规则**：
- 每个调研任务必须落盘。**不存文件的调研等于没做**。
- 所有文件存在skill目录内部，复制整个目录即可独立使用。
- 用户提供的内部语料存入 `sources/`，调研文件中明确标注「来自用户素材」vs「来自公开调研」。

### Phase 1: 多源信息采集（并行优先，串行兜底）

#### 6个调研任务分配

| # | 任务 | 搜索/提取目标 | 输出文件 |
|---|------|-------------|---------|
| 1 | 黑话 | 行话/缩写/圈内梗；重点抓**同词异义**（圈内含义≠字面）和**信号词**（说这个词=什么身份/立场） | `01-jargon.md` |
| 2 | 生态 | 上下游角色、每个角色靠什么赚钱、抽成结构、谁依赖谁、权力在哪 | `02-ecosystem.md` |
| 3 | 潜规则 | 从业者复盘帖/离职爆料/访谈中反复出现的「懂的都懂」；报价规矩、账期惯例、关系规则 | `03-unwritten-rules.md` |
| 4 | 新人坑 | 失败复盘、维权帖、被割案例；提炼**被割模式**（话术特征→收割手法→受害画像） | `04-newbie-traps.md` |
| 5 | 信源 | 这个圈子里大家真正看什么（社群/KOL/报告/数据源）；**同时标记营销号和卖课盘的识别特征** | `05-info-map.md` |
| 6 | 趋势 | 最近12个月的政策/平台规则/格局变化；圈内正在吵什么（分歧=活的信息） | `06-trends.md` |

每个任务的硬性要求：
- 注明来源和可信度：从业者一手陈述 > 行业报告 > 媒体报道 > 匿名爆料（需≥2个独立来源互证）
- 区分「多方证实的」vs「单一来源的」vs「我推断的」vs「**模型记忆**」——**潜规则和坑的部分尤其要标**
- **模型记忆规则**：执行agent对常见行业有训练语料残留，且行业知识过时极快。凡是没有外部来源确认、仅凭记忆写下的行业信息，必须标注「凭记忆，未核实且可能过时」，且此标注必须传递到最终SKILL.md——不许在提炼时静默洗白
- 圈内说法互相矛盾时保留矛盾（不同层级/地区玩法本就不同），不要和稀泥

#### ⚠️ 内容污染红线（本Skill最大的敌人）

行业入门内容是**卖课营销号的重灾区**。很多领域搜到的"干货"本身就是收割新人的鱼饵。因此：
- 凡是结尾导向"扫码进群/买课/加微信"的内容，只能作为**收割话术样本**进04号文件，绝不作为行业知识来源
- "月入X万""普通人也能"句式 = 营销内容强信号，标记后弃用
- 优先找**利益无关的从业者陈述**：离职复盘、维权记录、行业报告、监管文件、上市公司财报（生态和钱流的最硬证据）

#### 合规边界（不可越）

- 金融类行业：解码生态和黑话，**不提供投资建议**，产物Skill必须继承此约束
- 医疗/法律类：同上，解码行业不替代执业建议
- 灰产/违法产业：拒绝解码（「XX行业怎么刷单」不做）；合法行业中的灰色环节可以**描述现象用于避坑**，但不提供操作方法

#### 失败降级表（if-then-兜底）

| 触发条件 | 一线修复 | 兜底 |
|---------|---------|------|
| 运行环境不支持并行subagent | 6个任务降级串行，做完一个落盘一个 | 单agent分6轮，每轮一维度立即落盘 |
| 上下文窗口不足 | 分Phase续跑：**调研文件即断点**，新会话先读已落盘文件 | 分3段会话跑 |
| 成本失控 / 中途喊停 | Phase 0A档位确认就是熔断器 | 已落盘文件即为可交付中间产物 |
| 封闭行业公开信息极少（如toG、某些B2B） | 提示用户「这个行业的知识主要在人身上」，请求内部语料 | 只交付生态+公开合规部分，潜规则维度诚实标注空缺 |
| 潜规则信源全是匿名帖无法互证 | 降置信度收录，标「单一来源，谨慎参考」 | 该条目移入「传闻区」单独隔离 |
| 搜索工具不可用 | 换等价工具 | 切纯本地语料模式 |
| 目标地区信源不可达（搜索工具语言/地区受限，如US-only工具查中文圈） | 该地区条目按模型记忆规则标注，产物正文声明地区覆盖缺口 | 引导用户提供本地语料（社群记录/本地媒体存档） |
| Phase 4 无法spawn独立子agent | 主agent以「圈内老兵挑刺」视角重读执行三项测试，产物诚实边界标注「验证非独立执行」 | 交付时明确告知，建议用户新开会话复测 |

### Phase 1.5: 🔴 CHECKPOINT · 调研质量确认

展示摘要表：各维度来源数、关键发现、单一来源未互证的条目数、信息空缺维度。**特别展示：有多少内容因疑似营销污染被弃用**（这个数字低反而可疑）。用户确认 → Phase 2。

### Phase 2: 导航框架提炼

先读取 `references/methodology.md` 获取收录判据。

**2.1 核心黑话表（20-40条）**：不是越多越好。收录判据（三重验证变体）：
- **圈内共识度**：≥2个独立来源确认同一含义
- **信息差价值**：圈外人会误解或听不懂（「用户增长」不收，「自然单」收）
- **行动相关**：知不知道这个词会影响实际决策/表现

**2.2 生态地图**：角色→靠什么赚钱→谁付钱给谁→权力位置。必须能回答「这个行业的钱最终从谁口袋出、在哪个环节被谁截留」。

**2.3 潜规则集（5-15条）**：每条标注置信度（多方证实/单一来源/推断），并写清**违反的代价**。

**2.4 防割清单（5-10条）**：从04号文件提炼被割模式，格式：话术特征 → 背后的收割手法 → 见到时该做什么。

**2.5 信息源地图**：可信源清单 + 营销号识别特征。

**2.6 诚实边界**：潜规则类信息无法完全验证；地区/层级差异大；行业变化快于调研；解码器给的是地图，不是通行证——人脉和实操经验蒸馏不了。

### Phase 2.5: 🔴 CHECKPOINT · 提炼确认

展示摘要（黑话N条+生态角色N个+潜规则N条含置信度分布+防割清单N条），用户确认后再构建。

### Phase 3: Skill构建

读取 `references/template.md` 填充。要点：

- **产物description**：<300字，正向触发（行业名+该行业专属黑话词）+ 负向触发（「不在用户要具体投资/医疗/法律建议时触发」）
- **Agentic Protocol**：产物Skill遇到涉及具体平台/政策/价格的问题时先搜最新信息（行业规则变化快，训练语料必过时），研究维度从生态地图反推（先查钱流上下游的最新变动）
- **合规约束继承**：Phase 1的合规边界必须原样写进产物Skill
- **终检**：交付前全文搜索 `[` 占位符（仓库链接、行业名模板变量），全部替换或明确留待用户填写；核对description中的数字声明（N条黑话等）与正文实际数量一致
- **⚠️ `$数字` 禁用**：SKILL.md正文不得出现 `$0`/`$1` 等「$紧跟数字」写法——部分runtime的skill加载器会把它当参数占位符插值，正文被污染（实测发现：`$0.30` 被替换成用户传入的参数文本）。金额一律写「0.30美元」或「USD 0.30」

### Phase 4: 独立验证

先跑结构自检脚本（确定性检查，不耗token）：`python [skill目录]/scripts/quality_check.py <产物SKILL.md路径>`——全过后再进入主观验证。

**主观验证用独立子agent执行**（生成者不自评）：

1. **圈内一致测试**：选3个该行业从业者有公开共识的问题，用新Skill回答，对比真实行情
2. **边缘诚实测试**：问1个信息不足的子领域问题，期望标注「此维度信息有限」而非编造
3. **防割实战测试**：给1段真实风格的收割话术，检查Skill能否识别并给出行动建议

通过标准：

| 检查项 | 通过 | 不通过信号 |
|--------|------|-----------|
| 黑话条目 | 20-40条，全部≥2源互证或标注单源 | 堆砌百科词条 / 无置信度标注 |
| 生态地图 | 能回答「钱从谁出、被谁截留」 | 只有角色罗列没有钱流 |
| 潜规则置信度 | 每条有标注 | 传闻当事实 |
| 防割清单 | 有具体话术特征+应对动作 | 只有「小心骗子」式空话 |
| 诚实边界 | ≥3条，含「无法验证的部分」 | 只有免责套话 |

迭代上限2轮，超限则标注薄弱维度后交付。**宁可交付诚实标注局限的60分Skill，也不造看似全知实则编造的90分Skill。**

### Phase 4.5: 真实调用测试（Live Test）

离线验证（脚本+子agent读文件）测不到skill被loader真实加载后的行为——插值污染、触发命中、实搜分支都只有真实运行才暴露。Phase 4通过后执行：

1. **加载确认**：产物出现在当前runtime的可用skill列表。不支持会话内热加载的runtime → 引导用户新开会话执行本Phase
2. **插值污染检查**：带参数真实触发一次，通读被加载的正文，检查是否被污染。重点：`$数字`写法（费率/价格高发）、残留模板占位符（实测教训：`$0.30`会被loader当参数占位符替换成用户输入）
3. **实搜分支实跑**：问一个时效性问题（如某渠道当前费率/平台政策），验证：①搜索真的执行了而不是凭内置数据回答；②实时信息与skill内置数据不一致 → 更新内置数据并标注日期（实测教训：产物写入当天，内置费率就可能已过时）
4. **触发边界抽查**：用一个命中负向触发的相邻问题（如一般编程问题、要求投资建议）确认不误命中且合规拒答生效

任一项失败 → 修复后只重测该项。runtime无法执行真实调用 → 在诚实边界标注「未经真实调用测试」，把以上4项转为用户自测清单随产物交付。

🔴 CHECKPOINT · 展示离线+真实调用两级验证结果，用户确认后交付。

## 更新已有行业Skill

「更新XX行业」→ 只重跑任务6（趋势）+ 任务4（新型坑），增量更新，刷新调研日期。行业Skill建议每6个月更新——**过时的行业地图比没有地图更危险**。

## 反模式黑名单（绝不做）

| # | 反模式 | 为什么 / 替代做法 |
|---|--------|------------------|
| 1 | 把卖课内容当行业知识 | 那是鱼饵不是干货。营销内容只进「收割话术样本」 |
| 2 | 传闻当事实 | 潜规则必须标置信度；单一来源进「传闻区」隔离 |
| 3 | 做成百科术语表 | 收录门槛是信息差价值：圈外人会误解的才收 |
| 4 | 提供投资/医疗/法律建议 | 解码行业≠执业建议，产物Skill必须继承此约束 |
| 5 | 解码灰产/违法产业的操作方法 | 拒绝；合法行业的灰色环节只描述现象用于避坑 |
| 6 | 只写光明面 | 没有坑和潜规则的行业Skill=旅游宣传册，新人坟场维度不可省 |
| 7 | 忽略地区/层级差异 | 「这行就是这样」大概率只是某个层级的样子，标注适用范围 |
| 8 | 不报成本量级直接开跑 | 完整解码是重任务，先选档位 |
| 9 | 把检查点变成交付阻塞 | 能给默认值就给默认值 |
| 10 | 用过时信息冒充现状 | 行业变化快，一切具体规则/价格标注信息日期 |

## 特殊场景

- **封闭行业**（toG、军工配套、某些B2B）：公开信息天然稀薄，提前告知「这个行业的知识主要在人身上」，主打生态+合规框架，潜规则维度诚实空缺
- **快变行业**（跨境电商、直播、加密）：任务6权重加倍，产物内所有具体规则强制标注日期，建议3个月更新
- **强监管行业**（金融、医药）：合规边界前置，监管文件列为最高优先信源
- **地方性行业**（餐饮加盟、工程承包）：地区差异写进每个维度，不做全国通用假设
- **用户已在行内**（「我干了2年但想看懂上层玩法」）：跳过基础黑话，调研聚焦生态上游和资本层，Phase 0A确认当前层级
