# 公众号内容创作

面向公众号等新媒体平台的一站式内容创作。核心链路：**选风格 → 生成正文 → 生成标题摘要 → 生成封面 prompt**。

项目原型是"公众号写作神器"，本 skill 提炼其写作规范，并抽象为可扩展的风格框架。

## 目录约定：每篇文章一个文件夹 ⚠️ 强制执行

**每一篇文章的所有资产，必须收在同一个文件夹里**，不要散落到 `examples/`、`assets/` 等公共目录。这样文章可复制、可归档、不会串图，也是本 skill 后续所有命令的默认假设。

建一个 `articles/` 目录存文章，每篇一个子文件夹，例如：

```
articles/
  9k跨行-我用AI求职/            ← 一篇文章一个文件夹
    manifest.json               ← 该篇的批量出图清单
    generated/                  ← 配图落在这里（image2.py 默认输出，含封面+正文图）
    {标题}.md                   ← 成稿（正文/标题/摘要）
    {标题}-titles.json          ← 5 组标题+摘要
    {标题}-排版.json            ← 排版单元 JSON
    {标题}_wechat.html          ← 微信导入版 HTML（preview.js 生成）
    {标题}_shot.png             ← 预览截图（render.js 生成）
```

一篇的典型目录结构：

| 资产 | 文件名 | 由谁生成 |
|------|--------|----------|
| 成稿 | `<篇名>.md` | 手写/LLM |
| 标题摘要 | `<篇名>-titles.json` | 第 2 步 |
| 出图清单 | `manifest.json` | 第 3 步 |
| 配图 | `generated/<asset_id>/*.png` | image2.py |
| 排版单元 | `<篇名>-排版.json` | 动手排 |
| 预览截图 | `<篇名>_shot.png` | render.js |
| 微信导入版 | `<篇名>_wechat.html` | preview.js |

**关键规则：**
- **全部命令在 `articles/<篇名>/` 目录内执行**（或用相对该目录的路径），只引用本文件夹内的文件。
- **排版 JSON 里的图片路径用相对路径**（如 `generated/cover/cover_1.png`），工具会自动以**排版 JSON 所在目录**为基准解析——这是防止"图找不着"的关键。
- 不要复用全局 `assets/manifest.json`；每次把该篇的 `manifest.json` 放进文章文件夹。

## 风格体系

风格是"结构化 prompt 指令"，决定文章的辨识度。用户可以在 `styles/` 目录添加 `.md` 风格文件来扩展，文件名即风格名。styleLoader 会自动读取。

每个风格文件遵循统一骨架：

1. **Role** — 一句定位（谁在写、文风、立场）
2. **Task** — 一句话任务说明（围绕主题写一篇[X]文章）
3. **Style Constraints（至关重要）** — 最具辨识度的硬约束：语气态度、结构节奏、语言特征
4. **Negative Constraints（禁止事项）** — 明确"不要出现什么"，防止 AI 味
5. **Example Sentence Pattern** — 可复用的句式模版（可选）

内置风格见 `styles/科技媒体评论.md`。写之前先确认用哪个风格；未指定则默认采用该风格或询问用户偏好。

## 写作流程

### 第 1 步：生成正文

加载所选风格的约束，作为 system message，主题作为 user message，流式输出。风格约束主要看 `styles/` 对应文件。

公共要求（适用于所有风格）：

- 用第一人称 + 明确立场，拒绝客服式客气语
- 短段落（每段不超过 5 句），关键句独立成段，适配手机阅读
- 结尾用一句金句收尾、升华主题
- 禁止总结性过渡词（如"综上所述"、列点式教科书结构）
- **字数：正文目标 1500–3000 字（汉字）**，低于 1500 需扩写。扩写用具体场景、真实例子、比喻、对比来充实，不要注水/堆形容词

### 第 2 步：生成标题摘要

正文完成后，一次性生成 5 组"标题 + 摘要"。规范如下：

- 标题要有吸引力：风格多样，可含疑问句、数字型、反差型
- 摘要在 1-2 句内概括核心观点，语言精炼有力
- 标题与摘要严格一一对应
- 严格返回 JSON 数组，无其他内容：

```
[
  {"title": "标题1", "summary": "摘要1"},
  {"title": "标题2", "summary": "摘要2"},
  {"title": "标题3", "summary": "摘要3"},
  {"title": "标题4", "summary": "摘要4"},
  {"title": "标题5", "summary": "摘要5"}
]
```

### 第 3 步：生成封面 & 正文配图（图文并茂）

根据正文提炼关键点并生成 3 个不同风格的文生图 prompt：

- 先提炼 2-3 个关键内容点（每个不超过 15 字）
- 生成 3 个不同风格封面 prompt：如科技感/赛博朋克、极简/扁平化、抽象/概念化
- 每个 prompt 用英文撰写：包含视觉描述、风格、色调、构图
- 统一宽高比 **2.35:1**（宽幅横图），prompt 中明确标注
- 严格返回 JSON：`{"keyPoints": [...], "prompts": [...]}`

**实际出图**：用同目录的 `image2.py`（OpenAI 兼容文生图/图生图，标准库实现，无第三方依赖）。在文章文件夹内执行，默认把图输出到该文件夹的 `generated/`。

```bash
# 单张（prompt 用引号包住）
python image2.py --size 1536x1024 --quality high "your prompt" --output-dir generated
# 批量（推荐做封面+正文配图，一次跑完、风格统一；不加 --output-dir 就落在 manifest 同级 generated/）
python image2.py --batch manifest.json
# 只重生成某一张
python image2.py --batch manifest.json --asset-id cover
```

- 批量清单 `manifest.json` 放进文章文件夹，结构：`defaults`（size/quality）、`prompt_prefix`（统一到每张）、`assets`（每条 `id`+`prompt`）
- 输出机器友好 JSON（`path`/`url`/`b64_json`），批量写入 `generated/<asset_id>/`
- **无文字原则**：公众号封面/配图通常由系统叠加标题，图内 prompt 加 `no text, no words, no letters` 避免乱码
- **风格统一**：配图要"图文并茂"，给整套图配统一色调（如深海军蓝+电光青）更显专业。若要线稿/手绘等其他风格，改 `prompt_prefix` 即可

## 图文并茂

正文配图按小标题/段落生成，1 张封面 + 若干张段落插图。每张图对应一个核心观点，形成视觉节奏。

## 可视化预览 + 循环修正（tools/）

写完文章后，先把内容排成「排版单元」JSON，用工具渲染成公众号样式截图，**读图检查排版，发现问题就改 JSON 再渲染，循环直到满意**。这一个闭环是 skill 的核心能力。

### 用途
把"发布前审稿"变成 agent 可自动完成的视觉检查：无 markdown 脏符号、图文位置对、金句/关注引导有呼吸感。

### 排版单元 JSON

文章内容转成 `blocks` 数组，每个 block 一个 `type`：

| type | 作用 | 关键字段 |
|------|------|----------|
| `title` | 文章主标题 | `text`, `meta` |
| `subtitle` | 副题/摘要 | `text` |
| `cover` | 封面大图 | `image` |
| `quote` | 引用 | `text` |
| `heading` | 小标题 | `text` |
| `paragraph` | 段落 | `text` |
| `image` | 配图 | `image`, `caption` |
| `highlight` | 金句（居中加粗） | `text` |
| `divider` | 分割线 | — |
| `action` | 关注引导 | `text` |

图片用相对路径即可（相对排版 JSON 所在目录），工具会自动解析；也可用绝对路径。

### 一键渲染截图

```bash
# 排版 JSON -> 公众号样式 PNG（默认手机宽度 375）
# 在文章文件夹内执行：node ../tools/render.js <篇名>-排版.json 375
node ../tools/render.js 9k跨行-排版.json 375
# 输出 <篇名>_shot.png 就到文章目录里
```

### agent 修正循环

1. 检查排版单元 JSON 是否有 markdown 符号（`**`、`> `、`#`），有就去掉改用对应 type
2. `node ../tools/render.js <篇名>-排版.json 375` 出图（输出到文章目录）
3. **Read 读取 PNG**，逐项核对：
   - 标题/摘要/封面是否齐全
   - 小标题、配图是否出现在正确位置
   - 金句是否有分隔线 + 呼吸感
   - 结尾 action（关注引导）是否独立成块、有留白
   - 有无溢出、文字挤压、图片重复
4. 发现任何问题 → 改 JSON（或 `preview.js` 的 CSS）→ 重新 `render.js` → 再读图，循环至满意

### 一键导入公众号平台

写完文章、确认预览后，用「微信兼容版 HTML」复制到公众号编辑器。

⚠️ 重要：微信公众号编辑器对外部 HTML 有严格白名单，**只保留文本级样式**（字号、颜色、加粗、居中、行距、字间距），会剥掉背景色块、圆角、padding、`<h1><section>` 等装饰样式，剥不干净时整段退回纯文本。

所以"能一键导入"的样式范围是：
- ✅ 小标题加粗 + 颜色、金句加粗居中、关注引导加粗居中
- ❌ 灰底/圆角/内边距这些"块状"样式，粘贴即丢失（如需背景块，用 135/壹伴 或手动加）

正确流程（必须用浏览器复制，微信才识别富文本）：

```bash
# 1) 渲染：class 版(截图用) + _wechat.html(微信兼容版, 内联文本级样式 + 图片base64)
# 在文章文件夹内执行
node ../tools/preview.js <篇名>-排版.json <篇名>
```

然后用浏览器打开 `<篇名>_wechat.html` → Ctrl+A 全选 → Ctrl+C → 公众号 Ctrl+V。

不要用脚本直接注入剪贴板（`clip.js`）——微信编辑器对程序注入的 CF_HTML 识别率低，会退回纯文本。

- 图片：微信粘贴 base64 可能不认，若没图则手动把图片插进公众号编辑器

### 工具文件

- `tools/render.js` — 一键封装（排版 JSON → PNG）
- `tools/preview.js` — 排版 JSON → 公众号样式 HTML（输出 class 截图版 + _wechat 导入版）
- `tools/shot.js` — HTML → 整页 PNG（playwright-core + 系统 Chrome，fullPage 精准截图）
- `tools/clip.js` — 把导入版 HTML 写入剪贴板（富文本）
- 依赖：`tools/node_modules`（仅 playwright-core，复用本机 Chrome，无需下载浏览器）


## 使用建议

- **先定风格再动笔**：风格框定了口吻和结构，选错风格整篇就废。
- **正文优先流式**：提供实时生成体验，避免一次性等待。
- **标题要 A/B 备选**：5 组给用户挑，不要只给一个。
- **封面约束别放松**：2.35:1 与风格多样性是硬指标，避免千篇一律。
- **先建文章文件夹再干活**：动手前先 `mkdir articles/<篇名>/`，之后所有产物都放里面，别散落公共目录。
