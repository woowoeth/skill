# 圖表與統計驗算

簡報和報告裡的圖表是最容易出事、也最有價值的部分。做對了，能在上台前抓出報告裡的數字錯誤；做錯了，會把錯誤包裝得更自信、更難被發現。

這份紀律來自一次真實的跨平台驗證——同一份 100 筆數據，三家 AI 的結果天差地遠。三個具體的崩壞案例在 `references/failure-cases.md`。

---

## 四條鐵律

1. **真算，不是假算。** 把原始數據完整嵌入，用程式（Python／SVG 繪圖）實際計算每一個統計值，並**留下程式碼或計算過程**。讓任何人都能重跑驗證。「看起來有算」不算。
2. **重算文件聲稱的每個數字。** 報告說活化能 48.2？自己用它附的數據擬合一次看看。報告說平均誤差 8.2%、R² > 0.995、斜率多少？逐項重算，與原文比對。哪些一定要重算，見 `references/recompute-checklist.md`。
3. **不一致就如實標註。** 寫「擬合值 45.7 vs 報告值 48.2，差 2.5，發表前需核對」，標在圖上或圖旁。
4. **裁決留給人。** 標註待核即可，不要替使用者下最終結論。⛔ **若發現重大數字差異，停下來向使用者回報，等裁決再繼續**，不要自己決定要用哪個數字。

---

## 執行順序

1. **先取得原始數據**。只有結論數字、沒有原始數據時，⛔ 停下來問使用者要——沒有原始數據就無法驗算，這時只能說「無法驗證」，不能靠印象判斷對錯。
2. **列出文件聲稱的所有數字**，逐項對照 `references/recompute-checklist.md` 標記哪些要重算。
3. **實際跑計算**（Python / numpy / scipy 或等效工具），保留程式碼。
4. **比對並分類**每一項：一致 ✅／小幅差異（四捨五入、有效位數）⚠️／實質不一致 ❌。
5. **畫圖**（若需要）：一律用原始數據繪製，把數據嵌進輸出檔，圖由程式即時畫出。
6. **輸出驗算報告**：哪些對、哪些有落差、落差多少、可能原因、建議怎麼核對。實質不一致的項目 ⛔ 交給使用者裁決。

---

## 三條紅線（`references/failure-cases.md` 有完整案例）

這三個是實測中真的發生過的崩壞：

- **背書錯誤值（假算）**：算出一個「剛好符合報告」的數字，但那個數字根本無法由原始數據重現。**湊答案比不算更糟。**
- **捏造誤差**：公式代入得到離譜結果（例如 99% 誤差）就當成真實偏差去渲染。正確做法是**先懷疑單位／倍率不一致**，標註「公式與數據尺度對不上、不可直接引用」。
- **指控原作者**：基於自己未經交叉驗證的計算，說作者「刻意美化」「低估偏差」。**永遠不要**。發現不一致，描述事實、標註待核，把判斷交給人。

## 自我檢查清單（交付前過一遍）

- [ ] 原始數據是否完整嵌入、圖由程式即時畫出？
- [ ] 文件聲稱的每個統計值都重算過、且結果能由數據重現？
- [ ] 代入公式得到的怪異結果，是否先排除過單位／倍率問題？
- [ ] 不一致處是否「標註待核」而非擅自改數字？
- [ ] 是否避免了對任何人的指控、把裁決留給使用者？
- [ ] 重大差異是否已 ⛔ 停下來回報，而不是自己選了一個數字繼續？

> 對照基準：在那次跨平台驗證裡，能做到以上全部的平台拿了滿分；背書錯值＋捏造誤差＋指控的平台只拿 1/5。差別不在算力，在紀律。
