# JING JING Clarifier（晶晶體修飾器）

## 目標

將以中文為主、但混入不必要英文的文本修訂為自然、清楚且一致的繁體中文。

優先順序：

1. 保持原始事實、技術語意與邏輯。
2. 保持所有不可安全改寫的精準字串。
3. 減少沒有必要的中英混寫。
4. 使用台灣自然且符合領域慣例的繁體中文。
5. 維持全文術語與寫作風格一致。

本 Skill 的目標不是消除所有英文。對專有名詞、業界慣用術語或翻譯後反而降低精確度的詞彙，應保留英文。

## 適用情境

在下列情況使用：

- 中文潤稿。
- 技術文件中文化。
- 清理中文句子中不必要的英文。
- 修正「晶晶體」或不自然的中英混寫。
- 統一繁體中文技術術語。
- 在不改變工程語意的前提下改善中文可讀性。

若使用者只是要求翻譯一個單字、解釋術語，或要求保留原有中英混寫風格，則不應機械套用本 Skill。

## 術語決策優先順序

發生術語選擇衝突時，依下列順序處理：

1. 使用者明確指定的詞彙、格式與 glossary。
2. 目前文件或專案中已建立且一致使用的術語。
3. 台灣該專業領域常用的繁體中文術語。
4. 可明確判定且不會失真的自然中文翻譯。
5. 若翻譯可能造成歧義、失真或不自然，保留英文。

不得僅為了減少英文而強行翻譯。

## 必須保護的內容

除非使用者明確要求修改，以下內容視為 protected literals，不得自行變更：

- 專案、服務、產品、品牌與公司名稱。
- API、SDK、協定、標準與正式規範名稱。
- CLI 指令與參數。
- 程式碼與 inline code。
- shell command。
- 檔案與資料夾路徑。
- URL。
- 環境變數。
- 欄位名稱與 schema key。
- class、function、method、variable 等程式識別碼。
- issue、task、test、requirement 等識別碼。
- commit hash。
- 版本號。
- 錯誤碼。
- 數值與單位。
- placeholder、template token 與格式字串。
- Markdown link 的目標網址。
- 使用者要求逐字保留的引用內容。

例如：`docker build`、`--no-cache`、`C:\Projects\example`、`/var/log`、`OPENAI_API_KEY`、`REQ-123`、`REP_B02`、`v1.2.3`、`if (healthcheck)`。

上述字串即使包含一般英文單字，也不得因中文化而修改。

## 中文化判斷

### 一般敘述

一般中文句子中的英文連接詞、功能詞與可以自然改寫的英文敘述，應優先改成中文。

例如「A and B 都通過」可改為「A 與 B 都通過」。但若 `and` 位於程式碼、命令、正式名稱或其他 protected literal 中，則不得修改。

### 技術術語

具有穩定且自然中文用法的技術概念，可以中文化。

若英文術語在該領域通常直接使用英文、中文譯名不穩定、翻譯後容易與其他概念混淆，或英文原文對技術精確度較重要，則保留英文。

不得使用固定字典進行機械式逐字替換。

### 專有名詞與縮寫

品牌、產品名稱、正式標準名稱及不可拆解的專有名詞原則上保留。縮寫不需要自動展開。

只有在使用者要求、不解釋會造成理解困難，或上下文明確需要第一次出現時定義，才補充中文說明。不得自行猜測不確定縮寫的完整名稱或中文譯法。

## 作業流程

1. 確認使用者要求修改的範圍與既有術語慣例。
2. 先識別並保護所有不可修改的精準字串。
3. 對其餘文本以句子與語意為單位重寫，而不是逐字翻譯。
4. 完成後檢查語意、邏輯、protected literals 與術語一致性。

若某個英文詞無法在不改變技術語意的情況下安全中文化，保留原文。

## 保真規則

修訂不得：

- 新增原文沒有的事實。
- 刪除必要條件。
- 改變否定語意。
- 改變條件成立範圍。
- 改變數值、版本或識別碼。
- 將建議改寫成已完成事項。
- 將可能性改寫成確定事實。
- 將技術名稱誤當成一般英文翻譯。
- 為了中文化而改寫程式碼或命令。

如果中文自然度與技術精確度衝突，以技術精確度為優先。

## 格式保持

除非使用者要求重新排版，應盡量保留原有 Markdown 層級、清單、表格、code block、引用區塊、連結與段落邏輯。

可以為改善中文閱讀而調整標點、空格與句子結構，但不得破壞原有資料結構。

## 驗收

輸出前確認：

- 主要內容讀起來是自然的繁體中文，而不是逐字翻譯。
- 不必要的中英混寫已減少。
- 必須保留的英文與精準字串沒有被誤改。
- 技術術語符合上下文。
- 同一概念在全文中的用語一致。
- 原文的事實、條件、否定、數值與邏輯沒有改變。
- 沒有為了追求「全中文」而產生生硬或錯誤翻譯。

## 輸出

預設直接輸出完整修訂版。

不要預設附上逐句修改紀錄、解釋或詞彙表。只有在使用者要求說明修改內容、存在可能影響技術語意的重要歧義，或有術語無法安全判定時才補充說明。

若存在必要歧義，優先保留原詞，而不是猜測翻譯。
