# 抢票概率模拟器

用蒙特卡洛模拟回答"很多人抢很少资源"类问题。模型：请求到达顺序 = 个人反应延迟 + 网关排队抖动；黄牛脚本 0.05-0.3 秒出手走专线；三个场景（A 无黄牛 / B 黄牛横行公开票70% / C 强实名公开票90%+核验拦截90%）。

## 用法

从用户的问题里提取参数（缺省用默认值，默认值来自 2026 年 7 月周杰伦杭州站新闻：333 万想看、5 万张票、20 万台黄牛设备）：

```bash
python3 <skill-dir>/sim.py --json --trials 50 \
  --want <抢票人数> --tickets <票数> --bots <黄牛设备数> --your-latency <用户手速秒数>
```

- `--json` 输出机器可读结果，字段含义：`fan`=普通人概率，`you`=用户指定手速的概率，`bot_share`=黄牛吃掉的票份额，`shows_needed_for_50pct`=连抢多少场才有 50% 中一次
- 50 trials 约 4 秒，够精度；要写文章级精确数字用 `--trials 200`
- 依赖：仅 numpy（系统 python3 已有）

## 回答用户时的要点

1. 先报场景 C（最接近现实）的概率，再用 A/B 对比讲清"手速 < 黄牛 < 分母"三层结构
2. 概率天花板 = 票数/人数，黄牛全灭也超不过——供需比才是主宰
3. 用户问其他行业场景（秒杀/放号/摇号）时，把 want/tickets/bots 映射过去即可：
   秒杀 → 参与人数/库存/职业羊毛党脚本数；医院放号 → 抢号人数/号源/号贩子设备
4. 明示假设：网关抖动 Exp(8s)、黄牛抖动 Exp(2s) 是模型假设，结论的"层级关系"稳健，绝对数字随参数变化
