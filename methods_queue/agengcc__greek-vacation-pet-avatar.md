# Greek Vacation Pet Avatar

把用户上传的一张毛孩子照片，变成可直接作为微信头像使用的希腊海边度假照。

## 输入

- 一张只包含一只毛孩子的清晰照片。
- 优先使用能看清脸型、耳朵、鼻子、毛色、花纹和毛发质感的照片。
- 如果用户没有上传照片，先请用户上传；不要凭文字猜测它的长相。

## 模型路由：生成前先执行

先检查当前产品、运行环境或图片模型的可见标识。若其中出现以下任一信号，自动使用豆包专用适配层：

- `豆包` 或 `Doubao`
- `Seedream` 或 `SeedEdit`
- 明确标注为字节跳动、火山引擎提供的豆包图片生成或编辑模型
- 用户明确说当前正在豆包中生成

命中时，读取并执行 [references/doubao-adapter.md](references/doubao-adapter.md)，不要再把 [prompt.md](prompt.md) 的完整长提示词叠加给模型。豆包适配层已经继承通用视觉标准，短指令能减少重点被稀释。

如果运行环境没有提供任何产品或模型身份，也没有豆包相关信号，则走下方默认通用流程。不要仅为了确认模型身份打断用户。

## 固定输出

- 1:1 方形写实头像，一次默认生成一张。
- 毛孩子自然坐正，只允许头部轻歪，不为展示背景扭转或倾斜身体。
- 戴琥珀玳瑁椭圆墨镜；镜片深黑且完全不透明，不能看见眼睛。
- 用符合原物种结构的两只前爪抱住红色冷饮，通过红白条纹吸管喝饮料。
- 表情松弛，嘴角有非常轻微的得意感；不要生成人类嘴唇或牙齿。
- 背景无人，以地中海为主，辅以少量希腊蓝白建筑和棕榈树。
- 背景中度虚化：能认出海、建筑和树，但看不清具体细节。
- 带 1990 年代胶片抓拍质感；不同模型允许质感强弱有差异，但不能牺牲身份和肢体正确性。

## 工作流程

以下流程用于未命中豆包路由的其他模型：

1. 先识别原图中的身份锚点：物种、脸型、耳朵、鼻口、毛色、花纹、毛长、毛发类型和体型。
2. 阅读 [references/visual-standard.md](references/visual-standard.md)，按其中的优先级构图。
3. 如果当前运行环境能读取图片资源，参考 [assets/references](assets/references) 的成品，只学习共同的画面语言，不复制某一只毛孩子的外形。
4. 使用 [prompt.md](prompt.md) 作为完整生成指令；根据上传照片替换其中的物种和毛发细节，不改变固定场景。
5. 生成前检查 [references/common-failures.md](references/common-failures.md)，避免高频错误。
6. 生成后按下方验收清单自检。若工具支持在同一轮修正，优先修正身份、墨镜、肢体和姿势；不要为加强背景而牺牲主体。

## 验收清单

- 仍然像用户上传的同一只毛孩子。
- 墨镜中绝对看不到眼睛或眼睛轮廓。
- 身体中轴接近竖直，只有头部轻微歪斜。
- 前爪符合猫或狗的真实结构，没有人类手指、多余肢体或扭曲关节。
- 吸管进入嘴部而非鼻子，嘴部没有穿模。
- 毛孩子是绝对主体；海面占背景的大部分。
- 希腊建筑、海和棕榈树能被辨认，但细节虚化。
- 画面中没有人、人影或人类倒影。
- 圆形裁切后仍能看到脸、墨镜、吸管和饮料。

## 降级处理

如果当前模型不擅长胶片质感，优先保住身份、动作、姿势、无人背景和头像构图，再尽量增加颗粒、闪光、色偏和高光晕染。不要为了追求颗粒而把脸和关键花纹做糊。

如果当前环境不能直接生成图片，返回 [prompt.md](prompt.md) 中的完整提示词，并告诉用户可将它与毛孩子原图一起提交给支持图片生成的模型。
