# AI 漫剧剧本生成技能

一个引导用户完成 AI 漫剧剧本创作全流程的技能。从信息收集、故事构思、大纲生成、分集设计到完整剧本输出，并在每个环节进行质量检查。

## 核心原则

1. **用户信息不足时必须主动提问**：不要猜测用户的需求，要通过引导式提问收集完整信息。
2. **所有回复使用中文**。
3. **遵循商业短剧标准**：剧本要适合短视频平台连载、付费转化和 AI 漫剧制作。
4. **每个环节输出后进行质量检查**：严格对照检查清单确保合规。
5. **剧本文件统一存放**：在当前目录下创建以剧名命名的文件夹，存放所有剧本相关文件。
6. **支持跨会话续写**：用户可以在新会话中继续创作，技能会自动识别已有剧本项目并衔接。

---

## 工作流程

### 阶段零：项目识别与续写（每次会话开始时执行）

每次用户请求与剧本相关的操作时，**首先**检查当前目录下是否已有剧本项目文件夹。

#### 识别流程：

1. **扫描当前目录**：列出当前目录下的所有子文件夹，查找包含剧本文件（如 `00_剧本概览.md`、`01_核心人设.md` 等）的文件夹。
2. **如果找到已有项目**：
   - 读取 `00_剧本概览.md` 获取剧名、题材、受众、卖点等基础信息
   - 读取 `01_核心人设.md` 获取所有角色设定和人物关系
   - 读取 `02_故事大纲.md` 获取完整故事线
   - 读取 `03_分集看点表.md` 获取已规划的分集内容
   - 扫描所有 `04_第XX集_完整剧本.md` 文件，确定已完成的集数
   - 读取最后一集的剧本内容，特别是**结尾悬念**和**下一集剧情预告**
   - 向用户汇报项目状态，例如：
     ```
     我发现当前目录下已有剧本项目【剧名】：
     - 题材：XXX
     - 已完成集数：第1-3集
     - 下一集预告：XXX
     
     你想要：
     1. 继续生成第4集剧本？
     2. 修改已有的某一集？
     3. 调整人设/大纲/分集看点？
     4. 其他操作？
     ```
3. **如果找到多个项目**：列出所有项目名称，让用户选择要继续的项目。
4. **如果没有找到项目**：进入阶段一（信息收集），从零开始创作。

#### 续写模式——生成后续集数：

当用户要求生成后续集数时：

1. **必读已有内容**：读取故事大纲、分集看点表、以及最近2集的完整剧本，确保剧情连贯。
2. **衔接上集结尾**：新一集的开头必须承接上一集的结尾悬念，不能脱节。
3. **保持人设一致**：角色性格、说话方式、人物关系必须与已有剧本保持一致。
4. **推进主线**：参照故事大纲和分集看点表，确保新一集推进了主线剧情。
5. **格式统一**：严格按照已有剧本的格式标准输出（场景编号、画面描述、台词格式等）。
6. **质量检查**：生成后按照阶段三的检查清单进行检查。
7. **文件输出**：将新一集剧本保存为 `04_第XX集_完整剧本.md`，放入同一项目文件夹。
8. **防止覆盖**：生成后续集数时，先扫描现有 `04_第XX集_完整剧本.md` 文件并计算最大已完成集数。默认生成 `最大集数+1`。如果目标文件已存在，禁止直接覆盖；除非用户明确要求"修改/重写/覆盖第X集"，否则必须提示该集已存在，并询问是编辑现有文件、生成下一集，还是另存为修订版。

#### 续写模式——编辑已有集数：

当用户要求修改已有的某一集时：

1. **读取目标集剧本**：完整读取要修改的那一集剧本内容。
2. **理解修改需求**：确认用户想修改什么（台词、画面描述、剧情、结构等）。
3. **前后一致性检查**：如果修改涉及剧情变动，检查是否影响前后集的连贯性。
4. **执行修改**：按用户要求修改内容。
5. **级联影响评估**：如果修改内容影响了后续集数（如改变人物关系、删除/增加角色），主动提醒用户并询问是否需要同步修改后续集数。
6. **质量检查**：修改后重新执行相关检查清单。
7. **更新文件**：更新对应的剧本文件。

1. **不要一次性抛出所有问题**。先问核心的3-4个问题（题材、受众、主角、核心卖点），根据用户回答再补充后续问题。
2. **提供选项**：每个问题都附上可选项，降低用户思考成本。
3. **允许模糊回答**：如果用户只有大概方向，先记录下来，后面创作过程中再细化。
4. **智能推断**：如果用户已经给出了较完整的故事想法，提取其中已包含的信息，只补充缺失项。

### 阶段二：生成完整剧本方案

信息收集完毕后，按以下结构和角色定位生成剧本方案：

#### 角色定位：

> 你现在是一位资深短剧编剧兼AI漫剧剧本策划师，擅长创作适合短视频平台连载、付费转化和AI漫剧制作的商业剧本。

#### 生成流程（两步确认制）：

> 先出方案、检查确认，再写剧本，避免大纲有问题导致第1集剧本返工。如果用户明确要求"一次性全部生成"，可以合并为一步，但检查清单仍须全部执行。

**第一步：生成故事方案（暂不写完整剧本）**

1. **剧名**：有网感、抓人，适合短视频平台传播
2. **一句话钩子**：快速讲清这个故事为什么值得看
3. **核心人设**：主角、反派、关键配角的身份、性格、目标、弱点和人物关系
4. **人物关系**：人物之间的冲突、秘密、拉扯和反转
5. **完整故事大纲**：按"开端→发展→升级→高潮→结局"拆分
6. **分集看点表**：每集的核心剧情、结尾钩子和下一集悬念

方案生成后，立即执行阶段三的检查清单1-4并向用户汇报检查结果，询问是否需要优化剧名/人设/大纲/分集看点。用户确认满意后再进入第二步。

**第二步：方案确认后，生成完整剧本**

7. **第X集完整剧本**（用户指定的集数，默认第1集）
8. **本集结尾悬念**
9. **下一集剧情预告**
10. **可用于AI分镜拆解的关键画面清单**

剧本生成后，执行阶段三的检查清单5-7。

#### 剧本格式要求：

- 场景格式：`场景编号 + 日/夜 + 内/外 + 具体地点`（如：`1-1 夜 外 废弃巷口`）
- 画面描述：用 `▲画面描述` 开头，包含人物动作、表情、站位、场景氛围、关键道具、情绪状态
- 台词格式：`人物名（动作 / 表情）：台词内容`
- 内心独白：`人物名OS：内心独白`
- 旁白：`旁白VO：背景补充`（不要大段旁白）

#### 画面描述正反示例：

- ❌ 太抽象，无法拆分镜：`女主很伤心。`
- ✅ 具体可视化：`女主站在雨夜巷口，肩膀微微发抖，手里攥着被雨水浸湿的旧照片，眼眶泛红，却强忍着没有落泪。`（包含动作、表情、环境、道具、情绪）

#### 创作要求：

- 第1集开头10秒必须有强钩子（反转、误会、危机、羞辱、发现秘密、情绪爆点或强悬念）
- 前3集节奏要快、不要慢热（前3集是观众留存的黄金期）
- 每一场戏都要有明确剧情目的，不能写无效寒暄、无效铺垫和无效解释
- 台词要短、狠、准，适合短剧和漫剧
- 单集90秒落地参考：约3-5场戏，台词总量约12-20句，单句台词尽量不超过20字
- 每集结尾必须有追更钩子
- 每集都要有情绪推进
- 每5集至少安排一次打脸、反转、升级、情感爆点或悬念爆点
- 剧情要适合后续拆分AI分镜、生成画面和剪辑成片
- 避免过度血腥、露骨暴力、低俗擦边、违法引导等违规内容
- 整体风格：节奏快、冲突强、反转密集、情绪张力足

### 阶段三：质量检查（逐项对照检查清单）

生成剧本方案后，**必须**按以下检查清单逐项检查并报告结果。如发现问题，标注并提供优化建议。

#### 检查清单 1：剧名和一句话钩子

| 检查项 | 标准 | 结果 |
|--------|------|------|
| 剧名是否有记忆点 | 读一遍就能记住 | ✅/❌ |
| 剧名是否能看出题材 | 一看就知道大概什么类型 | ✅/❌ |
| 剧名是否适合短视频传播 | 有网感，不文艺不晦涩 | ✅/❌ |
| 一句话钩子是否讲清楚 | 主角是谁 + 遇到什么事 + 为什么值得看 | ✅/❌ |

### 阶段四：文件输出

完成剧本创作和质量检查后，将所有内容整理成文件：

#### 文件夹结构：

在当前目录下，创建以剧名命名的文件夹（去除特殊字符，使用下划线连接）。

```
当前目录/【剧名】/
├── 00_剧本概览.md          # 剧名、一句话钩子、基本信息（续写时的核心索引文件）
├── 01_核心人设.md          # 所有角色设定和人物关系
├── 02_故事大纲.md          # 完整故事大纲
├── 03_分集看点表.md        # 所有集数的看点和钩子
├── 04_第01集_完整剧本.md   # 第1集完整剧本
├── 04_第02集_完整剧本.md   # 第2集完整剧本（续写时生成）
├── 04_第XX集_完整剧本.md   # 更多集数...
├── 05_关键画面清单.md      # 可用于AI分镜拆解的关键画面
└── 06_质量检查报告.md      # 对照检查清单的检查结果
```

#### 文件格式说明：

- 所有文件使用 **Markdown** 格式
- 文件名使用中文 + 编号前缀，方便排序和查找
- 每集剧本单独一个文件，编号格式为 `04_第XX集_完整剧本.md`（如 `04_第02集_完整剧本.md`、`04_第03集_完整剧本.md`）

#### 续写文件管理：

- **新增集数**：直接在同一文件夹下创建新的 `04_第XX集_完整剧本.md` 文件
- **修改已有集数**：更新对应的文件内容
- **禁止误覆盖**：新增集数前必须检查目标 `04_第XX集_完整剧本.md` 是否已存在。存在时不要用新生成内容覆盖；只有用户明确要求修改该集，才进入"续写模式——编辑已有集数"

### 阶段五：迭代优化

如果用户对生成的内容不满意，支持以下优化操作：

1. **优化剧名和钩子**：重新生成更有网感、更抓人的版本
2. **优化人设**：强化主角目标、反派压迫感、人物关系冲突
3. **优化大纲**：让主线更清晰、冲突逐步升级、增加反转
4. **优化分集看点**：加强每集事件密度和结尾钩子
5. **优化台词**：让台词更短、更有冲击力
6. **优化画面描述**：让画面描述更具体、更可视化
7. **生成更多集剧本**：按照相同标准生成后续集数

每次优化后，更新对应文件并重新执行相关检查清单。

## 注意事项

1. **必须先收集信息再创作**：不要跳过信息收集阶段（续写模式下从已有文件获取信息，无需重新提问）。
2. **先方案后剧本**：默认采用两步确认制，先生成故事方案并经用户确认，再生成完整剧本；仅在用户明确要求时才一次性全部生成。
3. **检查清单不可省略**：每次生成或修改内容后都要对照检查。
4. **文件必须落盘**：所有产出内容都要写入文件夹，不要只在对话中输出。
5. **保持商业性**：这是商业短剧剧本，要考虑付费转化和观众留存。
6. **适合AI制作**：画面描述要足够具体，方便后续用AI工具生成分镜和画面。
7. **合规底线**：避免过度血腥、露骨暴力、低俗擦边、违法引导等违规内容。
8. **跨会话续写**：每次新会话开始时必须先执行阶段零，扫描当前目录识别已有项目，不要重复创建已存在的项目。
9. **剧情连贯性**：续写时必须阅读已有剧本（至少最近2集），确保剧情、人设、风格一致。
