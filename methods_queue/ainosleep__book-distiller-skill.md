# 炼金书 · 书籍蒸馏术

> 一本书值钱的从来不是它说了什么，是它让你在具体处境里知道该做什么。

## 核心理念

炼金书不做读书笔记，做**可运行的方法论**。

一个好的书籍Skill是这本书的"执行引擎"：
- 书教了什么**核心方法**？（遇到X情况→做Y）
- 书给了什么**判断规则**？（怎么分辨该用哪个方法）
- 书里的**案例**证明了什么？（方法的边界在案例里）
- 这本书**在哪里失效**？（时代局限、领域边界、外部批评）
- 什么是蒸馏**做不到的**？（诚实边界）

**关键区分**：捕捉的是这本书让你 HOW to act，不是这本书 WHAT it says。摘要回答"书讲了啥"，框架Skill回答"现在我该怎么办"。

## 执行流程

### Phase 0: 入口分流

| 用户输入 | 路径 | 示例 |
|---------|------|------|
| 明确书名 | **直接路径** → Phase 0A | 「蒸馏《影响力》」「把《高产出管理》做成skill」 |
| 模糊学习需求 | **诊断路径** → Phase 0B | 「我想系统学谈判」「有没有一本书能治我的拖延」 |

### Phase 0A: 需求澄清（直接路径）

收到明确书名后，确认（**每项都有默认值，确认不阻塞交付**）：

1. **是哪本书**：书名+作者+版本（同名书、多版本书要确认；默认最新修订版）
2. **用途**：方法论顾问（默认）/ 执行清单 / 学习教练（费曼式带练）
3. **新建 or 更新**：检查 `.claude/skills/` 是否已有该书的Skill
4. **电子书语料**：「你手上有这本书的PDF/epub吗？有的话直接给我，蒸馏质量比纯网络调研高一个量级。没有也能做，走公开资料。」
5. **蒸馏档位**（开跑前必须报成本量级）：

| 档位 | 调研规模 | 适用场景 | 成本量级 |
|------|---------|---------|---------|
| 快速 | 3个维度（骨架01+方法02+批评05），每维度限5个来源。案例索引从01/02顺带提取，产物中标注「快速档：案例颗粒度粗」 | 先试效果 / 薄书 / 预算敏感 | 约标准档1/3 |
| 标准（默认） | 6个维度完整调研 | 大多数场景 | 中等 |
| 深度 | 6维度 + 用户提供全书精读 + 领域后续研究追踪 | 打算开源发布的精品Skill | 最高 |

用户只说「就蒸这本」→ 默认：最新版 + 方法论顾问 + 无电子书 + 标准档，直接推进。

### Phase 0B: 需求诊断（模糊路径）

用户不知道该蒸哪本书，只有学习需求。通过≤2轮追问定位需求维度，然后推荐2-3本候选书。

| 需求维度 | 典型表达 | 候选书方向 |
|---------|---------|-----------|
| 说服与谈判 | 「总谈不下来」「不会拒绝」 | 影响力、掌控谈话、Never Split the Difference |
| 管理与组织 | 「带团队力不从心」 | 高产出管理、联盟、重来 |
| 决策与思维 | 「总是选错」「想不清楚」 | 思考快与慢、穷查理宝典、超越智商 |
| 写作与表达 | 「写不清楚」「没人看」 | 风格的要素、金字塔原理、On Writing Well |
| 习惯与执行 | 「坚持不下来」「拖延」 | 原子习惯、深度工作 |
| 产品与创业 | 「找不到PMF」「不知道做什么」 | 精益创业、从0到1、Mom Test |

候选展示格式（**每本必须写局限**）：

```
### 候选1: 《书名》（作者）  ⚡已有Skill / 🆕需要蒸馏
**核心方法**：[这本书最可操作的一套方法，一句话]
**为什么适合你**：[直接对应用户需求]
**局限与批评**：[这本书公认的弱点/过时之处/不适用场景]
```

推荐原则：≤3本、已有Skill优先、候选间要有差异、必须写局限。用户都不满意 → 回到追问或用户自己提书名。

### Phase 0.5: 创建自包含Skill目录

**收到确认后立即执行**：

**slug命名规则**：英文书名取主标题小写连字符（`influence-framework`）；中文书优先用其通行英文名（《影响力》→`influence-framework`），无英文名则用拼音（《定位》若无英文名→`dingwei-framework`）。同名书冲突时追加作者姓（`influence-cialdini-framework`）。

```
.claude/skills/[book-slug]-framework/
├── SKILL.md                          # 最终产物
└── references/
    ├── research/                     # 每个调研任务的结果（必存）
    │   ├── 01-skeleton.md            # 本书骨架：章节结构、核心主张、概念定义
    │   ├── 02-methods.md             # 方法与工具：可操作步骤/清单/公式
    │   ├── 03-cases.md              # 案例库：书中案例及其教训
    │   ├── 04-author-context.md      # 作者语境：背景、动机、智识谱系
    │   ├── 05-criticism.md           # 外部批评：书评、反驳、过时之处
    │   └── 06-aftermath.md           # 实践检验：读者实践反馈、出版后领域新证据
    └── sources/                      # 一手素材（用户提供的电子书等）
```

**关键规则**：
- 每个调研任务必须落盘到对应md文件。**不存文件的调研等于没做**。
- 所有文件存在skill目录内部，**复制整个目录就能独立使用**——为分发设计。
- 更新模式：先读现有SKILL.md，标注哪些信息需要刷新。

### Phase 1: 多源信息采集（并行优先，串行兜底）

#### 模式判断

| 模式 | 触发条件 | 策略 |
|------|---------|------|
| **纯网络调研**（默认） | 用户没有电子书 | 6个任务全走公开资料 |
| **电子书优先** | 用户提供PDF/epub | 先精读原书（覆盖01/02/03），网络调研只补04/05/06 |
| **纯本地** | 冷门书/内部资料，网上查不到 | 只读用户素材，05/06标注「信息不足」 |

#### 6个调研任务分配

| # | 任务 | 搜索/提取目标 | 输出文件 |
|---|------|-------------|---------|
| 1 | 骨架 | 章节结构、每章核心主张、作者自创概念及定义 | `01-skeleton.md` |
| 2 | 方法 | 书中所有可操作的步骤/清单/公式/话术，逐条记录原始出处章节 | `02-methods.md` |
| 3 | 案例 | 书中案例：背景→做法→结果→作者用它证明什么 | `03-cases.md` |
| 4 | 作者 | 作者背景、写此书的动机、受谁影响、后续作品中的立场变化 | `04-author-context.md` |
| 5 | 批评 | 严肃书评、学术反驳、被指过时/夸大的部分、与同类书对比 | `05-criticism.md` |
| 6 | 后效 | 出版后领域新证据（支持/推翻书中主张）、读者长期实践反馈 | `06-aftermath.md` |

每个任务的硬性要求：
- 注明来源和可信度（原书 > 作者访谈 > 严肃书评 > 二手转述）
- 区分四类信息：「书里写的（有出处）」vs「别人总结的」vs「我推断的」vs「**模型记忆**」
- **模型记忆规则**：知名书籍在训练语料中有大量残留，执行agent会「记得」书里的案例细节。凡是没有外部来源确认、仅凭记忆写下的内容，必须标注「凭记忆，未核」，按二手可信度处理，且此标注必须一路传递到最终SKILL.md的对应条目——不许在提炼时静默洗白
- 发现书中主张与后续证据矛盾时，保留矛盾，不要和稀泥

#### ⚠️ 版权红线（贯穿全程）

- 调研文件和最终Skill里**不复制书的大段原文**。方法用自己的话重述，标注出处章节
- 直接引语：最终SKILL.md中合计不超过5句、每句不超过25字（或原文一句），每句必须带书名+章节出处
- 产物是方法论提炼，不是替代阅读的摘要。Skill里应主动写「完整论证见原书第X章」
- 不下载、不引导获取盗版电子书；电子书只接受用户自己提供

#### 信息源优先级与黑名单

优先：原书（用户提供）> 作者本人演讲/访谈/官网 > 出版社官方资料 > 严肃书评（学术期刊、主流媒体书评版、Goodreads长评）> 读者实践帖。
黑名单：**AI生成的书摘农场站、卖课号的「五分钟读完XX」、听书平台转述稿**——这些是二手失真的重灾区，任何维度都不用。

#### 失败降级表（if-then-兜底）

| 触发条件 | 一线修复 | 兜底 |
|---------|---------|------|
| 运行环境不支持并行subagent | 6个任务降级串行，做完一个落盘一个 | 单agent分6轮，每轮一个维度并立即落盘 |
| 上下文窗口不足 | 分Phase续跑：**调研文件本身就是断点**，新会话先读已落盘文件 | 分3段会话：Phase 0-1 / 1.5-2.5 / 3-4 |
| 成本失控 / 用户中途喊停 | Phase 0A档位确认就是熔断器 | 已落盘调研文件即为可交付中间产物，下次续跑不清零 |
| 冷门书公开信息极少（<10条来源） | Phase 0.5就提醒用户、请求提供电子书 | 核心方法减至2-3个，诚实边界加大篇幅 |
| 搜索工具不可用 | 换运行环境可用的等价工具 | 切纯本地模式，引导用户提供素材 |
| 书太厚/方法太多（工具书类） | 与用户确认聚焦章节范围 | 按用途裁剪：只蒸用户场景相关的方法 |
| Phase 4 无法spawn独立子agent | 主agent以「批评者视角重读」执行三项测试，并在产物诚实边界标注「验证非独立执行」 | 交付时明确告知用户未通过独立验证，建议用户新开会话自行复测 |

### Phase 1.5: 🔴 CHECKPOINT · 调研质量确认

所有任务完成后，暂停展示摘要表：每个维度的来源数、关键发现、书中主张与外部证据的矛盾点、信息不足的维度。用户确认OK → Phase 2；觉得某维度薄 → 补调研。

垃圾进垃圾出——在这里拦截比Phase 4返工便宜得多。

### Phase 2: 方法论提炼

先读取 `references/methodology.md` 获取三重验证判据。

**2.1 核心方法提取（3-7个）**：从`02-methods.md`列出全部候选（通常15-30个），逐个过三重验证：
- **可操作性**：能改写成「遇到X情况→做Y」？（感悟、金句、态度不算方法）
- **书内支撑**：作者用≥2个案例/章节支撑过？（一笔带过的不算核心）
- **排他性**：不是所有同类书都讲的常识？

三重全过 → 核心方法；过1-2重 → 降级为判断规则；0重 → 丢弃。宁少勿多。

**2.2 判断规则提取（5-10条）**：书中「什么时候用哪个方法/什么信号说明方法失效」的规则，每条挂书中案例。

**2.3 案例索引**：每个核心方法挂1-2个书中案例（一句话背景+结论+原书章节号），供Skill运行时引用。

**2.4 适用边界**（来自05/06）：这本书在什么条件下失效——时代局限、文化语境、被后续研究修正的主张、批评者指出的盲区。**批评材料不足=调研不合格**。

**2.5 诚实边界**：蒸馏不能替代读原书；案例细节有损；书的语境≠用户的语境；调研截止日期。

### Phase 2.5: 🔴 CHECKPOINT · 提炼确认

展示提炼摘要（核心方法N个+判断规则N条+适用边界N条），用户确认后再构建——避免写完几百行才发现方向不对。

### Phase 3: Skill构建

读取 `references/template.md`，将Phase 2结果填入。要点：

- **产物description**：<300字，正向触发（书名+作者+书中专属概念词）+ 负向触发两条：①「不在用户只要书摘或泛泛建议时触发」②「**用户未提及本书或书中专属概念、只是一般性[领域]问题时不触发**」——后者防止与同领域其他Skill抢触发
- **Agentic Protocol**：产物Skill遇到涉及具体现实对象（某公司/产品/人）的问题时，先搜索获取事实，再用书中框架分析——研究维度从本书核心方法反推（如《影响力》→查该场景里的互惠/稀缺/社会认同证据），不是通用「搜索相关信息」。**必须含失败分支**：分析对象是用户自己的东西（自家产品/内部决策）搜不到时，转为向用户索要材料清单；用户给不了 → 标注假设后按纯框架分析
- **证据强度必填**：每个核心方法必须有「证据强度」行（强/中/弱+依据），不允许只给部分方法标注——选择性诚实比不诚实更误导
- **终检**：交付前全文搜索 `[` 占位符，全部替换或明确留待用户填写；核对description中的数字声明（N个方法等）与正文实际数量一致
- **⚠️ `$数字` 禁用**：SKILL.md正文不得出现「$紧跟数字」写法（如 `$0.30`）——部分runtime的skill加载器会把 `$0`/`$1` 当参数占位符插值污染正文。金额写「0.30美元」或「USD 0.30」
- **防摘要化**：产物回答问题时输出的是「用书的框架分析你的处境」，不是「书里怎么说」

### Phase 4: 独立验证

先跑结构自检脚本（确定性检查，不耗token）：`python [skill目录]/scripts/quality_check.py <产物SKILL.md路径>`——逐项输出PASS/FAIL，全过后再进入主观验证。

**主观验证用独立子agent执行**（生成者不自评）：

1. **书内一致测试**：选3个书中明确回答过的问题，用新Skill回答，对比原书立场
2. **边缘诚实测试**：选1个书没讨论过但相关的问题，期望「基于书中方法X的推断，但书未直接讨论」而非斩钉截铁
3. **去摘要化测试**：给一个具体处境，检查回答是框架运行还是原文拼贴/泛泛书摘

通过标准：

| 检查项 | 通过 | 不通过信号 |
|--------|------|-----------|
| 核心方法数量 | 3-7个，每个有章节出处 | <3或>10 |
| 每个方法的失效条件 | 明确写出 | 只写优点 |
| 适用边界 | ≥3条，含外部批评 | 只有「不能替代读书」 |
| 直接引语 | 每句有出处，总量克制 | 大段无出处引用 |
| 回答风格 | 框架运行 | 书摘复读 / 通用鸡汤 |

迭代上限2轮，超限则在诚实边界标注薄弱项后交付。**宁可交付诚实标注局限的60分Skill，也不造看似完美实则编造的90分Skill。**

### Phase 4.5: 真实调用测试（Live Test）

离线验证（脚本+子agent读文件）测不到skill被loader真实加载后的行为——插值污染、触发命中、实搜分支都只有真实运行才暴露。Phase 4通过后执行：

1. **加载确认**：产物出现在当前runtime的可用skill列表。不支持会话内热加载的runtime → 引导用户新开会话执行本Phase
2. **插值污染检查**：带参数真实触发一次，通读被加载的正文，检查是否被污染。重点：`$数字`写法、残留模板占位符（实测教训：`$0.30`会被loader当参数占位符替换成用户输入）
3. **实搜分支实跑**：问一个需要Agentic Protocol Step 2的时效性问题（涉及具体现实对象），验证：①搜索真的执行了而不是凭内置数据回答；②实时信息与skill内置数据不一致 → 更新内置数据并标注日期
4. **触发边界抽查**：用一个命中负向触发的相邻问题（如未提本书的一般性领域问题）确认不误命中

任一项失败 → 修复后只重测该项。runtime无法执行真实调用 → 在诚实边界标注「未经真实调用测试」，把以上4项转为用户自测清单随产物交付。

🔴 CHECKPOINT · 展示离线+真实调用两级验证结果，用户确认后交付。

## 更新已有书籍Skill

「更新XX的skill」→ 只重跑任务5（新批评）+ 任务6（领域新证据），对比现有内容增量更新，刷新调研日期。不重写全书。

## 反模式黑名单（绝不做）

| # | 反模式 | 为什么 / 替代做法 |
|---|--------|------------------|
| 1 | 大段复制原文 | 版权问题+根本不是提炼。方法自己重述+标注章节 |
| 2 | 把摘要冒充框架 | 摘要回答「书讲了啥」，框架回答「我该怎么办」。产物必须是后者 |
| 3 | 把常识包装成本书独特方法 | 通不过排他性验证的不进核心方法 |
| 4 | 忽略对书的批评 | 任务5的批评材料是防「书粉滤镜」的关键，占比不足=调研不合格 |
| 5 | 把过时方法当普适真理 | 任务6专门查出版后新证据；被推翻的主张必须标注 |
| 6 | 编造书里没有的案例/数据 | 查不到出处的内容宁可不用 |
| 7 | 不报成本量级直接开跑 | 完整蒸馏是重任务，用户有权先选档位 |
| 8 | 引导用户获取盗版电子书 | 电子书只接受用户自己提供，来源不过问但绝不代找 |
| 9 | 把检查点变成交付阻塞 | 能给默认值就给默认值，检查点是纠偏不是扣产出 |

## 特殊场景

- **经典老书**（出版>20年）：任务6权重加倍，逐个方法标注「仍成立/已修正/已过时」
- **多本书合蒸**（「把这3本谈判书蒸成一个skill」）：先提取每本核心方法，再做「共识方法+各家分歧」两层结构，类似主题Skill
- **虚构类书籍**：小说不蒸「人生道理」（过不了可操作性验证）；只接受明确目标如「蒸馏这本小说的叙事技法」，按写作方法书处理
- **教材/工具书**：全蒸会爆炸，Phase 0A必须确认聚焦章节或用途裁剪
- **用户只有纸质书**：引导用户拍照/摘录关键章节，按部分语料模式处理，诚实边界标注覆盖不全
