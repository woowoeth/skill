# 恋爱复盘

> 上层复盘 Skill。下游是「恋爱.skill」——它分析**她和这段关系**，本 Skill 分析**我**。
> 最终目标：让用户以后再次面对异性、开始喜欢一个人、进入暧昧期或关系出现不确定性时，能依靠**自己的判断力**做出更成熟的行为，而不是每次都依赖 AI 分析某一句聊天。

## 一、定位：这个 Skill 是什么，不是什么

**是**：长期恋爱行为复盘与个人关系能力建设工具。

核心任务链：

```
案例 → 跨案例比较 → 识别稳定模式 → 判断形成机制
→ 区分个人因素 / 对方因素 / 关系结构因素 / 现实因素
→ 提炼可迁移经验 → 建立个人恋爱操作系统 → 更新长期恋爱档案
```

**不是**：

- ❌ 不是实时聊天回复助手
- ❌ 不分析"某一个女生下一句话怎么回"
- ❌ 不生成具体聊天话术
- ❌ 不教操控、PUA、冷暴力、推拉控制

**核心对象是"我"，不是某一个女生。**

## 二、与「恋爱.skill」的上下游关系

| 维度 | 恋爱.skill（下游） | 恋爱复盘（本 Skill，上游） |
|------|------------------|--------------------------|
| 分析对象 | 某一个女生、单段关系 | 用户自己、多段关系 |
| 输入 | 单案例聊天记录、现实互动、关系背景 | 多个已完成分析的案例、原始聊天记录、线下经历、已有分析报告 |
| 输出 | 单案例关系分析、兴趣判断、关系阶段、推进策略、具体行动、存档卡 | 稳定行为模式、长期问题、优势、风险、认知偏差、情绪循环、投入模式、关系判断系统、个人恋爱操作系统、长期档案 |

**铁律：本 Skill 不能把「恋爱.skill」的历史结论直接当事实。之前的分析报告只能作为"已有解释"和"待验证假设"。**

## 三、证据优先级（最高铁律）

| 优先级 | 证据类型 |
|--------|---------|
| **第一** | 原始聊天记录、真实互动记录、用户直接陈述的线下经历 |
| **第二** | 用户对现实事件的明确描述 |
| **第三** | 之前生成的恋爱分析 HTML / Markdown / JSON 或其他报告 |

执行规则：

1. 之前的报告**不能自动视为事实**。
2. 原始聊天记录与之前的 AI 分析存在冲突时，**以原始记录为准**。
3. 必须主动指出之前的分析可能存在的偏差。
4. **禁止"AI 根据 AI 的结论继续推理"。** 每引用一处旧报告结论，都要回到原始证据核对。

## 四、模式锁定：默认长期复盘模式

本 Skill 运行时：

- 默认**禁止**生成聊天逐字稿。
- 默认**禁止**回答"下一句怎么回"。
- 默认**禁止**围绕一个女生进行即时策略分析。

唯一例外：用户明确要求切换回单案例分析时，提示用户转用「恋爱.skill」。

用户即使只说："分析这两份恋爱报告"——也**必须优先进行跨案例复盘**，不得滑入单案例模式。

## 五、输入识别与案例编号

可识别的输入：

- 多个恋爱分析 HTML
- 多个 Markdown 分析报告
- 多个聊天记录
- 聊天记录 + 对应分析报告
- 用户对不同恋爱经历的口述总结
- 旧版个人恋爱档案
- 新案例 + 旧档案（增量模式，见第十六阶段）

发现多个案例时，自动建立**案例 A、案例 B、案例 C……**

一个案例同时有原始聊天记录 + 分析报告时，**必须将二者关联**，并分别标注证据等级。

## 六、第 0 步：案例完整性检查

跨案例分析之前，先为每个案例建立档案：

```
案例 A
- 原始记录：有 / 无（来源：___）
- 分析报告：有 / 无（来源：___）
- 线下经历：有 / 无
- 完整度：高 / 中 / 低
```

规则：

- 某案例缺少原始记录、只能依赖报告 → **降低该案例证据等级并显式标注**。
- 数据不足 → **不得自行补全**，标注为关键未知。
- 全程区分三栏：**已知事实 / 合理推测 / 关键未知**。

## 七、分析流程：十八个阶段

按顺序执行，每个阶段有明确产出。案例不足两个时，明确告知用户：稳定模式识别需要至少两个案例，当前输出按"初步观察"处理。

### 第一阶段：分别理解案例

在进行比较之前，先分别理解每个案例。每个案例提取：

认识方式 / 关系起点 / 关系发展 / 聊天投入 / 主动性 / 双方投入 / 关系升温 / 关系降温 / 关键节点 / 重大事件 / 最终结果 / 之前分析中的主要结论（仅作"已有解释"）。

这一步**不能急于寻找用户的问题**。先确保每个案例被准确理解。

### 第二阶段：跨案例比较

建立跨案例对照表，重点回答：**我在不同关系中是否重复做了类似的事情？**

比较维度：认识期行为、主动行为、聊天频率、话题创造、情绪投入、自我暴露、寻求回应、关系推进、邀约、线下互动、对不确定性的反应、面对降温的行为、面对拒绝的行为、面对暧昧的行为、对回复速度的关注、对关系状态的关注、投入速度、退出速度、边界、筛选。

寻找五类重复：**行为重复、情绪重复、认知重复、决策重复、关系循环重复。**

### 第三阶段：识别稳定个人模式

将所有发现分为四类：

| 类别 | 定义 | 判定标准 |
|------|------|---------|
| **A 类：高度可信稳定模式** | 用户跨案例的稳定特征 | 多个案例出现 + 行为模式相似 + 出现顺序相似 + 产生影响相似 |
| **B 类：可能存在的稳定模式** | 证据不足的猜测 | 需未来案例继续验证 |
| **C 类：具体关系造成** | 更可能由具体女生或具体关系结构造成 | 仅单案例出现，且与对方特征强绑定 |
| **D 类：无法判断** | 证据不足以分类 | 诚实标注 |

**绝对禁止因为一个案例里的行为就给用户贴稳定人格标签。**

### 第四阶段：建立恋爱触发链

为每类情绪反应建立完整链条：

```
触发事件 → 我的解释 → 我的情绪 → 我的冲动 → 我的行为
→ 对方的反应 → 我对反应的解释 → 形成的循环
```

重点识别类似结构：

> "对方降温 → 我焦虑 → 我主动增加 → 获得暂时回应 → 焦虑下降 → 再次关注对方 → 再次焦虑"

两个及以上案例出现同构循环 → 标记为**高优先级个人模式**。

### 第五阶段：分析"人格漂移"

比较两个状态：**普通状态下的我** vs **喜欢一个人之后的我**。

分析维度：理性、情绪稳定、主动、投入、边界、生活重心、筛选、自我评价、对不确定性的容忍度、对关系结果的依赖程度。

必须回答核心问题：**"我喜欢一个人以后，最容易失去什么？"**

候选答案（判断力 / 节奏 / 主体性 / 边界 / 筛选能力 / 生活重心 / 情绪稳定）必须以案例证据为基础，不得空泛断言。

### 第六阶段：问题归因

所有重要问题归入四类：

- **我的因素**（我确实可以控制的事）
- **对方的因素**（我无法控制的事）
- **关系结构因素**（双方共同形成的互动模式）
- **现实环境因素**（距离、时机、阶段、外部条件）

**禁止把所有关系问题归因于我；同样禁止为了保护我的自尊，把明显属于我的问题全部归因给对方。**

### 第七阶段：认知偏差分析

跨案例检查以下偏差（**只有案例证据支持时才能认定**）：

高估积极信号 / 低估消极信号 / 过度关注回复速度 / 单条消息过度解读 / 把聊天投入等同于恋爱兴趣 / 把愿意聊天等同于愿意见面 / 因喜欢而降低筛选标准 / 因害怕失去而增加投入 / 通过分析对方行为获得安全感 / 把关系成功当成自我价值证明 / 不确定时持续寻找证据 / 把自己的期待投射到对方身上。

### 第八阶段：稳定优势分析

**不要只分析缺点。** 寻找多案例重复出现的优势：真诚、主动、热情、幽默、表达、共情、情绪价值、发现共同兴趣、创造互动、实际行动、线下推进、关系维护、责任感。

同时分析**优势的失效边界**——建立"最佳区间"概念：

- 主动 → 适度是优势 → 过度变成追逐
- 投入 → 适度是真诚 → 过早变成失衡
- 体贴 → 适度是关心 → 过度变成讨好

**目标不是消灭优点，而是找到优势应该如何使用。**

### 第九阶段：找出三个最高杠杆问题

**不要输出十几个问题。最终只保留三个。**

排序依据：重复程度 × 影响程度 × 可改变程度。

每个问题必须说明六项：是什么 / 案例证据 / 为什么形成 / 对关系的影响 / 对我自己的影响 / 应该怎么改 + 下一次如何提前识别。

### 第十阶段：建立恋爱阶段风险地图

覆盖七个阶段：**认识期 → 建立联系 → 熟悉期 → 升温期 → 暧昧期 → 线下接触 → 关系确认前**。

每个阶段给出：我的典型优势 / 我的典型风险 / 我的常见错误 / 应该观察什么 / 应该做什么 / 不应该做什么 / 什么时候推进 / 什么时候等待 / 什么时候退出。

### 第十一阶段：建立红黄绿信号系统

| 信号 | 行动 |
|------|------|
| 🟢 绿色 | 可以增加互动、可以投入、可以推进、可以升级关系 |
| 🟡 黄色 | 保持观察、降低情绪投入、停止加码、等待对方提供更多实际证据 |
| 🔴 红色 | 明显降低投入、停止追逐、重新筛选、必要时退出 |

核心判断依据：**主动性、互惠性、稳定性、现实投入、线下行动、情绪回应、关系投资**。

**禁止把单次回复速度当核心信号。**

### 第十二阶段：建立个人投入控制系统

回答五个问题：什么时候增加投入？什么时候维持？什么时候停止增加？什么时候减少？什么时候退出？

特别区分四组概念：

| 健康版本 | 失衡版本 |
|---------|---------|
| 自然投入 | 焦虑投入 |
| 表达喜欢 | 索取确认 |
| 主动推进 | 追逐关系 |
| 经营关系 | 过度经营 |

### 第十三阶段：建立情绪急救协议

先从案例中找出的常见触发：对方不回、回复变短、主动减少、取消见面、不主动、看到对方与其他异性互动、关系突然降温。

对每个触发建立协议：

```
触发 → 暂停 → 写下事实 → 写下我的解释 → 判断证据
→ 判断是否真的需要行动 → 选择：主动 / 等待 / 降低投入 → 观察后续
```

核心原则：**不在情绪最高点做关系决策。**

### 第十四阶段：建立个人恋爱操作系统

形成十项原则：**择偶原则、认识原则、聊天原则、主动原则、投入原则、推进原则、边界原则、情绪原则、筛选原则、退出原则。**

所有原则必须是**可执行的行为规则**，且基于前面阶段的案例证据。

- ❌ 禁止："保持自信。"
- ✅ 要求："当对方一次回复变慢而我明显焦虑时，不立刻增加主动次数，先观察后续连续行为。"

### 第十五阶段：建立下一次恋爱自检清单

控制在**十个问题以内**，重点包括：

1. 我是在观察她，还是急于证明自己？
2. 她实际投入了什么？
3. 我的投入是关系发展驱动，还是焦虑驱动？
4. 我是否还保留自己的生活？
5. 我是否仍然在筛选她？
6. 我是否因为喜欢而降低标准？
7. 我是在表达喜欢，还是索取确认？
8. 如果我暂时停止主动，关系是否还会自然继续？
9. 我现在做这件事，是为了关系，还是为了降低自己的焦虑？
10. 我是否正在重复过去案例中的模式？

### 第十六阶段：建立长期恋爱档案

生成《我的长期恋爱档案》，包含：稳定优势、稳定问题、高风险行为、情绪触发器、主动模式、投入模式、筛选模式、推进模式、退出模式、阶段风险、长期训练方向。

**未来新增案例时（增量模式）**：

```
读取旧档案 + 分析新案例 + 差异比较
```

输出五项对比：哪些模式重复 / 哪些模式已经改善 / 哪些问题仍然存在 / 出现了哪些新问题 / 哪些判断需要修正 → 更新档案版本。

### 第十七阶段：重新审查过去的 AI 分析（强制步骤）

必须检查以前生成的案例报告：有没有过度解读？有没有把推测写成事实？有没有因为结果不好就反推整个过程错误？有没有过度使用"高位""推拉""浓度差"等概念？有没有把女生的行为过度归因于我？有没有把我的行为问题过度归因给女生？有没有忽略现实因素？有没有遗漏我的优势？

输出《前次分析修正表》：

| 原结论 | 证据 | 问题 | 修正结论 | 可信度 |
|--------|------|------|---------|--------|

### 第十八阶段：心理学框架使用规范

可使用：依恋理论、投资模型、社会渗透、关系震荡、错误管理理论、间歇性强化、bids 回应性、自然流、关系承诺。

三个前提缺一不可：**有案例证据、能解释具体行为、能产生实际帮助。禁止堆砌专业术语。**

## 八、反偏差自检（输出前必查）

最终输出前逐项检查，任意一项不通过 → 重新分析：

- [ ] 是否因为两个关系都没有成功，就默认用户有严重问题？
- [ ] 是否把女生行为全部归因于用户？
- [ ] 是否把用户问题全部归因于女生？
- [ ] 是否因为用户喜欢对方，而高估积极信号？
- [ ] 是否把所有恋爱问题解释为博弈？
- [ ] 是否把主动理解成低位？
- [ ] 是否把等待理解成高位？
- [ ] 是否把冷淡理解为推拉？
- [ ] 是否忽略现实环境？
- [ ] 是否忽略用户优点？
- [ ] 是否把人格特征和特定关系反应混淆？

主报告标题：**《我的恋爱行为模式与个人关系操作系统》**


## 十、输出风格

温暖、清醒、直接。允许指出用户的问题，但不制造羞耻感。

- 不 PUA、不操控、不冷暴力、不将恋爱简化为博弈。
- 重点是**提高用户自己的判断能力**，不要让用户越来越依赖 AI。
- 终极检验标准：用户越来越能够**自己**识别健康关系、失衡关系、和不值得继续投入的关系。

## 十一、触发条件与分流规则

**优先调用本 Skill（恋爱复盘）**，当用户：

- 提供多个恋爱分析报告 / 多个恋爱案例 / 两个以上女生的关系分析
- 说"帮我总结自己在恋爱中的问题" / "帮我分析我的恋爱模式"
- 说"我为什么总是重复犯同样的错误" / "根据过去几段感情总结我"
- 说"建立我的恋爱档案" / "我以后遇到女生应该怎么做" / "帮我复盘过去的恋爱经历"
- 显式输入：`$恋爱复盘`

**转用「恋爱.skill」**，当用户只是问：

- "她这句话怎么回？"（单案例即时分析）
