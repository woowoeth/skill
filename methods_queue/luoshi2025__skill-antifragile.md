# 反脆弱博弈

## 这个skill干什么

一句话：把一个方案变成一个更好的方案。

三步走：
1. A出方案（正方，说好的）
2. B找缝隙（反方，找错的、找弱的、找缺的）
3. 上帝之手融合（取各自的优点，剔除各自的错误，输出一条完整的好方案）

最终产出 = 一条项链 = 经过锤炼的好方案。

## 两种场景

**场景一：AI自拆**
用户说"这个方案反脆弱一下"——AI自己分裂成A和B对拆，然后上帝之手融合。
判断依据：用户给了一个方案让你分析。

**场景二：用户是A**
用户自己出了方案，说"反驳我"、"帮我找漏洞"——用户本人就是A，AI只当B找缝隙，然后上帝之手融合用户的原方案和AI的反驳。
判断依据：用户说了"反驳我"、"你来拆"、"帮我找问题"这类话。

两种场景走同一个三步流程，区别只在A是谁。

## 你必须做的事

1. 先判断是哪种场景
2. 走完三步，不能跳步
3. B必须锋利，不能客气
4. 上帝之手必须独立判断——A说的不一定全对，B的反驳也不一定全对
5. 最后必须输出一个融合后的好方案
6. 全中文

## 你不做的事

1. 不代替用户拍板——你输出方案，用户决定做不做
2. 不在没有具体方案的情况下空转
3. 不只拆不建——光找缝隙不给最终方案等于耍流氓

## 执行

### 第一步：确认输入，判断场景

用户给你一个方案、一个想法、一个决策。

如果用户说"反驳我"、"你来拆"、"帮我找问题"→ 场景二，用户是A，跳过第二步直接进第三步。
如果用户说"反脆弱一下"、"博弈一下"、"这个靠谱吗"→ 场景一，AI演A和B。

如果用户只说"博弈一下"没给内容，问一句："博弈什么？把方案给我。"

输入大（比如整个商业模式）就先拆成几个点分别博弈。输入小就直接博弈。

### 第二步：A大脑（仅场景一需要，场景二跳过此步）

站在方案的支持者角度，给出3条核心论据：

```
══ A大脑 ══

1. {这个方案好在哪——一句话}
   证据：{为什么这么说——事实或逻辑}

2. {第二个优点}
   证据：{支撑}

3. {第三个优点}
   证据：{支撑}
```

### 第三步：B大脑

场景一：逐条拆A大脑的论据。
场景二：逐条拆用户原方案中的论点。

铁律：
- 不说"整体不错"、"有道理"——这是糖衣，删掉
- 能拆就拆，拆不动就说"这条站得住"，一句话结束
- 每条打分1-10，1=纸糊的，10=铁打的

```
══ B大脑 ══

对第1条：{X}/10
  缝隙：{问题在哪}
  反驳：{为什么站不住——必须有事实或逻辑支撑}

对第2条：{X}/10
  缝隙：{问题在哪}
  反驳：{为什么站不住}

对第3条：{X}/10
  缝隙：{问题在哪}
  反驳：{为什么站不住}

A没看到的盲区：
  {有就写，没有就写"无"}
```

### 第四步：上帝之手

跳出A和B，做独立裁判。A说的不一定全对，B的反驳也不一定全对。上帝之手自己判断。

```
══ 上帝之手 ══

【A说对了的】（保留）
- {哪条}：{为什么对}

【B拆对了的】（采纳反驳）
- {哪条}：{为什么A确实站不住}

【A说错了但B也没拆对的】（双方都有问题）
- {哪条}：{真实情况是什么}

【B反驳过头了的】（A其实没问题，B找茬了）
- {哪条}：{为什么A原本是对的}
- 判断标准：B的反驳如果没有事实或逻辑支撑，只是为反对而反对，就是过头了

══ 最终方案（项链）══

{融合以上判断，输出一个完整的、经过锤炼的好方案}
{长度跟方案复杂度匹配——简单方案几句话，复杂方案写完整段落}
```

## 默认行为

- A固定出3条，不多不少（场景二中，如果用户的原方案论点不足3条，按实际数量拆）
- B必须逐条拆，不能笼统说"都有问题"
- 上帝之手必须四个象限都过一遍
- 最终方案是一段完整的话，不是打分表
- 场景判断不确定时，默认按场景一（AI自拆）执行
