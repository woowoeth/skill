# 火柴人动画

把一篇口播稿制作成白纸手绘风火柴人解释动画。默认竖屏 1080×1920、30 fps；以用户当前上传的主体图为母版，未上传时才使用默认小黑人。

## 先确定工作边界

1. 读取用户给出的文案、参考视频、当前上传的主体图和现有工程。
2. 按以下优先级锁定主体母版：当前请求明确指定或上传的图片 > 当前项目内经用户确认的主体母版 > 默认小黑人。不得从其他项目、旧任务或历史上传中沿用角色图片。
3. 接受人物、动物、物体、卡通形象或真人照片作为主体。保留其稳定识别特征；真人照片默认转成白纸手绘表达，不声明逐像素还原。
4. 若有参考视频，先逐帧确认真实运动规律；不要仅凭成片观感猜动画方法。
5. 若用户要求复刻某种效果，先做第一幕 4–5 秒测绘样片并验证，再扩展全片。用户明确要求自主完成时，可在本地通过样片门后继续。
6. 使用现有视频创作工具完成渲染；使用 HyperFrames 时先遵守对应核心、动画与命令行 Skill。
7. 不把 API key、token 或密码写入工程、日志、Skill 或报告。MiniMax 凭证只从环境变量或 macOS Keychain 读取。

## 执行六段流程

严格按以下顺序执行。每一步都必须留下可检查的产物；不要把“已经写好提示词”当成视频进展。

### 一、分段

- 按单一视觉命题切分口播稿，而不是机械按句号切分。
- 每幕只保留一个主要动作、一个主要构图和一句核心字幕。
- 先生成逐幕脚本、预计配音时长和场景表。
- 读取 [references/workflow.md](references/workflow.md) 的分段约束和交付物定义。

### 二、写提示词

- 为每幕写完整画面提示词，同时写语义图层清单与揭示方向。
- 明确统一主体母版、纸张色、线条、点缀色、镜头、留白和禁止项。
- 提示词必须为测绘服务：一个视觉元素对应一个可分离语义层。

### 三、画图

- 先锁定当前任务的主体母版，再生成所有场景；不可每幕重新发明主体，也不可沿用其他项目角色。
- 每幕生成干净的最终完成态静帧，背景色保持一致。
- 检查肢体数量、角色比例、道具、文本伪影和画幅。
- 画面是待拆解的终态，不是直接拿来做淡入淡出的幻灯片。

### 四、配音

- 默认使用 MiniMax `Chinese (Mandarin)_Gentleman`；除非用户指定其他声线。
- 按幕生成语音和逐字时间戳，再以真实语音时长反推画面时长。
- 默认在每幕语音后留约 0.45–0.65 秒视觉尾巴，场间重叠约 0.30–0.40 秒。
- 可调用 `scripts/minimax_tts.py`；先阅读 [references/workflow.md](references/workflow.md) 的音频请求格式。

### 五、测绘

- 把完成态图片拆成透明语义墨层：人物、环境、路线、道具、证据等。
- 为每层记录紧边界、揭示方向、开始百分比、结束百分比与顺序。
- 验证所有墨像素被覆盖，且透明层重建完成态时没有差异。
- 每层第一可见帧必须是零面积遮罩；可见面积只能单调增加。
- 禁止“完整图先出现 → 被遮掉/变白 → 重新刷出”。
- 完整实现与数据契约见 [references/measurement-and-motion.md](references/measurement-and-motion.md)。
- 运行 `scripts/validate_measurements.py <measurements目录>` 和 `scripts/validate_reveal_html.py <分镜HTML目录>`。

### 六、拼片

- 画面揭示跟随语义与口播节奏，不要让所有层同时匀速出现。
- 转场只控制幕与幕之间的纸张/容器；语义层的初始遮罩必须在转场前已生效。
- 字幕来自逐字时间戳，保持底部安全区，避免盖住主动作。
- 只在最后一幕做全片淡出；前面各幕不要自行淡黑。
- 先完成工程检查，再渲染最终 MP4。

## 强制验收门

在声称完成前，依次通过：

1. **资产门**：所有语义墨像素被某一图层覆盖；图层合成与完成态一致。
2. **首帧门**：第一幕和每个切点的前 1.1 秒按 0.1 秒连续检查；新幕只能从纸张或零面积图层开始。
3. **运行时门**：检查真实时间线，不用单独打开的静态 HTML 代替。
4. **交付门**：从最终 MP4 再抽一次九幕连续帧；完整解码、音频、黑帧和规格均通过。
5. **对齐声明**：只有逐像素比较通过时才写 pixel aligned；否则写 style/motion behavior aligned。

使用 `scripts/extract_boundary_sheets.py` 从最终 MP4 生成逐幕连续帧。详细检查表见 [references/qc.md](references/qc.md)。

## 失败即停止扩展

出现以下任一情况时，不要继续铺满全片：

- 第一帧能看到完整终态。
- 图层可见面积先减少再增加。
- 角色跨幕明显变形或换人。
- 配音时间仍是估算值而非实际音频时长。
- 只有中段抽帧，没有场景切入连续帧。
- 最终 MP4 与检查过的工程不是同一份产物。

先修复第一幕样片并重新过门，再批量重建其他幕。
