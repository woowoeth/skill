# 品味 · 产品定义

> 这份文档回答四个问题：解决谁的什么痛点、为什么是我们、产品怎么表达、人为什么会再来。
> 写于 2026-08-19 立项。所有判断都可以被推翻，但要给出理由。

---

## 一、痛点：不是"找不到"，是"不敢装"

Agent Skill 生态已有 **266 万条**，平均质量 6.2/12。检索早就不是瓶颈了。

用户真正卡住的地方不是"有没有"，是这三句心里话：

1. **"我装了会不会白花半小时"** —— 装一个 skill 的成本不是磁盘，是注意力和信任。踩一次坑，下次就不装了。
2. **"这玩意儿跟我上周装的那个有什么区别"** —— 同类第 N 个 code review、第 N 个 planning，用户分不出来，也没义务分。
3. **"我想找的那种东西，搜不出来"** —— 尤其是中文用户。

目录站解决第一层（有没有），**没有任何人解决第二层（值不值）**。
skills.sh、SkillsMP 这类以收录量为模式的站，结构上不可能解决——它们的 KPI 是收得多，判断是负担。

**所以品味的产品定义只有一句：我们卖判断，不卖索引。**

---

## 二、为什么是我们：一块结构性空白

所有大市场都是英文爬虫、英文搜索。**中文创作者的东西在那边基本不存在。**

这不是猜测，是数据：上一轮宽漏斗扫约 6000 条，机器粗筛出 164 件，**其中 159 件是中文**——
而这 159 件在原来那 20 组 GitHub 英文关键词里，一件都不会出现。

捞上来的东西长这样：

- 用密码学随机数起卦的周易占卜——绝不编造卦象、一事一占、凶卦如实直断、事后可对账
- 按京房纳甲体系走完整装卦流程的六爻，而不是丢一句吉凶
- 按 GB/T 9704 写党政公文——引了具体国标号，作者真在这行里
- 把照片蒸馏成 zine 海报——不调任何生图模型，纯手写 HTML/CSS/SVG 绘制
- 北京 16 区花粉过敏预报——窄得理直气壮，但对那批人是刚需
- 把长期健身做成 RPG——用剧情推进解决"坚持"这个真问题

**这些在英文市场里一件都不会出现。** 这就是"用户在别处拿不到"的具体形式。

> ### ⚠️ 这一节的证据正在被重测，暂不可当结论引用
>
> 支撑这一节的两个数都**不能证明它**：
>
> - 「扫 6000 条、164 件里 159 件是中文」——**那一轮的词表本来就全是中文词**，捞到中文是必然的。
> - 「中文候选只有 0.3% 被 skills.sh 收录、非中文 78%」——**那 78% 的样本本来就取自 skills.sh 的 sitemap**，
>   100% 命中是构造出来的，不是发现出来的。
>
> 干净口径（只统计 GitHub 搜索独立发现的）：**含中文 0.28% · 不含中文 0.16%，没有差距。**
> 这份数据能证明的只是「skills.sh 漏掉了 GitHub 长尾的 99.7%」，**证明不了「它专门漏掉中文」**。
>
> **两件事对定位的含义完全不同**：
> 漏掉中文 → 护城河是**语言和文化**，英文爬虫结构上补不上，我们有时间；
> 漏掉整条长尾 → 护城河只是**他们暂时没爬到这一层**，任何人加一轮爬虫就能补上。
>
> 正在跑 30 条**同概念英文垂直词**的对照组（tarot / feng shui / acupuncture / civil service exam /
> beekeeping …），同一条漏斗、同一个指标。英文垂直的收录率若也是 0.2%，这一节要改。
>
> **在对照组出结果之前，这一节是假设不是结论。**（内容 2026-08-19 自查发现）


### 护城河在哪，以及它有多厚（诚实版）

不在收录量——那我们永远打不过。
在**判断**，而判断的载体是三样东西：

| | 能不能被抄 |
|---|---|
| 中文覆盖 | 能，但要重建一整套中文漏斗，且他们没动机 |
| 垂直深度（命理/公文/中医/过敏这类） | 能，但要有人真懂这些行当才写得出点评 |
| **公开的拒收记录** | **不能**——公开拒收等于自伤收录量，与他们的模式冲突 |

**要说实话：如果 skills.sh 明天加上"已验证/已实测"标签，我们的差异化立刻缩水。**
那时候剩下的只有中文覆盖和垂直深度。所以紧迫性在于：趁他们还没做判断，把判断这件事做扎实。

如果他们把判断做好了——用户赢了，这个产品就该死掉，不该硬撑。
我们存在的理由是这块没人做好，不是我们有权占着。

## 三、产品怎么表达

### 核心形态判断：不是货架，是专栏

**单位不是卡片，是判断。**

现在的网站是 154 件平铺的信息流，每张卡长得一模一样。人扫到第 10 张就停了——
因为没有节奏，没有主角，没有"下一个"的欲望。

有品味的东西一定有节奏：有大有小、有长有短、有主角有配角。
参照物应该是**好的独立杂志和买手店专栏**，不是 SaaS 落地页。

### 四条设计硬判断

**1. 杀掉星数。**
我们自己的标准明写着"星数是滞后且有偏的指标，会亏待新发布、垂直、非英语、无营销的好项目"，
然后又把 `★ 0` 印在每张卡的首屏上——这是自我否定。星数可以留在详情里当参考，不能当门面。

**2. 杀掉重复封面。**
上架 154 件里 **125 件没有真封面（81%）**，显示的是"把标题又写一遍"的渐变色块。
一个讲品味的站，八成图位是占位符，这件事本身就说明标准没落到实处。

两条路，都比现在强：
- **放真东西**——skill 的**产出物**截图（海报、像素图、公文、图表）。那才是品味的证据，比任何文案都有说服力。
- **彻底不放图**——纯用排版做区分。**品味是删出来的，不是加出来的。**

最差的选择是留着假图。

**3. 每条点评必须有"但是"。**
现在的点评只夸不贬。但用户的痛点是"不敢装"，
**诚实的局限比夸奖更能建立信任**——你告诉我它哪儿不行，我才信你说它哪儿行。

固定格式：`它妙在哪` + `但是（机制短板 / 平台限制 / 适用边界）`。

**4. 建立层级。**
头条 1 件（大幅 + 三百字的长判断）+ 精选 6 件 + 名录若干。
154 件全部平铺 = 没有推荐。有主角才有节奏。

### 新增内容位：拒收榜

公开"**今天扫了 6000 条，收了 3 件，拒了这些，每条一句为什么**"。

这是这个产品里我最想推的东西，四个理由：

1. 它把 `docs/CURATION.md` 的标准变成了内容，**零额外生产成本**
2. 拒收比推荐更好看、更有信息量、更有传播性——人爱看毒舌，但毒舌必须公允
3. 说"我们只收 3%"和**展示被拒的那 97%**，是完全两回事。这是筛子为真的**唯一证据**
4. 竞品结构上做不了——公开拒收与"收录量即价值"的模式直接冲突

配套：**标准的版本记录也要公开。** `editorial/feedback.json` 已经在跑一个机制——
同一类问题出现第二次，就改标准而不是只改那一件。把这个改动史摊开，
人看得见筛子在变严，才会信这不是随口挑的。

## 四、人为什么会再来（留存）

**先承认一个残酷事实：精选列表天然是一次性的。** 看一眼、收藏三个、再也不来。
这是这类产品最常见的死法，不解决它，前面三节都白写。

### 认清楚：不该指望人主动回访网站

转录里已经踩过这个坑——自制的 `find-reusable` 死在"**想不起来用**"这个死穴上。
一个要人主动记得去访问的东西，几乎必死。

所以留存要靠两条腿，**分工明确、KPI 不同**：

| | 给谁用 | 干什么 | 怎么衡量 |
|---|---|---|---|
| **网站** | 人 | 橱窗。建立信任和品牌，让人读到判断、认同这个店的口味 | 看过的人信不信（读完率、拒收榜的分享） |
| **skill 入口** | agent | 被反复调用。用户干活时**自动触发**，不需要他想起来 | 被调用多少次 |

**skill 入口是留存的真正答案**——因为它绕开了"想不起来"这个死穴。
你在写 PPT 的时候，agent 自己去查"品味里有没有做这个的"，这才是可持续的复用。

网站负责让人第一次相信我们，skill 负责让这份信任被反复兑现。

### 网站这一侧，三个机制

1. **节奏**——每次来都有新头条。不硬承诺"每日"，承诺了做不到反而伤信任。
2. **积累**——标准在变严，而且这件事看得见（公开的标准改动史）。
3. **身份**——店主要有脾气、敢说"这个我不收"。买手店的复购从来不是靠货全，是靠认同口味。

## 五、我知道的风险

不写出来就是骗自己。

1. **平台自带能力。** Claude 已经有记忆和历史检索，我们可能在做平台白送的东西。
   差别在于我们给的是**结构化的判断**（妙在哪 / 但是），不是被动回忆。这个差别够不够，没把握。
2. **人工判断不可规模化。** 机器只能筛掉明显没品味的，**挑不出有品味的**——那 11 件是人一条条读描述挑的。
   这既是护城河也是天花板：判断层没法自动化，规模上不去。
3. **一旦要人手动整理就会死。** 所以捕获必须自动、判断才是人工。这条边界不能模糊。
4. **竞品做判断。** 见第二节。这是最大的单一风险，且我们控制不了。
5. **署名与许可证欠账。** 已存 126 份方法正文，无一带原作者署名和许可证声明——
   对 MIT 项目这违反许可条件。现阶段刻意搁置（需求未验证前不做合规装修），
   但**上线放量前必须补**，否则是明知故犯。

**已知缺口**：81% 无真封面；154 件全部缺"局限"字段；无头条位；无拒收数据。
