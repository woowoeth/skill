# 过堂 · 把阅读队列按店主的标准挨个读一遍

`docs/TASTE.md` 是标准，这份是**怎么用它把队列清掉**。

## 为什么要人（或 agent）读，不能让打分器代劳

2026-09-03 的回测（`scouts/taste_backtest.py`，`taste-backtest.yml`）：拿店主标心的 73 件当正样本、
08-28 判为「有用但通用」的 150 件当难负样本，让判官打 0–100 分 ——

    留出正样本 18 件 均分 67.1
    留出负样本 18 件 均分 66.5
    最佳分数线 ≥50：正样本过 100% · 负样本过 89%   → +11pt

**判官分不出「店主要的」和「有用但通用」。** 它能挡烂货（对问一/问二拒收的 40 件是 +61pt），
挡不住平庸。所以自动上架关了（`TASTE_MIN=101`），≥50 分的进 `editorial/reading_queue.json` 等人读。
截至 2026-09-06 队列里 **1,971 件，0 件被读过**。流扫每天从 GitHub 最新的 SKILL.md 里再往里灌。

店主 2026-09-06 的话：「至于品味这种东西，我觉得还是要有好的内容源才行」「要么就把最新的 GitHub 挨个看一遍；
按照目前的数据集已形成自己的评判标准」。这份就是把第二句做成流程。

## 流程

1. **取货**：队列里判官 ≥70 分的先读（≥80 的 86 件、70–79 的 605 件）。50–69 的等这一批读完看命中率再定。
2. **抓正文**：每件把上游 SKILL.md 存到 `methods_queue/<owner>__<repo>.md`（队列的键是 `owner/repo`，还没有货架 id；上架后正文才搬到 `methods/<id>.md`）。**没有正文的不判**（判的是它本身，不是 README 的营销段）。队列的 `path` 是 skill 所在目录，正文在 `<path>/SKILL.md`；为空就试仓库根。
3. **分片读**：每个 agent 领 30–40 件，按下面的《读一件的规矩》逐件写判决，落 `editorial/fresh_pass/<日期>/batch_NN.json`。
4. **汇总**：`收` 的进候选单；主编（当班的 agent）复核每一件 `收` 的证据句，再决定上架。
5. **上架**：走正常管线（文案 + 封面 + `covers_publish`），先发后审。
6. **清账**：读过的一律从队列移走 —— 收的进 `editor_picks.json`，不收的进 `rejected.json`（带一句为什么，拒收榜是公开的）。
7. **记数**：这一批的命中率（收 / 读）写进 `docs/DECISIONS-*.md`。命中率是「内容源好不好」唯一可量的数。

## 读一件的规矩（给 agent 的原话）

> 你在替一家中文 Agent Skill 精选店读货。店主认可什么样的货，见 `docs/TASTE.md`，先整份读完。
> 现在读 `methods/<id>.md`（上游 SKILL.md 正文），**不看星数、不看 README 营销段、不看判官给的分**。
>
> 逐件输出 JSON：
> ```
> {"id": "...",
>  "三问": {"是商品": true/false, "别处拿不到": true/false, "写得出文案": true/false, "why": "≤40 字"},
>  "信号": {"拦住自己": 0-2, "真干过": 0-2, "一条硬约束": 0-2, "产物是东西": 0-2, "腔调/怪/冷门": 0-2, "中文现场": 0-2},
>  "证据": ["原文引用一句（对应给了 2 分的每个信号，引不出来就不能给 2）", "..."],
>  "反信号": ["第N个通用件" | "同作者套路堆" | "框架内部装修" | "单装做不了完整事" | "二维码/广告" | "官方目录"] 或 [],
>  "判决": "收" | "不收" | "待读",
>  "钩子": "店主口吻一句，参照 hearts 的 why_zh；写不出来就不能判收",
>  "为什么": "≤60 字，写给拒收榜看的"}
> ```
>
> 收的条件：三问全 true，信号总分 ≥5，前三个信号里至少一个是 2，反信号为空，钩子写得出来。
> **拿不准就「待读」，不要为了凑数判收。** 一批 35 件里收 0–3 件是正常的；收 10 件说明你把标准放低了。
> 同一作者多件：只把最有独立媒介身份的那一件判收，其余写「同作者套路堆」。

## 这一批之后

- 如果 ≥80 分那一档的命中率明显高于 70–79 档，说明判官的分数**在高分区有序**，可以只读高分区。
- 如果两档差不多，说明判官的分在这个区间没有信息，队列该按别的东西排（作者、来源、题材）。
- 命中的货来自哪些源（`source` / 作者 / 题材），回写 `docs/SOURCES.md` 的「T1 必盯」。**好的内容源是从命中里长出来的，不是想出来的。**
