# 产品裁决 · 2026-09-06 · 封面与品味整治

累计裁决记录，接 `docs/DECISIONS-2026-08-19.md`。**标准正文在 `docs/COVERS.md` 和 `docs/CURATION.md`，这里只记「为什么这么定」和踩过的坑。**

店主原话（开工令）：「品位这个网站好好搞一下，目标是做有品位的 skills 推荐。1. 很多 skill 没什么品味 2. 最低要求每个 skill 要带图，不管用什么方式 3. 很多 skill 图都不合适没把这个 skill 能力表现出来，居然还有带二维码的 4. 很多图片会失掉打不开链接成了死图」。后面又补：「别问我，你自己挨个解决掉」。

开工时的数字：在架 319 件，**162 件没图（51%）**，157 张有图的**没有一张被人打开看过**，6 张外链，47 件精选。

---

## D30 · 「每件都要有图」从「注意」升为「坏」

`shelf_health.py` 原来把没图记成「注意」，理由是「一条永远红着的红灯会被人学会忽略」。结果它黄了两个月，货架上一半的卡没有脸。

**裁决：** 红灯被忽略的解法不是把它调成黄灯，是把红的原因清掉。没图=坏，外链=坏，没有 w800 派生图=坏，封面没有过目判 ok=坏。四条都用故意注入的坏数据验过会拦。

## D31 · 图合不合格，只能看图判，不能算像素

第一版写了个分类器：边缘密度、底色占比、小连通块数量。跑出来把干净的线稿（`geeklee` 白板、塔罗牌、小人 IP）判成「几乎空白」，把几十张满屏文字的截图**一张没抓到**。

**裁决：** 作废。判据是语义的 —— 「遮住标题，这张图说的是不是这个技能干的事」—— 一张精美的埃菲尔铁塔照片像素上完美，放在写代码的技能上就是废图（店主补的第五条：「很多图跟技能本身也没什么关系」）。四个判官逐张打开图、对着文案判：ok 73 / replace 79 / remove 5。判决落在 `editorial/curation.json` 的 `cover_verdict`，有人看过才算。

## D32 · 二维码 / 广告封面 → 整件下架，不是换图

下架的 5 件：两张收款/拉群二维码、两张「GPT 代充/成品号」横幅（伪装成 OpenAI 推文）、一张自家营销 banner。

**裁决：** 图在告诉你这个技能是什么。一个作者拿代充广告当封面，这件东西本身就不该在架上。
其中一件是店主 8/28 钉住的精选 —— 按底线下架，但在 `picks_pinned.json` 留痕写明原因，店主可以一句话加回来。

## D33 · 取不到作者的图，就自己做 —— 但图上一个字都没有

162 件没图的，全在两三天前跑过 `repo_covers`（含翻文件树），**一张都没取到**。作者仓里就没有图。剩下的路只有自己做。

第一版样张把 `title_zh` 排成大字、`tagline` 排成小字放进图里。店主一眼看穿：「你生成的这些图也不好，明显和下面的标题描述重复了」—— 卡片底下本来就印着这两句。而且它违反 COVERS.md 自己那句「字只能当标签不能当解释」。

**裁决：** 作废重做。**图上一个字都没有**，按它干的事配一个能力图形（视频剪成帧、书拆成块、照片变贴纸、字幕落到时间轴…29 个），判官按中文意思逐件分派；拿不准用 `make`（中性），因为**一个错的图形比中性图形更糟，它在误导**（龙猫护理配一只碗、ComfyUI 配一头雪豹，都是这个病）。三条硬规则照 `assets/ours/op7418-guizang-social-card-skill.png`：不要圆角、不要阴影、不要渐变。`cover_kind: specimen`，图注写明「站方样张，不是产出物截图」，不算真图、进不了精选。

两次试过的分派法：正则按 `desc_en` 里的英文碎词匹配 —— "app" 落成 phone、"search" 落成 research，作废；改成只看中文标题一句话、判不出就 `make`，正式分派走判官（`--motifs`）。

## D34 · 死图的真根子不是外链，是派生图的生成顺序

6 张外链全部落到本地，容易。真正的死图是：`make_thumbs.py` 按 `skills/feed.json` 里在用的封面出 w800 派生图 —— 而它跑在 `refresh()` **之前**，派生图按旧 feed 出的，新 feed 指向的 155 张封面在 `w800/` 里根本没有。线上每张卡先请求 `w800/*.webp` 撞 404，再 `onerror` 回退 800KB 原图：首屏一排灰框、几百个 404。店主看到的「图打不开」多半是这个。

**裁决：** 收口只做两步、只按这个顺序：`refresh()` → `make_thumbs`，封装成 `scouts/covers_publish.py`。任何改了 cover 的脚本跑完都接这一步。健康检查加一条：feed 引用的每张封面必须有 w800 派生图。

## D35 · 「品味」按三问重读，下架 27 件；店主的信号高于判据

81 件门禁分 ≤7 或没分的货，按 CURATION.md 三问逐件重读：下架 27 件，全部落在问一（12：框架/索引/管段/攻击赋能）和问二（15：官方目录、第 N 个通用工具、同作者套路堆）；**问三 0 件** —— 凡是「写不出文案」的都有更硬的实因，没让问三当伞。

5 件被判掉的是店主亲手标过心的（`hearts.json`）。**裁决：** 恢复上架。hearts.json 第三条写得很清楚：判据把这批判掉了，是判据错，不是它们错。复审理由留作 `cull_note`，让店主看得见为什么曾被判掉。

## D36 · 详情页也要说清这张图是什么

详情页（`i/<id>/`）此前没有图注，而且没图时回落 GitHub 预览卡。加 `.shotcap`，按 `cover_kind` 印「作者仓库里的产出示例」/「我们自己装上真跑了一遍」/「作者自制的头图，不是产出示例」/「站方样张，不是产出物截图」。详情页是决策发生的地方，不能含糊。

## D37 · 闸红在第一件新货上：宽限 48 小时，CI 自己配样张但不替人签字

D30 那四条闸推上去的当晚，进货工作流第一次跑就红了：一件当轮新到的货有真图、没派生图、没人判。两处发现：

- **CI 从来没装过 Pillow。** `make_thumbs.py || true` 两个月来每轮都是 `ModuleNotFoundError` 被 `|| true` 吞掉 —— 新货的 w800 派生图一张没出过。D34 的 404 在本地是顺序错，在线上是这个。工作流现在装 pillow + playwright，走 `covers_publish.py`。
- **进货是自动的，看图是人做的，两者不同步。** 让新货一到就红，等于每天红一次，D30 说过红灯常红会被学会忽略。按 2026-09-02 的「先发后审」：新到货 48 小时内没判记「糙」，过了才「坏」；已判 `replace`/`remove` 却还挂着的不享受宽限。

取不到作者图的新货，CI 当轮用 `make_specimens.py --ci` 配一张中性样张 —— 图形按中文标题正则猜、猜不出用 `make`。**但它的 `cover_verdict` 留空**：机器不能替人签「看过」，巡货的 agent 逐件看图后再写 ok 或换图形。

## D38 · 把六个信号写进判官提示词：回测没拉开，不换

TASTE.md 写完后第一反应是塞进判官提示词（`TASTE_RUBRIC=1`）。按 `taste_backtest.py` 的信条先测再用，
同一天派了两轮（正样本 = 心选 73 + 指名，难负样本 = 08-28「有用但通用」150 件，各留出 18）：

| | 原提示词 | 带六个信号 |
|---|---|---|
| 留出正 / 负样本均分 | 64.0 / 61.6 | 64.7 / 63.3 |
| 最佳分数线 | ≥50：正过 94% · 负过 72% → **+22pt** | ≥60：正过 83% · 负过 72% → **+11pt** |
| 成对比较（对 3 个心选锚点的赢率） | 0.49 / 0.52 | 0.51 / 0.49 |

**裁决：** 不换。rubric 让分数抖动变小（跨度 27 → 10），但没让「店主要的」和「有用但通用」分开 ——
成对比较两头都是抛硬币。机器判官继续只做它证明过能做的事：挡问一/问二的烂货（+61pt）。
分「好」和「平庸」这一步，由人（或读全文的 agent）按 TASTE.md 做，见 `docs/TASTE-PASS.md`。
开关留着，默认关；以后有新想法先派 `taste-backtest.yml -f rubric=1`，没到 +25pt 不动生产提示词。

顺带一条：同一提示词 09-03 测是 +11pt、今天是 +22pt，留出 18 件的抽样抖动就有这么大。**单轮回测的差距小于 10pt 不算差距。**

## 给下一个 agent 的三句话

1. **判图只能看图。** 像素统计、文件名、字段，都替代不了把图打开。
2. **一个错的图形比没有图形更糟。** 拿不准就用中性的，别猜。
3. **改了封面就跑 `covers_publish.py`。** 顺序是产品的一部分。
