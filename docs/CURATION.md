# 选品与文案标准 / Curation Standard

信条：**质大于量。宁可 60 件件件想装，不要 300 件划过去都不看。**
上架是例外不是默认；可留可不留的，一律不留。

---

## 一、什么算"好玩好用"

一件 skill 要上架，必须能通过**三问**。三问都过才收，否则不收。

### 问一：它是不是拿走就能用的商品？
不是商品的一律拒，星再高也拒：
- 框架/底座（给开发者搭系统用，不是装进 agent 就能用）
- 教程/幻灯片/handbook/cheatsheet
- boilerplate、项目脚手架
- **别人项目自己的装修配置**（bump-version、update-playbooks、内部运维件）
- skill 市场/管理器/聚合站（除非确有独到之处）

判据：clone 下来能不能直接用起来。

### 问二：它给的东西，用户在别处拿不到吗？
**这条是店的命门。** 万星大路货在任何目录站、任何一篇"50 个必装"里都查得到 ——
我们收它，用户得不到任何增量。所以：

**拒收**
- 官方厂商目录（Anthropic / OpenAI / Google / Vercel / HuggingFace 的官方合集）—— 用户自己会去官网
- 通用开发工具（第 N 个 code review、第 N 个 planning、第 N 个 commit 规范）
- 大而全的数量堆（几十上百件打包，没有一件拎得出来的招牌）
- 已有更好同类在架、且没有"它独有"的理由

**优先收**
- **中文精品**：花叔、歸藏、卡兹克、宝玉、乔木、王树义这类中文创作者的东西 —— 国外目录站不会收，中文用户找不到
- **点子够怪**：让 Claude 像原始人说话、把小说做成游戏、让 skill 吞噬别的 skill、手写变字体
- **冷门但对的人极有用**：倪海厦中医、数学建模竞赛、里程玩家、Obsidian 命令行、跑团 DM
- **单一明确风格**：一种视觉腔调做到底（zine 海报、小黑怪诞配图），而不是"设计工具箱"

### 问三：能不能写出让人想装的文案？
**这是准入测试，不是收尾工作。**
如果我只能憋出"一个不错的 X 工具"，说明它没有值得说的点 —— 那它不配上架。
写不出来就别收，别指望日后补。

#### 问三·补：标题必须先说「你拿到手的是什么」，禁令排后面

**2026-08-21 店主标了 73 件当参考标准，数据把这条钉死了**（在架 255 件，整体心选率 29%）：

| 标题形状 | 心选率 |
|---|---|
| **说出产出物**（做成/生成/画/算/写成/一份 X） | **43%**（75 件） |
| 两者都无 | 28%（135 件） |
| **只有禁令、没说产出物**（不许/绝不/拒绝 X） | **9%**（54 件） |

分批控制之后这条更狠：8-20/21 那批里「只有禁令」的 **38 件只被标中 2 件（5%）**。

**这个坏结果是我们自己造出来的。** 任务书里那句
「好标题里都有一个**不该出现在这里的东西** —— 一个具体到你会愣一下的细节或**禁令**」
被当成了唯一判据，于是两级都歪了：**选货偏向「有硬禁令的」而不是「能产出东西的」，
标题又把禁令摆在最显眼处，产出物被挤出去。**

所以规则改成：

1. **标题的主语是产出物**，禁令最多作修饰。
   - ❌「不许说『有什么可以帮你』，先反问三轮的咖啡顾问」
   - ✅「先反问三轮再给冲煮参数的咖啡顾问」
   - ❌「凑不满三道菜也不放宽过敏原的『有啥吃啥』」
   - ✅「照冰箱剩货给三道菜，凑不满也不放宽过敏原」
2. **禁令降级到点评和局限里** —— 那里它是证据，标题里它是路障。
   「不许 X」回答的是「它不干什么」，而读者要的是「我能拿到什么」。
3. **写标题前先答一句**：装了它，你拿到手的是什么？
   答不出一个具体的东西（一张图、一份清单、一段脚本、一个算清的数）——**那这件根本不该收**。

> 这条不是要放弃「具体」。「愣一下的细节」仍然是好标题的标志，
> **但它得长在产出物上**：「植被多就换品红键色，把照片做成能剪下来的贴纸页」——
> 品红键色是那个细节，贴纸页是产出物，两个都在。

#### 一条同时被这批数据推翻和确认的
**star 仍然不是信号。** 整体看「star≥50 心选率 39% / star=0 是 20%」，像是反了我们的判据；
**分批控制之后完全平掉**：8-19 那批里 star=0 是 **50%**、star≥50 是 45%；新批三档全在 8–10%。
整体那个差是**批次混淆**（老批质量高、又恰好偏热门仓库）。
**差点因为一个未控制的相关性推翻自己一整天的判据 —— 报相关性之前先问「有没有第三个变量」。**

### 红线（无条件拒，与星数、作者、授权声明无关）
- 攻击赋能类安全工具：渗透攻击面、C2、横向移动、漏洞利用、红队方法论、OSINT 侦察自动化
  （防御向/审计向/加固向可以收）
- 恶意代码、绕反爬、批量盗号等灰产
- 金融荐股/交易信号预测
- 价值观有害的（PUA 等）

## 二、三个字段怎么写

卡片只有三行，各司其职，**不许重复**：

| 字段 | 回答的问题 | 写法 | 长度 |
|---|---|---|---|
| **标题** | **这是什么？** | 一句话说清它干什么。**不是外号**——"女娲造 skill"是外号，"把任何人的思维方式蒸馏成一个能装的 skill"才是标题 | 中文 12–24 字 |
| **简介** | **我为什么要装？** | 说痛点、场景、反差、以及别处没有的那个具体细节。不复述功能列表 | 中文 44–58 字，占满两行 |
| **点评** | **它到底好在哪？** | 店长视角的判断：机制上的差异点、诚实的局限、平台限制。可以有态度 | 中文 30–52 字 |

**反面例子**（我自己犯过的）
- 标题写成外号：「技能饕餮」「小黑怪诞配图」→ 用户不知道那是啥
- 简介复述功能：「支持 A、B、C 三种模式」→ 没回答"我为什么要装"
- 点评说空话：「实用利器」「效率神器」→ 等于没说

## 三、货从哪来

按信噪比排序。**第一条最高质量，最后一条最不可靠。**

| 渠道 | 说明 | 现状 |
|---|---|---|
| **人工指路** | 真人看到好东西直接给链接。一个人觉得值得推荐，胜过任何自动指标 | `--suggest owner/repo`，绕过所有门槛直进人工评审 |
| **作者雷达** | 店里每上架一个作者，持续盯他之后发的新仓库。好作者会持续产出 | 已自动化，近 60 天新作直进候选 |
| **社交流情报** | X / 公众号 / 小红书是新品首发地，但**机器读不了**（robots 拒）。这块只能靠人 | 依赖人工指路 |
| **平台画廊情报** | 如 YouMind Skills 画廊（公开可访问）。**只当情报源，不当货源** —— 那些 skill 是平台内资产，没有可 clone 的仓库，部分是付费商品 | 用于看品类空白、顺作者回查 GitHub |
| **GitHub 搜索** | 20 组常驻查询，覆盖生态主干 / 新品快车道 / Codex 生态 / 研究型 / 单一视觉风格 | 已自动化，信噪比最低，产出多为数量堆和装修配置 |

**已知盲区（诚实记录）**
- 社交流首发的东西，搜索索引更新前看不见 —— 这是人工指路不可替代的原因
- 全新作者的第一件作品，雷达看不见（没有历史）、搜索排不上（没有星）

## 四、准入门槛（机器初筛用，人工可推翻）

星数是滞后且有偏的指标，会亏待新发布、垂直、非英语、无营销的好项目。所以不设单一门槛，四条通道任一命中即进候选：

- **新品快车道**：创建 ≤7 天 且 ≥3 星
- **星速度**：创建 ≤14 天 且 ≥25 星
- **认真程度信号**：≥10 星 且 满足「有主页/演示、描述≥60字、近30天有维护」中两项
- **老仓兜底**：≥40 星

fork、命名黑名单（awesome/dotfiles/template/guide/tutorial…）始终拒。

**放宽准入是刻意的取舍：漏掉的好货无法追回，进来的杂质人工删得掉。**

### 加分项，不是门槛

「作者做到哪一步」的那几样东西 —— 拆出 `references/`、附 `scripts/`、带 `assets/`、
明写边界、明写适用条件、**自带 evals** —— 一律是**加分项**，任何一条都不许写成准入条件。

理由是实测出来的，不是推想的：拿 `methods/` 里已存档的正文本地统计（`python3 scouts/prep_signals.py`
随时可复算，分母是当时有存档的件数，会随存档补齐而变），六条里最常见的「参考文件」命中约六成半，
而 **`evals/` 只有 2 件，约 1%** —— 生态里几乎没有人给 skill 写评测。
把 1% 命中率的东西写进门槛，等于一刀砍掉 99% 的货，包括我们自己最看重的那批中文垂直货。

**定量的门槛必须先量生态命中率再定。** 一条照着理想写、没照现实校准过的标准，
和星数一样会亏待正确的东西 —— 只是错得更隐蔽，因为它听起来很专业。

对应的正向表达是首页的「备料齐」徽章（`prep_badge`，≥3 条证据），
它**只有正向档**：备料少不显示任何东西。一个只有一段提示词的极简 skill 可能恰恰是好东西。

## 五、抓取与文案必须同时做

**不许"先抓一批、以后再补文案"。** 那样货架上会长期堆着机器占位文案，用户看到的就是一坨没人管的东西 —— 这是本店犯过的最大错误。

流程：
1. 候选进来 → 立刻过三问
2. 过了 → **当场写标题/简介/点评**（写不出来就是没过问三，退回不收）
3. 写好了才入库；入库即可见

自动进货（GitHub Actions）只负责往**候选池**里放东西，**不直接上架**。

## 六、反馈闭环

店主标记「没吸引力」的商品收在 `editorial/feedback.json`：
- `flagged` —— 待处理，记 id + 店主原话
- `resolved` —— 已处理，写清改了什么
- `patterns` —— **从个案里提炼的共性问题**，每条都要反过来改标准

已提炼的五类问题见该文件。**规则是：同一类问题出现第二次，就说明标准没写清，要改标准而不是只改那一件。**

非 skill 但有价值的东西（数据集/模型/素材库）记进 `docs/MATERIALS.md`，**不上货架**。

## 七、兜底

所有下架都是 `hide: true`，记录保留、随时可翻回；所有文案在 editorial 层，可改可撤。
机器只负责「抓来、够格、不霸架」；**"有没有品"这关永远是人在把。**

## 红线补：拆了还工作吗（机制 / 选项）

2026-08-21，合集全扫上线后第一批命中里出了两件在架货，逼出这条。

`borski/travel-hacking-toolkit`（48 件，已下架）：满仓 Patchright，作者自己在 docstring 里写
「undetected Playwright」，`vrbo/scripts/entrypoint.sh` 开 Xvfb 虚拟显示器，注释写明
「Akamai detects headless」。**把 Patchright 拆掉，这一包一件都不工作。**

`artokun/comfyui-mcp`（店主 ❤️ 过，留架 + 披露）：模型表里一行 `Qwen/abliterated/…`
标「Abliterated (uncensored)」，同表另有两个普通写实模型；`ltxv2-video` 的 abliterated
LoRA 带 ⭐，但作者写的功能是「prompt-accuracy / correct-eyes fix」。
**把那行拆掉，这一包照样工作。**

所以红线问一句：**拆了它，这件货还工作吗？**
- 不工作 → 它是**机制**，红线，下架。
- 照样工作 → 它是**选项**，留架，但在 `limit_zh` 里说清楚，让人装之前知道。

配套两条，缺一条这判据就会变成想判谁判谁的借口：

1. **「作者自己写下的功能描述优先于我们的推测」必须双向生效。** 它把 borski 判死
   （作者写了 undetected），就必须同样接受 comfyui 的作者写了 correct-eyes。
   只在一个方向上用，它就不是判据。
2. **判据判掉了 `editorial/hearts.json` 里的货，先怀疑判据。** 这次「破限」按字面会把
   菜单上的一行判成零件——是判据分不清机制和选项，不是那件货错。
   （hearts.json 第三条本来就写了这件事会发生。）

追加披露时**追加，不要覆盖**——我第一次改 comfyui 就把原来那句
「没有 ComfyUI，这一整包一件都用不上」冲掉了，而那句比新加的重要。
