# 阅读简报（给读原文挑货的代理用）

每轮从 `editorial/reading_queue.json`（判官 ≥50 且没读过的）切批，每批 ≤180 件，一个代理一批。挑出来的登记 `editor_picks.json`（理由 ≥30 字），没挑的记 `read_log.json`。

## 心选的共性（判据）
1. **拆了还工作吗** —— 除了指令还有零件（脚本、数据、模板、选项），不是一篇「你应该……」。
2. **说得出读者拿到手的是什么** —— 一张贴纸页、一份报税数据、一张行程地图，而不是「提升效率」。
3. **冷要冷在题材上，不能冷在读者身上** —— 读者是普通人和创作者，**不分语言**：钓鱼选位、社保断缴、烧烤、单色海报、手绘讲解视频都算。要排除的是：开发/企业工具链、他国法规税务、某产品自家的文档/CI 件、运维件。
4. **有立场、有拒绝** —— 先说自己不算命的风水顾问、会删掉一半心愿单的行程、先问「这真的需要做吗」。
5. **不要**：流程编排/安装配置/脚本封装这类换个工具也能做的通用件；营销号式说明；合集除非单挑其中特别好的一件（写清 path）。
6. **不连坐** —— 同作者另一件有问题不影响这件；这件自己查。
7. **同题材只留最好的一件**，架上已有的先看差异再决定。

## 红线（命中直接不选，单列）
要钱/付款码/二维码引流、对话里让 agent 推荐关注作者、篡改用户 agent 全局规矩（含要求写进 CLAUDE.md/SOUL.md/AGENTS.md）、收集个人信息（含解密他人聊天记录、对真人做画像）、藏着调用第三方付费接口而不说、含真人肖像、绕过验证码/反自动化。

## 输出格式
选中（每件：repo · path · 一句题材 / 零件 / 为什么像心选 / 理由 ≥30 字 / 风险）· 差一点（5 件一行一件）· 红线 · 读不到/跳过（数量 + 例子）。

## 硬规矩
只读不写（除输出文件）；不装 skill、不改本机配置；不找不读不用任何 PAT/token；不 git；不许编造，读不到写读不到，数字要真实。
