# 品味标准 · 从店主标过心的 73 件里读出来的

`docs/CURATION.md` 的三问是**门**：不是商品、别处拿得到、写不出文案，一律不进。
这份是门里面的事：**过了三问的货，什么样的才是我们要的。** 它不是拍脑袋写的 —— 2026-09-06 把店主亲手标心的 73 件
（`editorial/hearts.json`）和当天按三问下架的 27 件摆在一起读出来的。判官（人或模型）判新货时，按这份判，
以那 73 件为范例、27 件为反例。

先说一个数字：73 件里 **22 件不到 50 星，7 件是 0 星**；中位数 211 星。**星数不是信号。** 判官不许看星数下结论。

---

## 一句话

我们收的是**有人真干过、肯给自己设限、一条硬规矩决定品质**的单件。

## 六个信号（每件至少要有两个，且其中一个是前三条之一）

### 1. 肯拦住自己 —— 边界写成硬规则
好的 skill 花很多字说自己**不做什么**。这不是免责声明，是作者知道这件事的坑在哪。
- 风水顾问先说自己不算命；起名器没有出生时刻绝不伪造命盘
- Seedance 导演只产文字、不调用生成、不花积分
- 考纲复习「没材料就不辅导」；增肌教练「没有触发行就说本周无需调整，不为了显得有用而改方案」
- 健身件把胸痛、晕厥写成硬停止条件
- 装修老师傅不推荐任何品牌，也不替你决定交不交定金

**在 SKILL.md 里找什么：** 「绝不」「不做」「禁止」「FAIL FAST」「反模式」「安全边界」这样的段落，而且内容具体到这个领域，不是通用的安全套话。

### 2. 是真干过的人写的 —— 文字里有伤疤
一手经验藏不住：写的是「数字藏在哪」「哪两个端点已经 404 别调」「绿场景会撞色所以改用品红打底」。
- 富途月结单报税：专列常见坑，「对着真账单啃过一遍才写得出」
- 稀有鸟：20 个端点逐个实测，写明哪两个死了
- 离线旅行页：「离线可读、手机优先、单文件」——真在国外用过才想得到的三个约束
- 八步调研：作者高校教师出身，是带学生真用的那套
- 装修报价单：带一节「内在张力」，明写自己也纠结的三处

**找什么：** 具体到不可能编出来的细节、自己踩过的坑、承认自己拿不准的地方。通用套话（「高效」「专业」「一站式」）是反证。

### 3. 一条硬约束决定了品质
最好的货往往能用一条自我约束解释它为什么出品稳定。
- 极简海报「全程代码绘制、零生成模型」—— 所有效果可控，不抽卡
- 三盘星历「引擎算天空，模型只负责读」
- 社保计算「每个政策数字都走确定性 CLI，从不在对话里口算」
- 换装视频「先定首帧再派生」；剪辑「100% 本地，不出本机」
- 增肌教练「一次只动一根杠杆」；豆包 PPT 先逼你答「这页要人记住哪一句」

**找什么：** 一句能引用的规矩，去掉它整件就塌。

### 4. 产物是个东西，能进工作流
不是聊完就散，是落下一个可用、可改、可接着用的文件。
- 白板示意图：产物是**可编辑源文件**而不是截图
- 整本书并行翻译：几十分钟压完，**排版不散**
- 任务拆解写到磁盘，/clear 后自动续上
- 日记年轮看板、离线旅行单页、可投递的简历

### 5. 一种腔调做到底，或点子够怪，或冷门但对的人极有用
- 单一风格：手绘解释图（不给一堆选项）、朋克视觉库、蒸馏海报
- 够怪：原始人腔说话省 token、苏格拉底式陪练打断含糊用词、替你删掉一半心愿单的行程图
- 冷门但准：赶海拾遗、花粉 53 城、跑团 DM、数学建模三天赛程、考研英语逐句、被辞退取证

**反面：** 「设计工具箱」「写作全能助手」「效率提升套件」—— 什么都做的，一件也不在这 73 里。店主 2026-09-07 的定位原话：**一件一装，风格写死，有样图。20 种风格箱、工程全能包、落地页生成器不进。**

### 6. 中文现场
73 件里三分之一以上是中文生活现场：社保断缴、境外所得报税、装修报价、考研、起名、风水、网文去 AI 味、公众号封面。
国外目录站不会收，中文用户找不到。同等水平下，**中文现场优先**。

## 五个反信号（有一条就基本不收）

以 2026-09-06 下架的 27 件为反例（理由都在 `editorial/curation.json` 的 `hide_why`）：

1. **第 N 个通用件** —— 简历/ATS 合集、又一个「先写技术设计文档」的规划器、又一个 code review。别处拿得到。
2. **同作者套路堆** —— 一位作者第四件海报、命名叫「Style 1」的系列半成品。有独立媒介身份的那一件留，其余不留。
3. **框架的内部装修** —— CopilotKit 自带渲染器的接入件、「不是 SKILL.md 形态、装不进 agent」的组件库。
4. **单装做不了完整的事** —— 「不能独立抽牌，只负责仪式流程」；路由靠仓库根的另一份配置。
5. **文案只能写成「帮你更好地 X」** —— 这是问三，但它几乎总是前四条的症状，不是独立原因（27 件里 0 件是单凭问三下架的）。

另外两条硬底线在别处：封面带二维码/广告整件下架（`docs/COVERS.md`）；官方厂商目录不收（`docs/CURATION.md`）。

## 判官怎么用这份

1. **先读 SKILL.md 正文**，不读 README 的营销段、不看星数。没有正文存档的不判（`gate_review.py` 已把这条算作抓取的错，不是货的错）。
2. 三问过门。
3. 六个信号逐条记 0 / 1 / 2（没有 / 有一点 / 明确），**引用原文一句作为证据**，引不出来就是 0。
4. 反信号逐条 是/否。
5. 收的条件：信号总分 ≥ 5，且前三条里至少一条是 2，且反信号全否。
6. 最后写一句店主口吻的钩子（参照 `hearts.json` 那 73 件的 `why_zh`）。写不出来，回到第 5 条重判 —— 多半是信号给高了。

范例与反例的机器可读清单：`editorial/taste_refs.json`（正例 = hearts；反例 = 当天 hide_why 带「问一」「问二」的）。
改这份标准要同时改 `scripts`/`scouts` 里引用它的判官提示词，并在 `docs/DECISIONS-*.md` 记一条。
